## 5. 재측정 명령

```bash
B=~/JS_Project/BS

# LOC·파일 수 (node_modules/dist/build/.next/.dart_tool/legacy-reference 제외)
find "$DIR" -type f \
  | grep -Ev '/(node_modules|dist|build|\.next|\.dart_tool|coverage|\.git|legacy-reference|postgres_data|migration-data|tmp|logs|__pycache__|\.turbo)/' \
  | grep -E '\.(ts|tsx|js|py|dart|css)$' | tr '\n' '\0' | xargs -0 cat | wc -l

# 테이블
grep -rhoE "__tablename__" $B/BS_CASE_MANAGEMENT/backend/app/models | wc -l
grep -cE "^model " $B/BS_MAIN_HOMEPAGE_V2/backend/prisma/schema.prisma

git -C $B/<repo> log --since="2026-01-19" \
  --author="mikely329@gmail.com\|sohl.jin@law-win.co.kr\|js-sohlJin\|sorrybro" --oneline | wc -l
```

## 6. 수치 사용 시 주의

- **사건관리는 2인 팀이다.** "49,000 LOC 단독" 같은 표현을 사건관리에 쓰지 않는다. 내 기여는 커밋 기준 **439/1,729 = 25%**.
- LOC는 `wc -l`(주석·빈 줄 포함)이다. 순수 로직 라인이 아니다.
- 변경량(`+/-`)은 대량 파일 이동·이관·생성물을 포함하므로 **규모 감각용**이지 생산성 지표가 아니다. CRM의 +20만 라인은 데이터 이관 스크립트·시트 덤프가 큰 비중.
- 기존 경력기술서의 CRM "API 54개 · 16테이블 · 49,000 LOC"는 **2026-05 정식 오픈 시점** 값이다. 현재값(65 · 17 · 55,100)과 다르며, 시점을 밝히고 쓴다.
- 레거시 홈페이지는 수치가 없다. 숫자로 부풀리지 않는다.
