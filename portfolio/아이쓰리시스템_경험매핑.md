# 아이쓰리시스템 SW 개발 공고 — 경험·근거 매핑

검토일: 2026-09-13. 사용자 제공 채용 공고 이미지와 이 저장소의 일일·주간 회고를 기준으로 정리했습니다. 후속 조사에서 개인 GitHub `sorrybro2`와 로컬 개인 프로젝트의 학습·구현 기록을 추가했습니다.

공고는 내부 MES 등 업무시스템 개발을 주요 업무로 두고, 프론트엔드 개발 경험을 필수로 제시합니다. Full Stack·Backend·Database·UI/UX 기획·Web 화면 디자인은 우대사항입니다. 이 문서는 지원 자료의 근거를 모은 것으로, 지원 자격 충족이나 합격 가능성을 판정하는 문서는 아닙니다.

## 2. 이 공고에 우선 제시할 사례

### A. 업무 흐름을 화면으로 설계 — 상담료 처리 대기

- 탭을 오가던 상담료 목록과 처리 대기를 좌우 분할로 바꾸고 각 영역에 독립 스크롤을 적용했습니다.
- 대기 항목을 선택하면 의뢰인·상담일·유형·메모·상담 변호사를 입력 폼에 자동 반영했습니다.
- 예약·접수·완료·취소·노쇼를 다중 필터로 구분하고, 취소·노쇼는 입력 대신 처리 완료 동선을 제공했습니다.
- 같은 화면의 FDW 조회를 8초→0.05초로 개선했습니다. 이 수치는 전체 앱 속도가 아닌 처리 대기 조회의 실측입니다.
- **연결 항목**: React, 업무시스템, UI/UX, Full Stack, Backend, DB.
- **근거**: [2026-07-01](../daily/7월/2026-07-01.md), 25~47행. 커밋 `d12d74e`, `f7a5d61`, `bbfa34d`.

### B. 결재 업무의 정보구조·탭·알림 동선 설계

- 대기·완료·기안함 3탭을 만들고, 바로 승인할 수 있는 동작과 반려 사유가 필요한 상세 동작을 구분했습니다.
- `?tab=`과 탭 상태를 연결해 새로고침·뒤로가기에도 선택이 유지되도록 했습니다.
- 대시보드와 결재함의 분류를 맞추고, 알림 클릭 시 대기 목록 위에 상세를 열어 문서를 처리한 뒤 남은 업무를 이어 볼 수 있게 했습니다.
- **연결 항목**: React 상태·라우팅, 업무시스템, UI/UX 기획.
- **근거**: [2026-07-29](../daily/7월/2026-07-29.md), 46~48행. `7f9eb8a`, `143d69a`, `7fdaea7`.

## 3. 백엔드·DB·산업 업무 경험의 보조 근거

- **NestJS API·데이터 이관**: 홈페이지 공개 화면·CMS와 연결할 게시판·약관·상담·변호사 API 및 약 730만 건 이관. [5월 3주차](../weekly/5월/5월%203주차.md), 29~37행.
- **CRM 데이터·연동**: 구글시트에서 Cloud SQL로 약 9.8만 건 초기 적재, 직원 식별키 유지와 단건·배치 동기화. [4월 1주차](../weekly/4월/4월%201주차.md), 17~23행.
- **FastAPI 업무 규칙·조회 개선**: 상담료 처리 대기·다중 사무소 API 및 FDW 조회 최적화. [2026-07-01](../daily/7월/2026-07-01.md), 45~48행.
- **공장 데이터 화면**: Jubix의 Spring·PostgreSQL 기반 센서 데이터 출력·가공·UI 개선은 산업 현장 시스템 경험으로 연결할 수 있습니다. 근거는 현재 [TMI VIII절](../경력기술서_TMI.md)이며, 해당 이전 회사의 상세 회고는 이번 daily/weekly 검색에서 확인되지 않았습니다. MES 생산실적·작업지시·품질관리 담당 여부는 별도 확인이 필요합니다.
- **KOGAS**: 기존 Go 시스템 코드 분석 역할입니다. 신규 업무시스템 전체를 직접 구축한 사례로 바꾸지 않습니다.

## 4. 지원 문서에 사용할 수 있는 표현

### 소개

> React 기반 사내 업무시스템과 Next.js 홈페이지·운영 CMS를 개발하며, 업무 흐름을 UI/UX로 설계하고 API·DB 연동·배포까지 담당한 풀스택 개발자입니다.

### UI/UX 기획

> 결재 대기·완료·기안함의 역할별 정보구조와 URL 상태를 설계하고, 알림 확인→문서 처리→남은 대기 목록으로 이어지는 업무 동선을 구현했습니다. 설정 화면에는 저장·취소·미저장 피드백과 삭제 영향 안내를 적용했습니다.

### 웹 화면 디자인

> 업무 대시보드의 정보 위계·색상·KPI 타이포를 재설계하고, 공통 테이블과 모바일 카드의 시각적 일관성을 정리했습니다. Next.js 전문센터에서는 히어로·본문의 공통 레이아웃과 브랜드 스타일을 구현했습니다.

### 프론트엔드 설계

> 공통 DataTable의 사용자 설정을 관리하고 표·모바일 카드의 정렬 상태를 공유하도록 구조를 개선했습니다. SSE 변경 신호를 쿼리 캐시 갱신과 연결하고, React의 참조·파생 상태 문제를 해결했습니다.
