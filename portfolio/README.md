# 포트폴리오 + 경력기술서

앞 3쪽은 **포트폴리오**로, 소개·대표 프로젝트·문제 해결 사례를 순서대로 보여줍니다.
첫 페이지는 사진·소개·성과·핵심 역량·기술로 구성하며, 시작 날짜 강조·연표·회사 경력표·하단 링크는 표시하지 않습니다.
3쪽 끝에서 포트폴리오 종료를 알리고, 전체본 4쪽은 **경력기술서** 제목과 문서 내부 목차로 시작합니다.
이후 `경력기술서_TMI.md`의 프로젝트별 상세 경력을 불러옵니다. 원문의 자기소개·전체 개관은 중복되어 제외합니다.
`portfolio/personal-projects.md`는 독립 자료로 보관하며 전체본 말미에 붙이지 않습니다.

확인할 결과물은 `진솔_포트폴리오_요약.pdf`(3쪽)와 `진솔_포트폴리오_경력기술서.pdf`(요약+상세)입니다.

디자인은 흰 바탕·진한 본문·파란색 포인트로 통일했습니다. 큰 성과 숫자와 구분선으로 읽는 순서를 만들고,
한글 Pretendard 폰트를 결과물에 내장해 외부 폰트 연결 없이 표시합니다.
참고 자료와 색상·타이포그래피 기준은 [디자인 가이드](design-notes.md)에 정리했습니다.

## 편집할 파일

- `portfolio/content.json`: 이름·소개·성과(`metrics`)·역량(`focus`)·기술·프로젝트·사진 경로. `focus`가 기존 경력표·연표·링크 구성을 대신합니다.
- `projects[].flow`: 서비스 캡처가 없을 때 표시할 실제 구현 업무 흐름
- `projects[].url`: 공개 서비스일 때만 채우는 실제 URL. "서비스 보기" 배지로 표시되며, `public-document.cjs`는 여기 등록된 주소만 통과시킵니다
- `cases[].source`: 내부 검증용 업무 기록 경로. 출력물에는 노출하지 않습니다.
- `경력기술서_TMI.md`: 내부 근거를 포함한 상세 경력 원문
- `portfolio/personal-projects.md`: 별도로 보관하는 개인 개발·팀 프로젝트·학습 이력
- `scripts/portfolio-print.css`: 포트폴리오 3쪽과 경력기술서 도입부의 A4 레이아웃
- `scripts/public-document.cjs`: 모든 외부 공유용 출력의 익명화·기록 링크 제거·누출 검사

## 사진 넣기

아래 이름으로 파일을 넣고 다시 출력하면 반영됩니다. PNG 대신 JPG/WebP를 쓰거나 파일명을 바꾸려면 `content.json`의 `images` 경로를 수정합니다.

| 사진 | 기본 위치 | 권장 구성 |
|---|---|---|
| 프로필 사진 | `assets/portfolio/profile.jpg` | 제공된 사진 사용. 원본 3:4 비율을 유지해 첫 페이지 우측에 32×42.67mm로 표시 |
| 홈페이지 V2 | `assets/portfolio/homepage.png` | 공개 사이트의 사건별 업무사례 목록이 보이는 구간 |
| CRM | `assets/portfolio/crm.png` | 당사자 목록이 보이는 구간 |
| 사건관리 | `assets/portfolio/case-management.png` | 전체 사건 목록과 상태·지사 필터가 보이는 구간 |

세 프로젝트 모두 실제 서비스 캡처와 프로필 사진이 등록되어 있으며 HTML/PDF에 내장합니다.
세 카드는 동일한 비중(3열)으로 표시하므로 새 캡처도 비슷한 정보 밀도로 준비합니다.
캡처가 없는 프로젝트를 추가할 때는 `projects[].flow`를 HTML/CSS로 그린
**구현한 업무 흐름** 도식으로 대신 표시합니다.

서비스 캡처는 작은 글씨가 읽히도록 전체 페이지를 길게 찍기보다 담당 기능 주변을 잘라 사용합니다.
세 프로젝트 모두 약 2:1 비율(가로로 넓은 화면 캡처)을 권장합니다.
이미지는 비율을 유지하고 전체가 보이도록 들어가며, 캡션이 담당 기능을 설명합니다.
사내 화면은 이름·연락처·사건 내용이 없는 테스트 데이터 화면이나 식별정보를 가린 캡처를 사용합니다.
인물 사진은 선택 사항이며, `images.portrait`를 `null`로 두면 숨길 수 있습니다.

## 출력

기존 TMI 렌더러와 동일하게 marked 12.0.2, Playwright를 사용합니다.
모듈 준비 방법과 환경변수는 `scripts/README.md`를 참고합니다.

```text
node scripts/render-portfolio.cjs
```

다음 4개 파일이 생성됩니다.

- `진솔_포트폴리오_요약.html`
- `진솔_포트폴리오_요약.pdf` — 앞 3쪽
- `진솔_포트폴리오_경력기술서.html`
- `진솔_포트폴리오_경력기술서.pdf` — 같은 3쪽 + 상세 경력

사진과 폰트는 HTML/PDF 안에 내장하므로 결과 파일만 공유해도 표시됩니다.
홈페이지 V2 카드의 "서비스 보기"는 `content.json`의 `projects[].url`에 등록된 실제 공개
사이트로 연결되며, 요약본에도 나타납니다. 그 외 상세 링크와 목차는 전체본 안에서 같은 문서의
해당 프로젝트로만 이동합니다. 첫 페이지에는 링크가 없습니다.

모든 출력은 `public-document.cjs`를 거칩니다. 현재 회사명(법무법인 법승)과 도메인은 그대로
표시하고, 이전 직장의 고객사명·내부 저장소명을 익명화하며 비공개 업무 기록 URL·내부 커밋
식별자·민감한 회계 금액을 제거합니다. 내장 SVG도 처리합니다.
기술 성과 수치와 사실관계의 한계는 유지하며, 원본 보고·경력 Markdown·도식은 내부 자료로 보관합니다.

`PDFJS_MODULE`을 지정하면 요약 3쪽 유지, 4쪽 경력기술서 시작, 내부 이동 링크,
등록되지 않은 외부 링크·식별정보 제거를 검사하고 임시 폴더에 전체 페이지 미리보기를 저장합니다.
사진 추가 후에는 재출력 결과를 확인해 캡처 내용과 캡션이 일치하는지 검토합니다.
