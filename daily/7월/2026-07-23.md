## 📝 상세 업무 내역

### 1. 사건관리 — Drive PDF 인페이지 미리보기

> 배경: 사건 Drive 파일 목록에서 PDF를 누르면 Drive 새 창으로만 열려 사이트를 벗어났다. 사용자 브라우저의 구글 로그인·권한에 의존하는 iframe 임베드는 서비스계정 위임 드라이브에서 "권한 없음"이 뜰 수 있어, 백엔드가 대신 받아 스트리밍하는 프록시 방식으로 사이트 안에서 열게 했다.

- **백엔드 프록시 다운로드** — 서비스계정으로 파일 바이트를 받아 스트리밍하는 `download_file`(`get_media` + `MediaIoBaseDownload`, 공유드라이브 지원)와 엔드포인트 `GET /cases/{case_id}/drive-files/{file_id}/content`를 신설. 한글 파일명은 `Content-Disposition: inline; filename*=UTF-8''` 인코딩. (backend `core/google_drive.py`, `api/cases_api.py`) (`c5d99c6`)
- **공용 미리보기 모달 + 양쪽 패널 적용** — blob URL로 iframe 렌더하는 공용 컴포넌트 `DrivePdfPreview`(로딩/에러 폴백·ESC 닫기)를 분리하고, 전체 사건상세(`DriveSidePanel`)와 목록/트리에서 뜨는 슬라이드 사이드패널(`CaseSidePanel`) 양쪽에서 PDF 클릭 시 모달로 열도록 통일. (frontend `DrivePdfPreview.tsx`, `CaseDetailPage.tsx`, `CaseSidePanel.tsx`, `hooks/useCaseDetail.ts`, `api/cases.ts`) (`c5d99c6`)

### 2. 사건관리 — 수발신 문서 결재 받는이·참조 (이슈 #50)

> 배경: 결재 메일 수신자가 화면에 드러나지 않았고, 참조 대상도 커버리지 낮은 상담가 기준이었다. "사건을 고르면 주요 변호사가 받는이, 나머지 변호사·직원이 참조"라는 실제 업무 규칙에 맞게 자동 지정하고 화면에도 노출하되, 개발 중에는 실제 발송을 막았다.

- **받는이·참조 자동 지정 로직 개선** — 받는이(결재자)는 담당변호사→배당변호사→담당직원→수발신담당자 순 유지, 참조(Cc)를 상담가 대신 **사건에 배정된 나머지 변호사·직원**으로 교체하고 `cc_names`를 응답에 추가. 등록 모달 미리보기에 참조자 이름 표시. 개발 오발송 방지는 기존 `APPROVAL_EMAIL_OVERRIDE`(test6) 환경변수가 그대로 담당. (backend `document_logs_crud.py`·`document_logs_api.py`·`document_logs_schema.py`, frontend `api/documentLogs.ts`·`DocumentLogAddModal.tsx`) (`549a4c2`)
- **상세뷰 참조 표시 + 크래시 방지** — 상세 드로어 결재정보에 "참조" 항목 추가(참조는 저장값이 아니라 사건 담당자에서 계산되므로 미리보기 API로 `cc_names` 조회), "결재자"→"결재자(받는이)" 라벨 명확화. 등록 모달에서 `cc_names` 미정의 시 `.length` 접근으로 나던 크래시를 `?? []`로 방지. (frontend `DocumentLogAddModal.tsx`, `DocumentLogDetailDrawer.tsx`) (`ea6b972`)

### 3. 사건관리 — 대시보드 상담료·상담 집계·표기 (이슈 #47/#48/#49)

> 배경: 상담료 지표가 없었고, 전화상담 집계에 누락 유형이 있었으며, 히트맵 요일이 월요일 시작이라 관습과 어긋났다. 데이터 소스와 표기를 실제 운영 화면(상담료 관리)과 맞추고 사용성을 정비했다.

- **히트맵 요일 일요일 시작 (이슈 #48)** — 전화상담 히트맵 요일 라벨을 월~일 → 일~토로 바꾸고 시작 셀 오프셋(`getDay`, Sun=0)도 맞춰 라벨-데이터 정합 유지. CallHeatmapCard(표시본)·CallHeatmap·MiniCallHeatmap 3종 통일. (`4d2af3b`)
- **미수금 위젯에 상담료 추가 (이슈 #47)** — 미수금 현황 위젯에 이번 달 상담료 항목 신설(`d55163e`), 이후 합산 기준을 상담료 관리 화면의 "총 상담료"와 동일하게 `fee_amount` 합으로 정정(`2425975`)해 두 화면 값이 일치하도록. (frontend `ReceivablesWidget.tsx`)
- **전화상담 집계 누락 보정 (이슈 #49)** — 백엔드 집계가 `전화상담(직원)`·`전화상담(변호사)`만 세어 접미사 없는 `전화상담`(약 2,100건)이 빠지던 것을 집합에 추가. 기관전화 등은 계속 제외. (backend `dashboard_crud.py`) (`3084d7b`)
- **상담료 월 연동 + 전체 보기 (이슈 #47)** — 상담료 지표가 항상 현재 월 고정이라 데이터 없는 이번 달만 보이던 문제를 대시보드 월 선택기(ym)에 연동해 해결하고, "전체 보기" 링크(상담료 관리로 이동, 대시보드 월을 URL `?ym=`로 전달)를 추가. 미수금 위젯 금액 표기도 만/억 축약 → 콤마 숫자로 변경. (frontend `ReceivablesWidget.tsx`·`ConsultationFeesPage.tsx`) (`b90589b`, `3527041`)
- **방문상담 블록 통합 (이슈 #49 논의 후속)** — 상단 KPI 바에 흩어져 있던 방문상담 수치와 월간요약 카드의 현황 그래프를 한 블록으로 결합(총계 숫자+전월 대비 + 완료/예약/취소 현황), KPI 바는 수임·전환율·진행중 3칸으로 축소. 집계 기준은 전체 유지. (frontend `DashboardPage.tsx`) (`04d9cab`)

### 4. 사건관리 — 대시보드 권한·레이아웃 재정비 & 전체사건 크래시 (이슈 #46/#52)

> 배경: 전체사건에서 특정 사건을 열면 앱이 통째로 죽는 크래시가 있었고, 대시보드 권한 노출 기준도 재정리가 필요했다.

- **전체사건 크래시 수정 (이슈 #52)** — 슬라이드 사이드패널(`CaseSidePanel`)의 타임라인이 `SOURCE_STYLE.schedule.dot`를 쓰는데 `SOURCE_STYLE`에 `schedule` 항목이 빠져 있어, **수기일정이 있는 사건**을 열면 `Cannot read properties of undefined (reading 'dot')`로 크래시했다. 전체 상세 페이지엔 있던 항목이 사이드패널에만 누락돼 있어 동일하게 추가(수기일정 5건 사건으로 재현·검증). (`e2037e0`)
- **권한별 노출·데이터 스코프 재정비 (이슈 #46)** — 백엔드 summary·daily-calls에서 super_admin만 전체 열람, admin은 담당 사무소 그룹으로 제한(경영지표·목표액은 계속 노출). 프론트는 업무 섹션(일정·담당사건·결재)을 cases/schedules 권한 보유자만 노출(수납 전용 계정은 숨김), 지역탭·월 이동을 상단으로 통합하고 위젯 내 사무소 드롭다운 제거. (backend `dashboard_api.py`, frontend `DashboardPage.tsx`) (`ee3f2a6`)
- **결재 위젯 탭 스타일 정리** — 승인/요청 탭을 테두리+배경 세그먼트 컨트롤로 묶고 크기·라운드·활성 배지 색 조정. (`ApprovalWidget.tsx`) (`7dbf76b`)

### 5. 사건관리 — 기일 충돌 검사 범위 한정

- **오늘 이후 기일만 충돌 판정** — `get_conflict_ids` 쿼리에 `hearing_date >= CURRENT_DATE` 조건을 추가해, 이미 지난 기일끼리의 충돌은 무시하고 다가오는 기일만 충돌 대상으로 삼도록 보정. (backend `cases_api.py`) (`99313d9`)

### 6. CRM — 당사자 문자 상세 컬럼 표시

- **문자 상세·목록 정보 보강** — 당사자 문자 상세 팝업에 문자제목·발신지사·발신번호·수신번호·작성자·최종수정·수신상태 컬럼을 노출하고, 발신 지사 `sender_key`로 실제 발신 전화번호를 조회해 응답에 추가. 발신·수신번호를 하이픈 형식으로 통일하고, 문자 목록 카드에 수신번호·발신지사 요약 줄을 더함. (backend `partySmsCallController.js`, frontend `party_detail_screen.dart`) (`d9d6966`)
