# 일일 업무 보고 (2026. 07. 13)

> 지난주 세운 열람/등사 화면을 **오른쪽 드로어 방식으로 전면 재편**하고(상세·등록 패널·전역 store) 등록을 메일 미리보기가 붙은 중앙 팝업으로 개편, 도과 알림을 **매일 10시 인앱 스케줄러로 자동 발송 + 웹훅(톡) 단일화**했다. 병행해 미수금은 복수 지사 합산 조회를, 계약은 의뢰인 교체/삭제와 "당사자 신규는 CRM으로 유도"를, 사건은 계약 정보 자동 매핑을 붙이고, 사건 표시명을 "당사자 사건명"으로 전 화면에 전면 적용했다. 결재 메일 '수락'은 클릭 즉시 완료 처리로 바꾸고, 조회 화면에 노출되던 삭제 버튼을 수정 모드 안으로 옮겨 오조작을 줄였으며, 홈페이지 V2 지식센터 목록에 카테고리 필터를 붙였다 — 금일 커밋 18건(2개 repo)

## 📝 상세 업무 내역

### 1. 사건관리 앱 — 열람/등사(record-requests) 드로어 재편 + 등록 개편

> 배경: 지난주 독립 화면으로 만든 열람/등사(화면 7·8)가 전체 페이지 이동 방식이라 수발신 문서(드로어)와 UX가 갈렸음. 앱 전반의 상세/등록 상호작용을 오른쪽 슬라이드 패널로 통일하고, 등록 흐름을 메일 미리보기까지 붙은 팝업으로 재설계.

- **상세·등록을 오른쪽 슬라이드 패널로 전환** — 전체 페이지 이동을 수발신 문서와 동일한 오른쪽 드로어 방식으로 통일. 전역 store(`recordDetailStore`) 기반 상세 드로어(`RecordRequestDetailDrawer` — 보기·수정·상태관리·재알림·이메일)를 `AppLayout`에 전역 마운트하고, 오른쪽 등록 패널(`RecordRequestAddPanel` — 목록=사건검색·사건화면=사건고정)에서 등록 직후 상세 드로어로 이어 열리게 함. 목록·사건상세·사이드패널의 진입점을 드로어로 재배선하고, 상세 담당자는 키가 아닌 이름으로 표시. 구버전 `RecordRequestFormPage`와 `/record-requests/new·/:id` 라우트 제거. (`features/record-requests/*`, `stores/recordDetailStore.ts`) (`eb94b93`)
- **등록 패널 개편 — 중앙 팝업 + 메일 미리보기·수신자 자동매핑** — 열람/등사 등록을 좌(입력)·우(메일 미리보기) 2단 중앙 팝업으로 개편. 사건 선택 시 담당변호사·주무변호사·담당직원의 이메일을 수신자로 자동 채우는 `RecipientSearchInput`을 도입하고, 이를 위해 직원 검색 API·`EmployeeItem`에 email 필드를 추가. (`RecordRequestAddPanel.tsx`, `pickers.tsx`, `consultation_fees_api.py`) (`3f66b00`)
- **수정 시 신규 수신자만 안내 메일 + 등록 후 드로어 미오픈** — 수정 시 새로 추가된 `notify_emails` 수신자에게만 신청 안내 메일을 발송(기존·기본 수신자는 등록 시 이미 수신). 등록 패널은 저장 후 상세 드로어 자동 오픈을 제거해 목록에서 확인하게 함. (`record_request_api.py`, `RecordRequestAddPanel.tsx`) (`635be23`)

#### 🔔 도과 알림 인앱 스케줄러 자동화 + 웹훅 단일화

- **도과 알림 매일 10시 자동 발송 + 실패 시 정보실 폴백** — 인앱 APScheduler에 매일 10:00 KST cron을 추가해 도과 체크 로직(`_check_copy_reminders` + `_check_remind`)을 인-프로세스로 직접 호출(외부 Cloud Scheduler·인증 불필요). `_send_webhooks`는 발송 실패 건이 있으면 이름이 "정보실"인 폴백 웹훅으로 실패를 통지(정보실 자신의 실패는 제외). (`record_request_scheduler.py`, `main.py`) (`389d6a1`)
- **등사일자 독촉을 웹훅(톡)으로 통합** — 이메일 독촉을 제거하고 도과 알림·등사일자 미등록 독촉을 모두 웹훅으로 발송하도록 단일화(`_build_copy_reminder_message`). 최초 도과=도과알림, 이후 영업일마다=독촉, 당일 1회. 설정 UI의 독촉 이메일 수신자 에디터도 제거. (`record_request_scheduler.py`, `RecordRequestSettingsSection.tsx`) (`0b4e68e`)
- **열람/등사 설정 화면 신설(admin)** — 시스템 설정의 "열람/등사 설정" 플레이스홀더를 실제 편집 UI로 교체. 도과 알림 웹훅(`record_request_notify_webhooks`, 이름+URL) 추가/삭제와 독촉 이메일 수신자(`record_request_notify_emails`) 편집을 지원하며, 슈퍼관리자만 편집·그 외 읽기 전용. system-settings upsert로 저장돼 스케줄러가 바로 사용. (`admin/components/RecordRequestSettingsSection.tsx`, `AdminPage.tsx`) (`869986a`)

### 2. 사건관리 앱 — 계약·미수금 연동

- **미수금 복수 지사 합산 조회 + 납부예정 월 필터** — 목록 API에 `office_keys`(쉼표구분 복수)·`due_ym`(납부예정월) 파라미터를 추가해, '전체' 탭에서 접근 가능한 모든 실제 지사를 합산 조회하고 납부예정일 월 범위로 필터. `ReceivableListPage`는 officeScope로 전체=복수지사·특정 지사=단일 조회를 분기. (`receivables_api.py`, `receivables_crud.py`, `ReceivableListPage.tsx`) (`700ff25`)
- **계약 수정 의뢰인 교체/삭제 + 당사자 신규는 CRM으로 유도** — 계약 사이드패널 수정 모드에 의뢰인 편집을 추가(CRM 검색으로 고른 당사자를 `matter.party_key`로 설정, 삭제 시 해제, 표시 의뢰인 즉시 갱신). 당사자는 CRM이 원천이므로 `PartyAddCard`의 로컬 '새로 추가'를 제거하고 CRM 당사자 등록 페이지로 이동하는 안내로 대체(계약·사건 등록 공통). (`matters.ts`, `PartyAddCard.tsx`, `ContractCreatePanel.tsx`, `ContractSidePanel.tsx`) (`05901dd`)
- **사무소 선택 UI에서 정보실 제외** — 계약 목록·미수금 사무소 탭과 계약 등록/상세/사이드패널의 담당사무소 선택에서 `accessibleOffices`를 그대로 나열해 정보실(비-사무소 조직)이 섞여 나오던 문제를, 열람등사·수발신과 동일하게 `isRealOffice`로 필터해 수정. (`contracts/*`, `ReceivableListPage.tsx`) (`13d9685`)
- **미수금 계약 링크 404 해결** — 목록 없는 `/contracts/:id` 대신 계약 관리 사이드패널을 여는 쿼리파라미터 방식(`/contracts?contract=`)으로 이동. (`ReceivableListPage.tsx`) (`bac21a9`)

### 3. 사건관리 앱 — 사건 등록·결재·UX 정리

- **사건 등록 시 계약 정보 자동 매핑 + CasePatch 필드 확장** — 계약으로 사건 등록 시 계약의 계약일·사건유형·당사자지위·기관(법원 판별)·담당(변호사·직원·사무소)을 폼에 1회 자동 채움(지사 기본값은 계약 없을 때만). `CasePatch`에 organization_key·사건번호(연도/부호/번호)·사건명·기관연락처·재판부·각하일 등 수정 가능 필드 추가. (`cases_schema.py`, `CaseFormPage.tsx`) (`fda4333`)
- **결재 메일 "수락" 즉시 완료 처리** — 이메일 결재 링크의 수락(`intent=approve`)은 페이지 진입 즉시 결재 완료로 처리하고 결과만 표시(확인 클릭 단계 제거). 거절·코멘트 후 결재는 기존대로 코멘트 폼으로 진입. (`document-logs/components/ApprovalPage.tsx`) (`9e30bca`)
- **삭제 버튼을 수정 모드 안으로 이동** — 조회 화면에서 노출되던 삭제(비활성화) 버튼을 수정 모드에서만 보이도록 옮겨 실수 삭제를 줄임. 사건 상세/사이드패널, 문서대장 상세 드로어에 동일 적용(`CaseSidePanel`은 삭제 로직을 상세 페이지 수정 모드로 위임). (`CaseDetailPage.tsx`, `CaseSidePanel.tsx`, `DocumentLogDetailDrawer.tsx`) (`86a150f`)
- **사건 상세 목록 담당자명 표시·컬럼 정리** — 사건 상세의 열람등사·수발신 표에서 담당자를 키가 아닌 이름으로 표시하고, 관할/방법/담당자 컬럼에 폭 제한 truncate + title 툴팁·nowrap을 적용. 수발신 문서 추가 패널은 저장 성공 시 연속 입력 대신 패널 자동 닫힘으로 변경. (`CaseDetailPage.tsx`, `DocumentLogListPage.tsx`) (`c197e1b`)

### 4. 사건관리 앱 — 표기 통일·기타
