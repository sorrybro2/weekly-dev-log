## 📝 상세 업무 내역

### 1. 사건관리 앱 — 수발신 문서 결재 워크플로 구축

> 배경: 수발신 문서에 결재(승인) 절차가 없어 담당 변호사 확인이 수기로 이뤄지던 것을, 상태 관리 → 이메일 결재 → 인앱 알림 순으로 단계(P1·P2·P4)를 나눠 하나의 워크플로로 구축.

- **P1 — 결재 상태 필드 + 목록 배지/필터** — `document_logs`에 결재 컬럼(approval_status 대기/완료/보류, approver_key, approval_comment, requested_at, approved_at)을 추가(migration 006)하고, 목록에 결재 상태 배지 컬럼과 전체/대기/완료/보류 세그먼트 필터를 붙여 페이지네이션과 연동. 결재는 신규 문서부터 적용하고 레거시(NULL) 행은 배지 '—'로 표시해 대상에서 제외. (`backend/migrations/006_document_logs_approval.sql`, `models/document_logs_model.py`, `features/document-logs/components/DocumentLogListPage.tsx`) (`4f0ff0b`)
- **P2 — 결재 요청 이메일 발송 + 원클릭 결재 페이지** — `POST /document-logs/{id}/request-approval`로 담당 변호사(lead_lawyer→assigned_lawyer)에게 결재요청 Gmail을 보내고 상담가를 best-effort로 Cc. 무인증 서명토큰 엔드포인트(`GET /approval/info`·`POST /approval/submit`)와 이메일 링크로 진입하는 결재 페이지(로그인 불필요, 수락→완료·거절(사유필수)→보류·재처리 방지)를 추가. 개발 중 오발송 방지용 `APPROVAL_EMAIL_OVERRIDE`도 마련. (`backend/app/core/gmail.py`, `core/security.py`, `features/document-logs/components/ApprovalPage.tsx`) (`400ac98`)
- **P4 — 인앱 알림 + 결재 UX 보강** — `notifications` 테이블(migration 007)과 API(`GET /notifications`, read/read-all)를 만들고, 결재 요청 시 승인자에게 인앱 알림을 생성. 헤더 알림 벨·뱃지·드롭다운·30초 폴링·우하단 토스트와 로그인 상태 인앱 수락/거절을 구현. 아울러 담당자 키→이름 표시(employee_info 조인), 수발신 상세·목록 삭제 버튼, 사건상세 문서 모달의 결재 요청 버튼을 추가. (`backend/migrations/007_notifications.sql`, `api/notification_api.py`, `components/common/NotificationCenter.tsx`) (`83b3983`)
- **결재자 fallback 확장 + Gmail 로그 인코딩 오탐 수정** — 사건에 담당 변호사·직원이 없어도 문서 결재가 가능하도록 결재자 fallback을 lead_lawyer→assigned_lawyer→lead_staff→문서 수발신담당자(assigned_to)까지 확장. 또한 발송 로그의 `→`·`—`가 Windows cp949 콘솔에서 `UnicodeEncodeError`를 일으켜 실제로는 발송 성공인데 실패(ok=false)로 잡히던 오탐을 로그를 ASCII로 바꿔 해결. (`backend/app/core/gmail.py`, `crud/document_logs_crud.py`) (`990a30a`)
- **알림은 승인자에게만 + 개수=미처리 기준** — 개발용으로 요청자 본인에게도 보내던 알림을 제거해 승인자(받는 사람)에게만 생성하고, 인앱·이메일 어느 경로로든 수락/거절하면 관련 알림을 읽음 처리해 뱃지가 줄도록 함. '모두 읽음' 버튼을 없애고 열어보는 것만으로는 줄지 않고 결재를 처리해야 사라지는 미처리 기준으로 통일. (`api/document_logs_api.py`, `components/common/NotificationCenter.tsx`) (`a37489d`)
- **수발신 문서 상세 전역 드로어 통합** — 상세 모달·폼페이지를 제거하고 `DocumentLogDetailDrawer` + 전역 `docDetailStore`로 일원화. 목록·사건상세(CaseSidePanel)·알림(NotificationCenter) 어디서 열어도 동일한 드로어로 뜨고 그 안에서 결재까지 처리하도록 AppLayout에 전역 마운트. (순삭 -1139/+382로 코드 대폭 정리) (`features/document-logs/components/DocumentLogDetailDrawer.tsx`, `stores/docDetailStore.ts`, `components/common/AppLayout.tsx`) (`972c3e5`)

### 2. 사건관리 앱 — 대시보드 집계 정상화

> 배경: 대시보드의 상담·방문·계약 지표가 실제 데이터가 있음에도 0으로 표시되던 문제를 데이터/표기 정규화로 바로잡고, 진행 사건 수를 지역 그룹별로 볼 수 있게 개선.

- **상담유형 공백 표기 불일치 수정** — 데이터는 `전화 상담(직원)`·`방문 상담`(공백 포함)인데 비교 상수는 `전화상담`·`방문상담`(공백 없음)이라 매칭에 실패해 모든 그룹의 calls/visits가 0이던 문제를, 비교 시 공백을 제거(정규화)해 양쪽 표기를 모두 수용하도록 수정(summary·daily-calls 공통). (`backend/app/crud/dashboard_crud.py`) (`7df52d0`)
- **지역 탭 개행 방지** — 지역 탭이 좁은 폭에서 줄바꿈되던 것을 컨테이너 가로 스크롤 + 각 탭 `shrink-0 whitespace-nowrap`으로 한 줄 유지. (`features/dashboard/components/DashboardPage.tsx`) (`3cfb330`)
- **contract_ym 정규화(월별 계약 집계)** — `contract_ym`이 CHAR(6)에 연도만(`'2025  '`) 저장돼 월별 매칭에 실패, 대시보드 계약 카운트가 0이던 문제를 계약일(contract_date) 기준 `TO_CHAR(...,'YYYYMM')`로 재설정하는 migration 008로 해결(DB 525건 적용, 정상화 확인). (`backend/migrations/008_normalize_contract_ym.sql`) (`95aa649`)
- **진행 중 사건 수 그룹별 집계** — 전사 총계만 나오던 '진행 중 사건 수' 카드를 선택된 지역 탭 기준으로 전환. `useActiveCasesCount(organizationKeys[])`로 바꿔 백엔드 `organization_keys`(콤마 구분)를 사용, 전체 탭은 전사값을 유지하고 특정 탭은 해당 그룹 org_keys만 집계하며 라벨도 그룹명 기준으로 표기. (`features/dashboard/hooks/useDashboard.ts`, `components/DashboardPage.tsx`) (`446b395`)

### 3. 사건관리 앱 — 사건 상세/목록 UI 정리

- **사건 상세 기본정보·법원정보 통합 + 요약 메타바** — 법원명·재판부·사건번호·사건명이 헤더/기본정보/법원기본정보에 중복되던 것을 제거하고 두 카드를 '사건 정보' 한 카드(밀집 2열 정의 그리드)로 합침. 제목 아래에 단계·유형·당사자·진행·확정·담당 요약 메타바를 추가. (`features/cases/components/CaseDetailPage.tsx`) (`14acee3`)
- **사건 상세 뷰 모드 섹션 단일 카드 통합** — 뷰 모드에서 사건정보·수기일정·연결사건·열람등사·수발신문서·사건결과 섹션을 카드 하나(divide-y)로 묶어 구분선으로만 구획. `SectionCard`에 flat 모드(카드 크롬 제거)와 isEmpty(내용 없으면 헤더 한 줄로 접기)를 추가하고, 사건결과는 데이터가 없으면 '진행 중' 배지로 표시. (`features/cases/components/CaseDetailPage.tsx`) (`8d85685`)
- **사건 목록 당사자 행 병합 호버 강조 수정** — 당사자 rowSpan 병합 셀이 그룹 첫 행에만 속해 행 단위 hover 배경이 첫 행에서만 먹던 문제를, 그룹 hover 상태(hoveredGroup)를 추가해 같은 당사자의 어느 행에 올려도 병합 셀이 함께 강조되도록 수정. (`features/cases/components/CaseListTable.tsx`) (`b756570`)
- **사무소 선택에서 정보실 제외(공용 상수 통합)** — 실제 사무소가 아닌 정보실이 사건 폼의 담당/부담당 지사 드롭다운과 사건 목록 사무소 탭에 노출되던 문제를 수정하고, 문서대장·상담료에 중복 정의돼 있던 `EXCLUDED_OFFICE_KEYS`를 `lib/officeConstants`로 단일화. (`lib/officeConstants.ts`, `features/cases/CaseListPage.tsx` 등) (`0c68612`)
