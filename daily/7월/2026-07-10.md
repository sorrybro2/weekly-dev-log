## 📝 상세 업무 내역

### 1. 사건관리 앱 — 열람/등사(record-requests) 화면 + 등사일자 독촉 알림

> 배경: 열람/등사 신청 관리 화면(화면 7·8)이 없어 사건 상세 링크만 배선돼 있던 것을 독립 화면으로 구축하고, 신청 후 등사(복사)를 완료하지 않고 방치되는 건을 놓치지 않도록 공휴일까지 반영한 자동 독촉 알림을 붙임.

#### 🖥️ 열람/등사 목록·등록/수정 화면 신규 (화면 7·8)
- **신규 feature `record-requests`** — 목록(`RecordRequestListPage`)과 등록/수정(`RecordRequestFormPage`)을 신설. 목록은 월·사무소탭·상태·도과 필터와 도과 행 강조, 사건명/담당자명 표시를 지원하고, 폼은 좌측 sticky 네비 + 4섹션(기본정보/상태관리/이메일알림/메모)에 등록·조회·수정 모드를 갖춤. 재신청 시 영업일→재알림일을 실시간 미리보기하고, 사건 선택 시 이메일 필드를 자동으로 채움. (`features/record-requests/*`, `api/recordRequests.ts`, 라우트 3개) (`18ff54c`)
- **목록 API 독립 화면용 확장(백엔드)** — `GET /record-requests`에 ym·date_from·date_to·office_key 필터를 추가하고, 목록 응답에 case_name·case_number·organization_key·assigned_to_name 조인을 붙여 독립 목록 화면에서 바로 쓸 수 있게 함. (`backend/app/api/record_request_api.py`, `crud/record_request_crud.py`) (`18ff54c`)

#### 🔔 등사일자 미등록 독촉 알림 (공휴일 API·영업일 이메일)
- **'도과'를 등사일자 미등록 독촉으로 재정의** — 기존 신청상태 기준 도과 체크를 등사일자(copy_date) 미등록 독촉으로 다시 설계. 알림 시작일 = 발의일자 + 7일(평일 공휴일은 카운트 제외·주말은 포함)로 계산해, 시작일 도달 시 최초 1회 `is_overdue` 표시 + 웹훅을 보내고 이후 영업일마다 미등록 독촉 이메일을 발송(당일 1회, `overdue_notified_at`으로 중복 방지). 등사일자가 등록되거나 종결 상태가 되면 대상에서 빠져 자동 중단. (`backend/app/api/record_request_scheduler.py`, `core/gmail.py`) (`a6ebfe0`)
- **공휴일 특일정보 API 연동 + 캐싱** — 공공데이터포털 특일정보 API(getRestDeInfo)로 연도별 공휴일을 조회해 `system_settings`에 JSON 캐싱하는 `holidays_kr` 모듈을 신설(서비스키 `DATA_GO_KR_SERVICE_KEY` 미설정 시 주말만 제외로 폴백). 수동 갱신용 `POST /scheduler/sync-holidays`와 독촉 메일 발송기 `send_copy_reminder_email`도 함께 추가. (`backend/app/core/holidays_kr.py`, `core/config.py`, `core/gmail.py`) (`a6ebfe0`)

### 2. 사건관리 앱 — 수발신 문서 결재 자동화 + 공용 DatePicker

- **등록 시 결재 요청 자동 발송** — 어제 만든 수동 결재요청 로직을 `_perform_approval_request` 공통 함수로 추출하고, 수발신 문서 등록(create) 시 담당 변호사에게 결재 요청이 자동 발송되도록 연결. 결재자 미확인·발송 실패해도 등록 트랜잭션은 유지되는 best-effort로 설계하고, 수동 결재 요청 버튼(request-approval)은 그대로 유지. (`backend/app/api/document_logs_api.py`) (`20108a9`)
- **공용 DatePicker 컴포넌트 도입** — 폼마다 제각각이던 날짜 입력을 단일 `DatePicker`로 통일하고 사건·계약·수발신·열람등사 폼 전반에 적용. (`components/common/DatePicker.tsx` 외 계약·사건·수발신 폼 다수) (`20108a9`)

### 3. 사건관리 앱 — 사건 상세 CRM 연동 + 사건 표시명 통일

- **CRM 이동·계약 미리보기 버튼** — 사건 상세/사이드패널 헤더에 의뢰인(delegator.party_key) 기준 CRM 이동 버튼과 계약 상세 미리보기 패널(`ContractPreviewPanel`)을 연결하고, Drive 사이드패널 헤더에도 CRM 버튼을 추가. 전역 헤더에 있던 CRM 링크를 사건 화면 컨텍스트로 옮기며 `uiStore`를 제거하고, 사이드패널에 갱신(크롤링)·삭제(비활성화) 버튼도 추가. (`features/cases/components/CaseDetailPage.tsx`, `CaseSidePanel.tsx`) (`4e4bf4c`)
- **사건 표시명 "당사자 사건명" 통일** — "당사자이름 사건명" 형식의 공용 포맷터 `formatCaseName`(한쪽만·둘 다 없음 대응)을 신설해 헤더 검색(제목=포맷명·부제=사건번호), 사건 상세·사이드패널(당사자명 뒤 가운뎃점 제거), 열람등사·수발신 pickers의 caseLabel까지 전 화면 표기를 통일. (`lib/caseName.ts`, `HeaderSearch.tsx`, pickers 등) (`f29991d`)

### 4. 크롤러 인프라 — 완료 리포트 통합·트리거 정상화

- **캘린더싱크 트리거 정상화 + 리포트 1회 통합** — 크롤러 6단계 트리거가 Cloud Run Jobs v1(잘못된 리소스 경로)을 호출해 매번 404로 실패하던 버그를 v2 API로 수정. 7개 태스크가 각자 Chat 리포트를 보내던 것을 완료신호 카운터(`crawler_run_signals`) + 원자적 선점(`crawler_run_triggered`)으로 통합해 1회만 발송하도록 재설계하고, `calendar_sync`가 BigQuery 크롤 통계 + 캘린더 동기화 결과를 하나의 리포트로 합쳐 보내도록 확장. `SKIP_CODEF=1` 오집계·BigQuery 스키마 드리프트(7개 필드)도 함께 수정하고, 한 번도 성공한 적 없던 `deploy-crawler.yml` CI를 폐기해 수동 배포를 공식화. (`crawler/ab_crawler.py`, `calendar_sync.py`, `bq_writer.py`, `docs/DEV_STATUS_v1.0.md`) (`9d81cb3`)
- **crawler_run_signals 마이그레이션 실행 스크립트** — 기존 `run_ddl.py`와 동일한 psycopg2 + Cloud SQL Auth Proxy 패턴으로 `add_crawler_run_signals.sql`을 적용하는 1회성 러너를 추가하고, 오늘 실제 운영 DB에 적용 완료(`crawler_run_signals`·`crawler_run_triggered` 테이블 생성). (`scripts/migration/run_add_crawler_run_signals.py`) (`cccda69`)
