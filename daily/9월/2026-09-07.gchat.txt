📋 *일일 업무 보고 (2026. 09. 07.)*

실시간처럼 보이게 하는 값을 웹소켓에서 사람 눈으로 옮긴 하루. 같은 요구(목록이 저절로 최신이 되게 해달라)를 CRM에 먼저 적용해 검증하고 그 설계를 사건관리 앱으로 옮겼으며, 원래 계획이던 웹소켓은 Cloud Run 과금 구조를 근거로 보류시켰다. 얻는 것은 타인 화면 반영 15초에서 1초뿐인데 월 3~9만원과 중계 인프라가 붙는다. 대신 폴링 범위를 넓히고 무엇이 바뀌었는지를 색으로 표시해 돈을 안 쓰고 체감을 올렸다. 금일 커밋 17건(2개 repo), 이슈 4건 생성, 코멘트 5건.

🔄 *〔CRM : 목록 자동 갱신과 새 행 강조〕*

•  *CRM에서 먼저 검증* — 사건앱보다 한 단계 뒤(폴링조차 없는 상태)라 여기서 만들고, 검증된 설계만 사건앱으로 옮겼다 (b6f4e0c)
•  *조용히 도는 재조회* — 스피너 없이 데이터만 교체해 스크롤과 선택을 유지하고, 실패해도 보던 목록을 오류 화면으로 덮지 않는다
•  *멈추는 조건을 실사용 기준으로* — 실제로 안 보일 때만 정지. 웹의 inactive는 다른 창을 클릭했을 뿐 화면은 보이는 상태라, 여기서 멈추면 듀얼 모니터 사용자가 갱신을 못 받는다
•  *릴리즈에서만 있던 잠복 버그* — 가로 스크롤이 무한 폭을 내려주고 stretch가 그대로 물려받아 표 행이 아예 안 그려졌다. 디버그는 assert로 걸리지만 릴리즈는 검사를 건너뛴다 (9e91ce6)
•  *깜빡임 대신 한 번만* — 켜짐 0.18초, 빠짐 0.9초로 시간을 나눔. 양쪽 다 느리면 눈에 안 띄고 반복 점멸은 거슬리기만 한다 (cc1f815)
•  *회생 상담관리도 동일 적용* — 15초 자동 갱신, 새 행 강조, 수동 새로고침 (9bf2c50, 76c29b8)

🗂 *〔CRM : 회생 현재상태 재정의〕*

•  *상태 목록이 네 군데에 흩어져 있었다* — 목록 필터, 등록 폼, 배지 색, 엑셀 색이 각자 보유. 실제로 수임이 필터엔 있고 폼엔 없었다. 한 파일로 통합 (95a4ef4)
•  *조용한 덮어쓰기 제거* — 저장된 상태가 목록에 없으면 기본값으로 보여줘서, 다른 항목만 고쳐 저장해도 상태가 바뀌어 있었다
•  *필터를 건수 중심으로* — 18개로 늘어 밀리던 것을 줄바꿈 배치로 바꾸고, 상담완료 6개는 접두어를 떼어 한 묶음 한 색으로. 이름은 작게 건수는 크게 (54c852c)
•  *상담관리와 같은 카드로 통일* — 공통 위젯으로 승격, 아이콘 제거(6개가 같은 아이콘이라 구분에 도움이 안 되면서 폭만 차지), 건수 0은 흐리게 (5ed62ab)

📇 *〔CRM : 구글 연락처 저장 대상 확대〕*

•  *조직당 1명에서 여러 명으로* — 회생팀은 공용 모바일 계정이 없어 담당자 개인 계정으로 저장되는데, 대상에 오용문 주임 추가 (이슈 bs_crm#9, 2ed0cb7)
•  *한 명을 못 찾아도 나머지는 저장* — 기존 구조는 한 명만 찾고 끝이라 퇴사나 오타 한 건에 전체가 멈췄다

⚡ *〔사건관리 앱 : 변경 강조와 폴링 확대〕*

•  *웹소켓 보류를 숫자로 결정* — Cloud Run은 연결이 열려 있는 동안 인스턴스를 활성으로 과금한다. 업무시간 유지 시 증분 월 21달러, 탭을 종일 열어두면 96달러, 폴링은 5달러 (이슈 #186)
•  *초록은 새로 들어온 행 주황은 값이 바뀐 행* — CRM은 새 행만 잡았지만 사건은 생성보다 진행상태와 기일 변경이 훨씬 잦아 변경 행도 대상 (a346600, d9606cd)
•  *파랑을 안 쓴 이유* — 기본 호버와 선택 행이 이미 파랑이라 강조인지 호버인지 구분되지 않는다
•  *사건상세는 약하게* — 한 화면에 목록이 여럿이라 강하게 주면 동시에 물들어 번쩍인다. 풀페이지와 사이드패널이 같은 기준 파일을 쓰도록 모음 (1124aaf)
•  *하위 항목까지 폴링 확대* — 연결사건, 열람등사, 수발신문서, 수납, 타임라인이 대상에 없어 화면을 다시 열기 전엔 반영되지 않던 것을 15초로 통일 (9ccaf81)
•  *작업 중 잡은 무한 렌더* — 호출부의 빈 배열 기본값이 매 렌더마다 새 배열을 만들어 사건상세가 죽었다. 내용이 같으면 상태를 갱신하지 않도록 수정
•  *상태* — 브랜치 feat/list-row-change-highlight 푸시 완료, 머지 전

🚀 *〔사건관리 앱 : 드라이브 중복 복사 수정과 배포〕*

•  *중복 사본 차단* — PC 업로드한 파일을 이어서 드라이브에서 선택으로 고르면 사본이 하나 더 생겼다. 부모 폴더 확인을 한 곳에 모아 앞으로 추가될 호출부까지 보호 (이슈 #491, a5326a8)
•  *본문 오류를 스스로 정정* — 수발신문서도 같은 문제라고 적었으나 그쪽은 이미 방어가 있었다. 줄번호만 보고 맥락을 안 읽은 실수
•  *배포 완료* — 리비전 lawwin-case-00212-5kh 트래픽 100%, health 검증 통과 (262a783)
•  *후속 안내* — 제보된 중복 파일은 사본이 일정과 캘린더에 연결돼 있어, 원본으로 재지정한 뒤 삭제하는 순서로 처리해야 한다
