## 📝 상세 업무 내역

### 1. 사건관리 — 실시간 동기화(SSE) 전환

#### 착수 판단 — 보류돼 있던 결정을 비용 근거로 뒤집음

- **비용 구조 재산정** — 폴링이 60명에서 비싸질 것 같다는 문제 제기로 시작. 계산해보니 결론이 반대로 나왔다: 60명이 20초마다 각자 4개쯤 조회하면 초당 12요청이라 **업무시간 내내 인스턴스가 활성 단가**다. 즉 #186이 웹소켓을 보류한 근거("연결 유지 시간을 활성 단가로 과금")는 폴링도 이미 내고 있는 비용이었다. 실시간 전환이 오히려 싸다는 결론. (이슈 `#186` 코멘트, `#518` 신설)
- **단가 오류 발견** — `lib/polling.ts` 주석이 egress를 $0.12/GB로 잡고 있었는데 한국행 Premium tier 실제 단가는 **$0.19/GiB**. 폴링 비용이 약 1.6배 과소평가돼 있었다. 서울 리전이 Cloud Run **Tier 2**임도 공식 문서로 확정(Tier 1은 도쿄·오사카·타이완·유럽·미국).
- **팬아웃 방식 결정** — Cloud Run은 인스턴스가 여럿이라 A에서 난 변경을 B에 붙은 클라이언트가 못 받는다. Postgres `LISTEN/NOTIFY`(이미 쓰는 Cloud SQL, 추가 비용 0) / Pub/Sub(인스턴스별 구독 생명주기 관리 부담) / Memorystore Redis(월 ~$35로 절감액 상쇄) 중 첫째로 확정.

#### 백엔드 — 브로커와 스트림

- **`core/events.py` 신설** — LISTEN이 커넥션을 영구 점유하므로 SQLAlchemy 풀이 아닌 **전용 raw 커넥션을 별도 스레드**에서 `select()`로 돌리고, `loop.call_soon_threadsafe`로 접속자별 asyncio 큐에 전달. 끊기면 지수 백오프로 재연결. 동기 스택(psycopg2)에서 비동기 SSE를 쓰기 위한 구조다. (`6123e90`)
- **자동 발행 — 엔드포인트 50곳을 안 고쳤다** — `core/audit.py`가 쓰는 것과 같은 세션 훅(`after_flush`+`after_commit`)으로 ORM 변경을 통째로 잡는다. 엔드포인트마다 `emit()`을 심으면 새 엔드포인트가 생길 때마다 빠뜨리는데 이 방식은 그럴 여지가 없다. audit과 달리 `actor_email` 조건을 걸지 않아 **크롤러가 채우는 법원 진행상황도** 신호가 나간다. 테이블 17개 → 리소스 8개 매핑, 한 flush에서 10건 초과면 "전체 갱신" 1건으로 접어 대량 갱신이 신호 폭주로 번지는 걸 막는다. (`6123e90`)
- **`api/events_api.py` — `GET /api/events`** — 25초 keepalive로 유휴 연결 판정을 피한다. (`6123e90`)

#### 프론트엔드 — 구독과 캐시 무효화

- **`lib/realtime.ts` 신설** — `EventSource`가 아니라 **`fetch` + ReadableStream**을 썼다. `EventSource`는 헤더를 못 붙여 JWT를 쿼리스트링에 실어야 하고 그러면 액세스 로그에 토큰이 남는다. 재연결·지터는 어차피 직접 구현해야 해서 자동 재연결을 포기해도 손해가 없다. 지수 백오프 + 지터로 배포 직후 전원 동시 재연결(thundering herd)을 방지. (`a2088a1`)
- **유휴 탭 연결 종료** — `visibilitychange`로 탭이 숨겨지면 끊고 복귀 시 재연결. 탭을 켜둔 채 퇴근하면 그 연결 하나가 인스턴스를 밤새 활성 단가로 붙잡아 **월 $60가 붙는다** — 최적화가 아니라 필수 동작이라 1차 구현에 포함. (`a2088a1`)
- **`hooks/useRealtimeSync.ts` 신설** — 리소스 → queryKey 접두사 매핑. 접두사 매칭이라 `['cases']` 하나로 목록·상세가 전부 걸린다. 300ms 창으로 신호를 병합해 한 번의 저장이 만든 여러 신호가 같은 쿼리를 연달아 다시 받는 걸 막는다. (`a2088a1`)
- **연결 중복 경합 수정** — `connect()`의 `finally`가 무조건 재연결을 예약해서, 빠른 탭 전환·StrictMode 이펙트 2회 실행에서 연결이 둘로 겹쳤다. 자기가 현역일 때만 예약하도록 수정. (`a2088a1`)

#### 폴링 제거와 배포 설정

- **폴링 27곳 + `lib/polling.ts` 삭제** — 사건목록·사건상세(7개 쿼리)·타임라인·법원진행·계약(목록·상세)·미수금·열람등사·수발신·상담료·상담대기열·결재함·알림벨. `useReceivables`/`useDocumentLogList`의 `pollMs` 옵션도 제거. 수발신문서 조회범위 연동 게이팅(#496)도 함께 걷어냈다 — 전체기간이 gzip 834KB라 20초로 돌리면 월 $130을 넘던 게 게이팅 이유였는데, 신호 기반이라 조회범위와 무관하게 항상 최신이면서 전송량은 오히려 줄었다. (`5bcd062`)
- **빼기 전에 잡은 것** — 폴링 대상 화면 중 결재함(`approval-inbox`)만 무효화 매핑에 없었다. 그대로 제거하면 **전적으로 남이 채우는 큐**가 자동 갱신을 잃는 상태였다. 결재 미리보기 단건 조회와 함께 매핑에 추가. (`5bcd062`)
- **Cloud Run 설정** — `--timeout 3600`(기본 300초면 SSE가 5분마다 끊긴다), `--concurrency 250`(SSE 연결이 슬롯을 연결 내내 점유해 기본 80이면 60명에 75%가 차서 일반 요청과 경합). `--cpu`는 1000m 유지 — **1 vCPU 미만이면 Cloud Run이 최대 동시성을 1로 강제**해 연결 하나당 인스턴스 하나가 뜨므로 SSE와 양립 불가. (`6159d94`)

#### 업무시간 예열창 08:30~19:30

- **야간·주말 인스턴스 해제** — 예열창을 평일 08:30~19:30 KST로 좁혀 월 약 $13 절감. 창 밖이라고 서비스가 죽는 게 아니라 접속하면 인스턴스가 뜨고 쓴 만큼만 과금된다. 업무시간 근거는 `hearing_refresh_scheduler`가 09:00~19:00로 도는 것에서 앞뒤 30분 여유. 예열 1시간당 월 약 $2.94. (`efa7dda`)
- **반드시 서비스 레벨이어야 하는 이유** — `--min-instances`는 **리비전 레벨**이라 토글마다 새 리비전이 배포되고 그러면 하루 두 번 SSE 연결이 전원 끊긴다. 서비스 레벨 `--min`은 리비전을 새로 만들지 않는다. `setup_warmup_window.sh` 신설(1회 실행, 재실행 안전). (`efa7dda`)
- **플래그를 빼기만 해서는 해제되지 않았다** — `gcloud run deploy`는 지정하지 않은 설정을 **이전 리비전에서 물려받으므로** 옛 값(1)이 계속 따라왔다. 리비전 00219에서 실제로 `minScale=1`이 남은 걸 확인하고 `--min-instances default`로 명시적으로 비웠다. (`18ca42c`)
- **`gcloud`로는 잡을 만들 수 없었다** — `gcloud scheduler jobs create http --http-method`가 **PATCH를 거부한다**(delete/get/head/post/put만). Cloud Run Admin API v2에서 부분 수정은 PATCH뿐이라 Cloud Scheduler REST API로 직접 생성(본문 base64). 검증부도 두 곳이 조용히 빈 값을 돌려주고 있었다 — `describe`는 v1(Knative) 표현이라 서비스 레벨 `scaling`이 아예 없고, `jobs list --filter`는 이름 패턴에 안 걸렸다. 둘 다 REST로 교체. (`8b014c7`)

### 2. 사건관리 — 운영에서만 터진 장애 3건 (로컬 검증으로 못 잡은 것들)

로컬(도커 DB + uvicorn + vite)에서 팬아웃·세션훅·브라우저 연결까지 전부 확인했는데도 운영에서 SSE가 붙지 않았다. 원인이 겹쳐 있었고 **셋 다 로컬에 없는 계층**에서 났다.

- **① gzip이 SSE를 압축 대기** — `GZipMiddleware`가 `minimum_size`(1000B) 충족 여부를 판단하려고 첫 청크를 물고 기다리는데, SSE 신호는 12~60바이트라 1000바이트가 영원히 안 찬다. 본문은 물론 **응답 헤더조차 나가지 않는다.** 프론트가 `Accept-Encoding: identity`를 보내는데도 재현된 이유는 Cloud Run 프론트엔드(GFE)가 그 헤더를 정규화하기 때문. 클라이언트 헤더에 의존하지 않고 `SseAwareGZipMiddleware`로 **경로로 판정**하게 고쳤다. (`8550f58`)
- **② `is_disconnected()`가 첫 호출부터 `True`** — 스트림이 `: connected` 한 줄만 남기고 200으로 즉시 닫혔다. 액세스 로그만 봤을 땐 "기록이 없다 → 매달렸다"로 오해했는데, **애플리케이션 로그에 `200 OK`가 1초 안에 찍힌 걸** 보고서야 "끝난 것"임이 드러나 원인을 특정했다. 이 검사는 애초에 불필요하다 — 클라이언트가 끊기면 Starlette가 제너레이터를 취소하고 `finally`가 구독을 해제하며, 25초 keepalive 쓰기 실패가 죽은 소켓을 더 확실히 잡아낸다. (`fd87359`)
- **③ Firebase Hosting이 스트리밍을 버퍼링** — `case-manager.lawwin.co.kr`은 `firebase.json`의 `**` rewrite로 **Firebase Hosting(Fastly CDN) → Cloud Run** 경로를 탄다. 도메인 경유는 응답이 아예 없고(status 000) run.app 직접 주소로는 정상이라는 대조로 갈라냈다. SSE만 `VITE_SSE_BASE_URL`로 run.app에 직접 붙이고, REST는 그대로 도메인을 써서 정적 자산 CDN 캐싱을 유지. 크로스 오리진이 되므로 `CORS_ALLOWED_ORIGINS`에 운영 도메인 추가. 근본 해결(도메인을 Cloud Run 매핑으로 이전)은 DNS·인증서 작업이라 별도 과제로 남김. (`6e7f659`)
- **부수 정리** — `Accept-Encoding: identity` 헤더 제거. 브라우저 금지 헤더라 fetch에서 무시되는데 curl 테스트에서만 먹혀 "우회했다"는 착각을 유발한 항목이었다. (`6e7f659`)

### 3. 사건관리 — 사건상세 초록색 강조 오작동

- **새로고침만 해도 전 섹션이 물들던 문제** — 사이드패널·풀페이지 모두 기일·법원진행·일정·연결사건·수발신·수납이 전부 강조됐다. 원인은 쿼리를 `const { data: hearings = [] }`로 받아 강조 훅에 넘긴 것 — 데이터가 오기 전 렌더에서 그 **빈 배열이 비교 기준으로 잡히고**, 실제 데이터가 도착하는 순간 모든 행이 "새로 생긴 행"으로 판정된다. 훅은 `undefined`를 "아직 기준 없음"으로 보고 첫 로드를 건너뛰도록 설계됐는데 기본값이 그 설계를 무력화했다. **기본값을 안 준 `records`(열람등사)만 정상이었던 게 단서.** (`860b701`)
- **조치** — 쿼리를 `~Raw`로 받아 강조 훅에 그대로 넘기고 렌더용 배열은 `useMemo`로 따로 파생. 덤으로 `useMemo` 의존성 경고 7건도 해소됐다(`?? []`가 렌더마다 새 배열을 만들어 하위 `useMemo`들이 매 렌더 재계산되던 것). 이 함정은 `DocumentLogListPage`에 주석 경고까지 있었는데 사건상세엔 적용이 안 돼 있어서, `useCaseSectionHighlights` 문서주석에 "호출부는 raw를 넘길 것"을 명시해 재발을 막았다. (`860b701`)

### 4. 사건관리 — 공휴일 API 키 두 번째 유실 (이슈 `#521`)

- **운영에 키가 없었다** — `DATA_GO_KR_SERVICE_KEY`(공공데이터포털 특일정보)가 `case-management_env`의 20개 키 중에 없었다. `PROJECT_SPEC §216`에 "2026-08-18 누락 확인 → 재설정 완료"로 기록돼 있는데 **또 없어진 것**이다. (`3d6f805`)
- **왜 아무도 몰랐나 — 조용히 폴백하는 구조** — `core/holidays_kr.py`는 키가 없으면 앱을 죽이지 않고 빈 공휴일 목록으로 폴백한다. 그러면 열람/등사 도과알림의 N영업일 계산이 주말만 제외하고 **공휴일은 무시한 순수 달력 계산**이 된다. 틀린 날짜로 발송되는데 에러는 없다.
- **지금 증상이 안 보이는 이유 — 시한폭탄** — `system_settings`에 `holidays_2026`이 캐싱돼 있다(2026-07-13 저장, 키가 있던 시절). 그래서 올해는 정상이고, **연도가 바뀌어 `holidays_2027`을 조회하는 순간 조용히 틀어진다.**
- **묶음이 아니라 전용 시크릿으로** — 실패 방식이 "app.env를 다시 만들면서 한 줄이 빠진다"인데 묶음 파일은 키별로 보이지 않아 빠진 걸 알 수 없다. 전용 시크릿이면 배포 스크립트 `--set-secrets`에 이름이 박혀 **빠뜨리면 배포가 실패**한다(VAPID와 같은 이유, CLAUDE.md §13). 값은 로컬 `.env`에서 파이프로 주입해 노출 없이 넣고 문자열 일치를 확인(64자). `backend/.env.example` 신설(그전까지 0바이트 빈 파일) + `DEV_STATUS §7-61` 기록. (`3d6f805`)

### 5. 홈페이지 V2 — 회생 상담 접수 창구 단일화 (이슈 `#81`)

### 6. 홈페이지 V2 — 상담봇 스펙 확정 (이슈 `#125`)
