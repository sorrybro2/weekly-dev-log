## 📝 상세 업무 내역

### 1. 홈페이지 V2 — AI 상담봇 검색·모델 호출·대화 처리 (이슈 #125)

#### 검색과 생성 경로를 서비스로 연결

- **모델·리전 운영 전제 정리** — 기존 명세의 미확인 상태를 실호출 기록으로 갱신하고, 서울에서 사용 가능한 모델 구성과 향후 교체 준비를 정리했다.
  `docs/ai-chat-spec.md`에 단일 생성 모델 선택, 예산 알림의 목적, 모델·리전 환경변수 분리 방침을 반영했다.
  이전 확인 결과의 문서 반영과 당일 추가 조사를 구분하고, 리전 이전의 법무 판단은 미결정으로 남겼다. (`f8fc400`)

- **검색 서비스 이식** — CLI에서 평가한 검색과 실제 서비스의 결과가 달라지는 위험을 줄이기 위해 순위 합산 검색을 백엔드로 옮겼다.
  `backend/src/chat/chat-retrieval.service.ts`에서 원본 게시물의 공개 상태를 매번 확인하고, 의미 검색에 근거가 없으면 문자 검색 결과도 배제한다.
  동일 벡터를 사용한 CLI·서비스 대조에서 결과 순서까지 일치한 기록을 확인했다. (`04234c2`)

- **모델 사고 서명 저장 구조 준비** — 모델 교체 시 대화 데이터 구조를 다시 변경하는 부담을 줄이도록 서명 목록을 저장할 자리를 추가했다.
  `backend/prisma/schema.prisma`와 `migration/sql/20260923_chat_thought_sig.sql`에 대화 메시지용 JSONB 컬럼을 정의했다.
  현재 모델에서 사용하지 않는 값은 비워 두며, 새 모델 적용 자체가 완료된 것은 아니다. (`51e1dd2`)

- **Vertex AI 접근 계층 구현** — 인증·임베딩·답변 생성·SSE 수신을 한 서비스로 분리해 대화 정책과 모델 연결 코드의 결합을 줄였다.
  `backend/src/chat/chat-vertex.service.ts`에 실행 환경 자격증명 인증과 모델·리전 설정, 응답 사용량·사고 서명 수집을 구현했다.
  호출 실패는 상위 대화 서비스가 상담 접수 안내로 처리하도록 전달한다. (`4f88ff4`)

- **SSE 응답이 비는 문제 수정** — 모델 응답은 도착했지만 CRLF 구분자를 처리하지 못해 본문이 비던 파서를 수정했다.
  `backend/src/chat/chat-vertex.service.ts`가 LF·CRLF 이벤트 경계를 모두 인식하도록 변경했다.
  실제 모델 응답으로 조각 수신, 사용량 집계, 종료 사유와 출력 검사 연결을 확인한 기록을 남겼다. (`01a2df5`)

- **대화 요청 전체 처리 연결** — 개별 검색·생성 기능을 한 요청으로 묶어 한도 확인부터 검색, 답변 생성, 검사, 저장까지 이어지게 했다.
  `backend/src/chat/chat.service.ts`, `chat.controller.ts`, `chat-prompt.ts`, `chat-branches.service.ts`에 SSE 엔드포인트와 대화 처리 흐름을 구성했다.
  연락처는 코드가 검증된 지사 정보로 붙이고, 접속 IP는 서버에서 판단하며, 검색 근거와 차단 여부를 함께 저장한다. (`867dfe7`)

#### 대기 시간·남용·출력 오류를 제어

- **시간 예산 기반 재시도** — 호출 실패 때 재시도 횟수만큼 오래 기다리던 동작을 임베딩·생성의 제한 시간과 남은 요청 예산으로 제어했다.
  `backend/src/chat/chat-vertex.service.ts`와 `chat-caps.ts`에 지터, 남은 예산을 넘는 대기 생략, 스트리밍 시작 후 재시도 금지를 반영했다.
  429·서버 오류를 주입한 검증으로 제한 시간 안에서 실패를 반환하고 상담 안내로 전환할 수 있음을 확인했다. (`5282276`)

- **남용 방어 기준 확정** — 실제 상담 본문 길이와 호출 사용량을 근거로 입력·대화·IP 한도를 재검토하고 전역 일일 한도를 명세에 추가했다.
  `docs/ai-chat-spec.md`에 최근 대화만 재전송하는 정책과 시간 예산을 정리해 긴 대화와 분산 요청의 비용 증가를 제한하도록 했다.
  정상 개발 요청에서도 429가 관측돼, 이를 곧바로 남용으로 판정하지 않도록 운영 전제도 바로잡았다. (`d48bf9c`)

- **운영 알림 모듈 공용화** — 상담봇이 정보실 알림을 사용하기 위해 레거시 동기화 모듈에 의존해야 하던 구조를 정리했다.
  `backend/src/legacy-sync/ops-notify.service.ts`를 `backend/src/notify/ops-notify.service.ts`로 옮기고 각 모듈의 참조를 갱신했다.
  기존 알림 동작을 유지하면서 여러 기능에서 같은 운영 알림 경로를 사용할 수 있게 했다. (`6d7f9da`)

- **전송 전 금지 표현 검사·한도 알림** — 스트림의 개별 조각 대신 누적문을 검사하고, 위반 표현을 담은 조각은 전송하지 않은 채 생성을 중단하도록 했다.
  `backend/src/chat/chat.service.ts`에 스트리밍 차단과 전역 사용 한도 임박·도달 알림을 구현했다.
  문턱값에서만 알리는 방식으로 반복 알림을 억제했으며, 조각 경계에 걸친 금지 표현과 알림 경계값 검증 기록을 남겼다. (`838e1df`)

- **안전한 답변도 차단하던 오판 수정** — 스트리밍 중 잘린 URL을 완성된 주소로 해석해 허용 목록에 없다고 판단하던 문제를 수정했다.
  `backend/src/chat/chat.service.ts`에서 금지 표현 검사는 누적 스트림에 유지하고, 연락처·URL 허용 목록 검사는 응답 완료 후로 옮겼다.
  검사 성격에 따라 시점을 분리해 안전장치를 유지하면서 정상 답변의 불필요한 대체를 줄였다. (`6dc14fe`)

- **모듈 의존성 누락 수정** — 타입 검사로 드러나지 않던 알림 서비스 의존성 누락이 백엔드 기동을 막는 원인을 확인하고 수정했다.
  `backend/src/chat/chat.module.ts`에 알림 모듈을 명시적으로 가져오도록 등록했다.
  상담봇 기능 추가가 사이트 전체 API 서버의 시작 실패로 이어질 수 있는 문제를 제거했다. (`acefe74`)

### 2. 홈페이지 V2 — 상담봇 화면·대화 맥락·접수 흐름 (이슈 #125)

#### 스트리밍 화면과 대화 진입

- **답변 교체 UX 명세** — 출력 검사로 답변이 대체되는 상황을 정상 흐름으로 정의하고, 작성 중인 문장과 확정된 답변의 표시 규칙을 정리했다.
  `docs/ai-chat-spec.md`에 스트리밍 도중 표시, 차단 시 교체, 사용 한도 도달 시 상담 안내, 런처 배치 제약을 기록했다.
  프런트가 안전장치 작동을 단순 오류나 문장 유실로 표현하지 않도록 구현 기준을 마련했다. (`1132257`)

- **상담봇 런처·패널 구현** — 공개 사이트의 PC 채널 버튼 묶음과 모바일 하단 상담바 위에 상담봇 진입점을 추가했다.
  `frontend/src/components/chat/`과 `frontend/src/features/chat/use-chat.ts`에 SSE 수신, 작성 중 표시, 차단 답변 교체, 반응형 패널을 구현했다.
  클라이언트 래퍼로 초기 화면 로딩과 충돌을 피하고, 탭 종료 시 대화 키가 남지 않게 처리했다. (`5cc1858`)

- **되묻기·진행 표시·근거 카드 도입** — 분야 이름만 입력해도 성급히 답하던 흐름을 사연 확인으로 바꾸고, 이때는 검색을 생략하도록 했다.
  `backend/src/chat/chat.service.ts`, `chat-prompt.ts`와 `frontend/src/components/chat/chat-panel.tsx`에 처리 단계 표시와 제목·사진 카드, 상담 페이지 사전 선택을 연결했다.
  카드 제목의 결과 표현도 정제해 답변에서 막은 문구가 별도 UI로 노출되는 경로를 줄였다. (`df18a21`)

#### 사연 확인부터 상담 신청까지

- **분야별 추가 질문·대화 내 접수** — 사연의 부족한 정보를 분야에 맞게 묻고, 긴급 상황은 전화 안내로 연결하도록 대화 흐름을 확장했다.
  `backend/src/chat/dto/chat-intake.dto.ts`, `chat.controller.ts`, `chat.service.ts`와 `frontend/src/components/chat/chat-panel.tsx`에 동의 기반 접수 폼과 전화 버튼을 구현했다.
  이름·연락처는 폼에서 받고 대화 내용은 이어 전달하며, 기존 상담 접수 경로의 제한·알림 기능을 재사용한다. (`8fe22d0`)

- **이전 대화의 사건·지역 유지** — 후속 답변에 사건명이 없으면 엉뚱한 분야를 검색하고, 이미 말한 지점도 잊던 문제를 대화 이력 기반으로 수정했다.
  `backend/src/chat/chat.service.ts`, `chat-prompt.ts`에서 검색 입력과 지점 판정에 앞선 사연을 반영하고, 관련 질문을 묶어서 하도록 정리했다.
  `frontend/src/components/chat/chat-panel.tsx`는 실제 제목 중심의 카드로 바꾸고 동일 사건 중복 제거와 지역 우선 표시를 반영했다. (`7340482`)

- **담당 변호사·사무소 표시** — 근거 사례가 어느 사무소와 변호사의 사건인지 알 수 있도록 카드 정보를 보강했다.
  `backend/src/chat/chat.service.ts`와 `frontend/src/components/chat/chat-panel.tsx`에 변호사 사진·이름과 사무소를 추가했다.
  레거시 변호사 정보 파싱 실패는 카드 전체 실패로 번지지 않게 하고, `cloudbuild.backend.yaml`에는 리전 설정을 임의 변경하지 않는 배경을 기록했다. (`4a33e30`)

- **지점 확정·진입점 개선** — 지점 미선택 상태에서 본사 연락처로 안내되던 흐름을 지점 버튼 선택으로 보완하고, 부정된 지역보다 나중에 선택한 지역을 우선하도록 했다.
  `backend/src/chat/chat-branches.service.ts`, `chat.service.ts`와 `frontend/src/components/chat/chat-launcher.tsx`, `chat-panel.tsx`를 수정했다.
  최초 안내 말풍선과 고정 서비스 설명을 추가하고, 런처의 시각적 구분을 강화해 상담봇의 목적과 진입 위치를 알렸다. (`9411a3f`)

- **근거 카드 노출 기준 강화** — 추가 질문 중이거나 관련성이 약한 사례까지 확신 있는 근거처럼 보이던 문제를 별도 화면 노출 기준으로 제어했다.
  `backend/src/chat/chat.service.ts`에 검색 통과 기준보다 엄격한 카드 기준과 복수 근거 조건을 추가했다.
  모델에 전달하는 검색 자료는 유지하면서 사용자에게 전면 노출할 사례만 추려 보여주도록 분리했다. (`40933db`)

### 3. 홈페이지 V2 — 상담봇 운영 준비·색인 안정화 (이슈 #125)

- **운영 문서 최신화** — 저장소 설명이 실제 상담봇 구조와 배포 환경을 반영하지 못하던 부분을 정리했다.
  `README.md`에 대화 처리 흐름, 코드와 모델의 역할, 분리 운영 중인 도메인, 환경변수·인증·색인 도구와 배포 명령을 추가했다.
  스키마 수동 적용과 백엔드 실제 기동 확인을 명시해 개발 환경의 성공을 운영 준비 완료로 오인하지 않도록 했다. (`daee05a`)

- **모델 리전 비교 측정 도구** — 서울의 생성 실패가 얼마나 지속되는지 판단할 자료를 얻기 위해 지역별 호출 결과를 기록하는 도구를 추가했다.
  `scripts/chat-region-probe.mjs`에 반복 호출·인증 갱신과 네트워크 실패·한도 응답 구분을 구현하고 `.gitignore`에서 측정 결과를 제외했다.
  서울·도쿄를 비교할 수 있게 해 서비스 전체 장애와 특정 지역의 가용성 문제를 구분할 근거를 마련했다. (`ab0b69b`)

- **운영 DB 적용 절차 작성** — 마이그레이션 SQL이 커밋돼도 운영에 자동 적용되지 않아 상담 요청이 실패한 일을 바탕으로 준비 절차를 문서화했다.
  `docs/ai-chat-prod-setup.md`에 테이블·컬럼 적용, 소량 색인, 전체 적재, 운영 SSE 확인, 프런트 배포 순서를 적었다.
  비밀번호를 파일에 남기지 않는 방식과 지역별 가용성 확인·측정 작업 정리 절차를 함께 기록했다. (`955d370`)

- **문장 경계 없는 장문 색인 오류 수정** — 문장 부호가 없는 글이 하나의 큰 조각으로 남아 임베딩 요청을 실패시키던 문제를 수정했다.
  `scripts/chat-index.mjs`에 길이 기준의 추가 분할과 앞 조각 일부를 겹치는 처리를 넣었다.
  입력 자동 잘라내기로 내용을 조용히 버리는 대신 원문을 나누어 적재하도록 해 긴 지식센터 글도 색인을 진행할 수 있게 했다. (`b9465ce`)

**운영 조치 — 코드 커밋 외 이슈 기록**

- **운영 DB 누락 확인·적용** — 백엔드 배포 뒤 실제 요청에서 `tbl_chat_session` 부재를 확인했고, 상담봇 테이블과 `thought_sig` 적용을 완료한 기록을 확인했다. 프런트 공개 전에 운영 DB를 검증한 과정이며, 해당 코멘트 시점의 색인 상태는 진행 중이었다. (이슈 `#125`)
- **서울 생성 용량 문제 관측** — 서울의 생성 요청 실패와 다른 지역의 정상 응답을 대조하고, Cloud Scheduler에 서울·도쿄 비교 측정을 설정했다. 리전 변경은 개인정보 처리와 관련한 법무 검토가 필요한 선택지로 남겼으며, 지속 관측으로 유지·이전·용량 확보 방안을 판단하도록 했다. (이슈 `#125`)
