## 📝 상세 업무 내역

### 1. 홈페이지 V2 — AI 상담봇 설계 스펙 3차 검토 (이슈 #125)

- **외부 자료를 스펙과 1:1로 대조했다** — Cloudflare 세션 자료 *AI Build and Protection* 26면을 설계 스펙과 맞대어, 채택 5건·반대 4건을 근거와 함께 `docs/ai-chat-cloudflare-review.md`(신규)에 남겼다. 검토 결과만 스펙 §15로 옮겨 본문이 부풀지 않게 했다. (`1f42041`)
- **플랫폼 이전 비채택 — 근거를 무효화하는 결정이기 때문** — 스펙 §2가 Vertex를 고른 이유는 "대화 내용이 곧 민감 개인정보라 국외이전 고지 문제를 아예 만들지 않는다"이다. 엣지 실행은 정의상 글로벌이고 데모 모델은 중국계 오픈모델이라, 상담 원문을 그 경로에 태우면 §2를 통째로 폐기하는 결정이 되고 키 없는 ADC 인증도 잃는다. 데이터는 Cloud SQL에 남으므로 GCP를 다시 부르는 왕복만 늘 뿐이다. (이슈 `#125`)
- **"Agent" 프레이밍도 비채택** — 자율 목표 루프는 §1의 "의도적으로 하지 않는 것"과 충돌한다. 3중 검색 팬아웃(§4.1 RRF 확정분 유지)과 사람 승인 루프도 불채택 — 후자는 `submit_consult`의 사용자 명시 동의가 이미 승인 게이트다. (이슈 `#125`)
- **정작 강의가 정확히 짚은 것은 관측의 부재** — 599줄 스펙에 관측 항목이 0건이었다. 검색·비용·가드레일·품질측정은 강의보다 깊은데 "돌아간 뒤에 무엇이 남는지"만 비어 있었다. 이 한 축으로 4건을 채택했다. (`1f42041`, `docs/ai-chat-spec.md` §15)
- **추적 ID로 두 영역 로그를 잇는다(§15.2)** — Cloud Run 요청 로그와 Vertex 호출은 관측 범위가 다르다. Cloud Run이 이미 주는 `X-Cloud-Trace-Context`를 공통 식별자로 써 `tbl_chat_message.traceid`에 남기면 **추가 계측 비용 없이** 어드민 대화 로그에서 Cloud Logging으로 바로 넘어갈 수 있다. (`1f42041`)
- **검색 근거 보존이 가장 값어치 있는 채택(§15.3)** — §6-2는 근거 URL 첨부를 정책으로 못 박았지만 그 근거를 저장하지는 않았다. `tbl_chat_message.evidence jsonb`에 선택된 청크 id·`score_lex`·`score_vec`·`rrf`·모델·지연을 턴마다 남긴다. **§14.4가 이미 이걸 전제하고 있었다** — 운영 중 실패한 답변에 무엇이 검색됐는지 기록이 없으면 Recall@5 튜닝이 오프라인 골든셋 50문항 안에 갇히고, 실제 의뢰인 표현으로 골든셋을 늘리는 경로가 막힌다. 지금은 컬럼 하나지만 Phase 2 이후엔 마이그레이션이다. (`1f42041`, 이슈 `#125`)
- **출시 게이트를 단계 표 뒤에 추가(§15.4)** — §10에 "이걸 만족하면 공개한다"가 없었다. 체크리스트는 검토 문서에 두고, 지금 값을 정해야 하는 것은 Recall@5 목표치와 kill switch env 두 가지로 좁혔다. (`1f42041`)
- **⚠ 착수 전 결정 항목 하나가 새로 드러났다(§9-7)** — 강의의 inbound 통제를 우리 토폴로지에 대보니 적용할 지점이 없었다. 브라우저 → ALB → 프론트에는 Cloud Armor를 붙일 수 있지만, 브라우저가 백엔드 Cloud Run을 **직접** 호출하는 `/api/chat`에는 앞단이 없어 앱 코드가 1차 방어선이다. 그런데 §7이 스스로 "Cloud Run은 인스턴스가 여러 개라 메모리 스로틀러는 장시간 창에서 사실상 무방비"라고 적어 뒀고, LLM 호출은 건당 비용이 커서 여기가 곧 금액이다. (A) Next.js route handler 프록시, (B) ALB에 백엔드 NEG 추가, (C) 현행 유지 — 세 안과 트레이드오프를 스펙에 남겼다. **SSE 경로를 짜기 전에 정해야 한다.** (`1f42041`, 이슈 `#125`)
- **확인하지 못한 것을 명시했다(§15.5)** — 모델 호출 직전 검사(강의의 AI Gateway DLP)에 대응하는 GCP 관리형 제품은 Model Armor가 근접하나 `asia-northeast3` 가용성·한국어 탐지 품질·SSE 궁합을 확인하지 못했다. 확인 전까지 앱 내부 방어가 우리 방식이며, 그것을 "차단"이 아니라 "피해 감소"로 표현하기로 했다. 또 Vertex request-response 로깅은 프롬프트 원문이 BigQuery에 적재되므로 **기본은 끈다**는 것을 함께 못 박았다. (`1f42041`)

### 2. 홈페이지 V2 — Phase 1 선행 확인과 점검 도구 수정

- **운영 DB에 쓰기 없이 착수 가능함을 확인했다** — `lawwin-pg`(운영, PostgreSQL 16)에서 실측해 `vector 0.8.1`·`pg_trgm 1.6`·`unaccent 1.1`이 이미 설치돼 있음을 확인했다. 이미지가 주는 버전(0.8.5)과의 패치 차이는 우리 용도(768차원·약 1~2만 청크·코사인)에 영향이 없고 HNSW·ivfflat 모두 0.7부터 있던 기능이라, 지금 `ALTER EXTENSION vector UPDATE`를 돌릴 이유가 없다고 판단했다. (`083ef04`, 이슈 `#125`)
- **점검 스크립트가 실패 원인을 숨기고 있었다** — `scripts/chat-preflight.mjs`가 DB 오류를 통째로 버리고 `{"code":"Error"}`만 출력했다. 자격증명 보호 의도는 맞지만 **실패를 진단할 수 없게 만드는 부작용**이 있었다. 접속 문자열의 비밀번호만 `***`로 치환하고 드라이버가 준 사유는 남기도록 바꿨다. 이 수정이 없었으면 `timeout expired`를 못 봤고 원인도 못 찾았다. (`083ef04`)
- **미설치와 미지원을 구분한다** — 기존에는 `pg_extension`(설치됨)만 조회해, 확장이 없을 때 "이 서버가 제공하지 않는 것"인지 "이 DB에 아직 `CREATE EXTENSION`을 안 한 것"인지 알 수 없었다. Cloud SQL은 이미지에 확장이 들어 있어도 DB마다 생성이 필요하므로 이 구분이 실제로 갈린다. `pg_available_extensions`를 함께 조회하도록 추가했다. (`083ef04`)
- **점검 대상 DB를 `backend/.env`로도 지정 가능하게** — 인라인 env 접두어 없이 다른 DB를 겨눌 수 있게 하고, 일회성 점검이 끝나면 키를 지우라는 주석을 함께 남겼다. (`083ef04`)
- **접속 경로 실측 결과를 문서 부록에 남겼다** — 공개 IP 직결은 승인된 네트워크가 0개라 타임아웃, 내 IP 허용목록 추가는 유동 IP라 항목이 죽고 일회성 조회에 운영 방화벽을 여는 비용이 커서 미채택, `cloud-sql-proxy`는 `gcloud auth login`만으로는 부족하고 ADC가 따로 필요, 최종적으로 Cloud SQL Studio로 조회했다. **직결을 택하면 TLS에서 한 번 더 막힌다** — 서버 인증서가 인스턴스 전용 Google 내부 CA 서명이고 `pg` 드라이버는 `sslmode=require`를 `verify-full`로 취급하므로, IP를 열어도 인증서 검증에서 실패한다. 이 함정을 `docs/ai-chat-preflight.md`에 남겨 다음 사람이 같은 시간을 쓰지 않게 했다. (`083ef04`, 이슈 `#125`)
- **다음 순서를 이슈에 못 박았다** — `tbl_chat_embedding` DDL은 `backend/prisma/migrations/`가 비어 있고 레거시 형상을 `db pull`로 가져다 쓰는 구조라 **raw SQL로 만들고 `db pull`로 역반영**한다(`prisma migrate dev`를 쓰면 기존 테이블을 건드린다). 이후 지식센터 803건 선적재 → RRF 검색 API → 골든셋 50문항 Recall@5 측정. (이슈 `#125`)

### 3. CRM — 모바일에서 상담 등록 입력폼이 보이지 않던 문제

- **입력폼이 40px 남짓으로 찌그러져 있었다** — 방문상담 유형에서 Google Calendar 미리보기를 입력폼 옆에 두는데, 모바일은 가로 폭이 부족해 미리보기가 폭을 차지하면 정작 입력해야 할 폼이 사실상 보이지 않았다. 좁은 화면에서는 미리보기를 아예 표시하지 않도록 조건을 좁혔다. (`62a6e33`, `consultation_form_screen.dart`)
- **데스크톱 동작은 건드리지 않았다** — 좌우 2단 배치는 기존 그대로다. 미리보기는 있으면 편한 보조 정보이고 입력폼은 이 화면의 목적이므로, 둘이 폭을 다툴 때 무엇을 버려야 하는지가 분명한 경우다. (`62a6e33`)

**금일 종합:** 오늘은 코드보다 **착수 전에 정해야 할 것을 정하는 날**이었다. 외부 강의 자료를 검토한 결과 실제로 가져올 것은 하나뿐이었지만(관측), 그 하나가 스펙에 완전히 비어 있던 축이었다. 특히 검색 근거 보존은 이미 스펙 §14.4가 전제하고 있으면서도 저장 경로가 없던 항목이라, 지금 컬럼 하나로 끝낼 것을 Phase 2 이후에 마이그레이션으로 치를 뻔했다. 반대로 플랫폼 이전과 자율 에이전트 확장은 "안 한다"를 근거와 함께 문서에 남겨, 다음에 같은 자료를 본 사람이 같은 논의를 반복하지 않게 했다. 값어치로 치면 점검 스크립트 수정도 작지 않다 — 실패 사유를 버리던 코드 때문에 원인이 `timeout expired`라는 것조차 볼 수 없었고, 그걸 고친 덕에 운영 DB 확장 설치를 확인해 **운영 DB에 손대지 않고 Phase 1을 시작할 수 있다**는 결론까지 갔다. 동시에 확인하지 못한 것(Model Armor 가용성)과 새로 드러난 결정 항목(`/api/chat` 앞단 통제)은 숨기지 않고 미결로 남겼다. 금일 2개 repo에 걸쳐 커밋 3건.
