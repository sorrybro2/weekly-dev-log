📋 *일일 업무 보고 (2026. 09. 04.)*

만든 것보다 재본 것이 많은 하루. AI 상담봇을 화면 시안, 대화 설계, 발주서, 제안서 편입까지 밀어 붙였고 그 과정에서 「초기 대응 안내 31건」 목록의 근거가 공급 통계라는 것을 스스로 의심해 레거시 상담 6,204건을 직접 집계했다. 보정에는 실패했으나(86%가 분야 미태깅) 대신 설계 판단 세 가지가 실측으로 검증됐다. 상담봇 근거를 찾다가 인프라 구멍 5개가 연달아 드러나 전부 이슈로 세웠고, 사건관리 앱에서는 8월 미수금 차액 10,836,000원을 1원 단위까지 분해해 결함 4건을 세웠다. 금일 커밋 3건(1개 repo), 이슈 10건 생성, 코멘트 9건.

🤖 *〔홈페이지 V2 : AI 상담봇〕*

•  *내가 만든 목록의 근거를 내가 깼다* — 안내 31건 배분을 해결사례 분포로 잡았는데 그건 우리가 처리한 사건이지 사람들이 물어본 말이 아니다. 레거시 상담 전수 집계로 검증했다
•  *보정은 실패* — 상담 1,960건 중 분야 태깅이 45건(2.3%) 뿐이라 수요 분포를 읽을 수 없다. 배분은 해결사례 기준을 유지하고 한계를 발주서에 명시
•  *대신 검증 1* — 최다 표현이 「경찰 조사」 9건, 0.5%. 어휘가 극도로 분산돼 키워드 매칭이 불가능함이 실측됐다. 벡터 검색 결정을 뒷받침 (340d123)
•  *대신 검증 2* — 가장 많이 묻는 것이 우리가 답하지 않기로 한 「결과」였다. 「가능성이 있는지」류 22건. 범위 밖 처리가 예외가 아니라 주력 경로다
•  *대화를 6턴에서 3턴으로* — 지역을 되묻는 단계를 통째로 삭제. 지역별 URL 구조라 보고 있는 페이지가 이미 지역이었다
•  *한 번 잘못 만들고 되돌렸다* — 발주서 서식을 그대로 화면 카드로 뿌렸다가 회수. 그건 대화가 아니라 FAQ 조회다. 원고 서식과 화면 말투는 별개
•  *명세에 없던 누락* — 만 14세 확인 게이트. 법무법인 챗봇에 미성년자가 사건 내용을 적는 것 자체가 문제라 앞단에서 막아야 한다
•  *산출물* — 시안(마케팅 회람), 질문답변 작성 요청(변호사 회람), 제안서 8면 PDF(대표 보고). 제안서에 「04 화면」 면 추가 (5473dc7)

🚀 *〔홈페이지 V2 : 인프라 구멍 5건〕*

•  *자동화가 하나도 없다* — Cloud Scheduler API 비활성, 백엔드 크론 없음, .github 디렉터리 자체가 없음. 오늘 터진 세 건이 전부 같은 뿌리다 (이슈 #131)
•  *밀린 것이 증명됐다* — 레거시 게시물 8443, 8444 가 등록일이 지났는데 라이브에서 404. 마케팅이 어드민에 올린 글이 V2 에는 안 뜬다
•  *썸네일 7건 복구* — 증분 동기화가 DB 행만 옮기고 업로드 파일은 안 옮긴다. 버킷 23,133키 전수 대조로 찾아 7건 전부 복구 (이슈 #126)
•  *이틀간 미배포였다* — 「업무분야」 이름 변경이 화면에 없던 원인이 코드가 아니라 배포. 배포가 커밋보다 2시간 55분 앞서 있었다. 배포 후 확인 완료 (이슈 #127)
•  *검색어를 안 쌓고 있다* — 히어로 한가운데 검색바가 있는데 무엇을 치는지 기록이 0. 접수까지 오지 않고 나간 사람의 관심사를 볼 유일한 데이터다 (이슈 #129)
•  *상담 DB가 갈려 있다* — 동기화 계획에 이미 있고 안 돌렸을 뿐. 다만 PK 충돌 시 V2 상담이 소리 없이 사라지므로 확인 전 적용 금지로 못박았다 (이슈 #130)
•  *공통 병목* — Cloud SQL 접속이 막혀 있어 오늘 확인 상당수를 우회 경로로 했다. 매뉴얼과 실제가 어긋난 상태라 다음 작업의 선행 과제

🏷 *〔홈페이지 V2 : 하단 상담바가 목록 마지막 줄을 덮던 문제〕*

•  *증상* — "페이지가 더 아래로 안 내려간다"로 읽혔다. 목록 끝 카드의 이름 줄이 계속 바 밑에 깔렸고 바가 뜨는 전 페이지 공통이었다 (이슈 #128)
•  *원인* — 고정 배치라 문서 높이에 몫이 없다. 푸터 회피 장치가 증상을 절반만 가려 버그로 안 잡히고 있었다
•  *조치* — 상수를 박지 않고 바 DOM 을 직접 재서 본문 아래를 비운다. 전문센터는 바를 숨기고 홈은 페이지 스크롤을 안 쓰며 높이도 두 종류라 상수로는 안 된다 (e0ae71e)
•  *걸린 함정* — 고정 배치 요소는 offsetParent 가 항상 null 이라 숨은 바를 못 거른다. 계산된 스타일로 판정해야 한다

💰 *〔사건관리 앱 : 미수금 정산과 결함 4건〕*

•  *8월 차액 10,836,000원이 1원 단위까지 설명됐다* — 원인 2개로 완전 분해. 시트 170행 중 149행이 앱에 없던 것은 베타 범위 밖이라 오탐으로 확인
•  *앱 8월 미납 19,345,000원 중 11,045,000원(57%)이 시트엔 이미 수납* — 동기화가 DB에서 시트로 가는 단방향이라 사람이 시트에 적은 입금을 앱이 못 읽는다 (이슈 #474)
•  *더 위험한 건 반대 방향* — 그 6건은 앱에서 메모 한 줄만 고쳐도 시트 금액이 빈칸으로 덮어써진다. 경고도 로그도 없다
•  *취소가 시트에 반영된 건이 하나도 없다* — 취소하는 순간 키를 만들 수 없게 되어 push 가 스킵된다. 구조적으로 쓸 방법이 없다 (이슈 #476)
•  *시트 중복 3건, 209,000원 이중계상* — 초 단위까지 동일한 시각이라 9/3 재동기화 스크립트가 유력. DB 기준 멱등이 시트 기준 멱등을 보장하지 않는다 (이슈 #475)
•  *시트가 아니라 DB 자체에도 중복이 있다* — 같은 사무소, 입금인, 금액, 입금일 활성 행이 2~3건씩. 27쌍 43,818,000원. 자동 생성 경로는 UNIQUE 로 막혀 있어 무관하고 전부 수기 입력 행이다 (이슈 #477)
•  *단 중복으로 단정하지 않았다* — 분납이나 별건 수임으로 같은 날 같은 금액을 두 번 받는 경우가 실제로 있다. 영수증 대조가 선행이고 실무자 확인이 필요하다
•  *전 과정 읽기 전용* — 운영 DB와 시트 모두 조회만 수행했고 변경 없음. 데이터 정리는 별도 승인 후
