📋 *일일 업무 보고 (2026. 09. 14.)*

사건관리 PC 업로드가 큰 파일에서 조용히 실패하던 원인(Cloud Run 요청 본문 32MB 하드 제한)을, 업로드가 있는 4개 기능 전부를 브라우저에서 Drive로 직접 올리는 방식으로 바꿔 제거했습니다. 그 과정에서 "스코프를 넓혀도 재동의가 먹지 않아 새 경로를 영영 못 타는" 구글 토큰 재발급 규칙 문제를 배포 전에 잡아, 운영에 나갔으면 원인 찾기 매우 어려웠을 사고를 막았습니다. 그 외 CRM 로그인 진입 차단 복구, 메인보드 운영 아이콘 깨짐 수정, 상담봇 연결 점검 도구를 붙였습니다. 금일 커밋 16건(4개 repo), 이슈 코멘트 5건.

📦 *〔사건관리 : PC 업로드 4개 기능 직접 업로드 전환 (#548, #549)〕*

•  *32MB는 설정으로 못 올림* — Cloud Run 플랫폼 하드 제한이라, 브라우저가 Drive와 직접 통신하는 것이 사실상 유일한 해법 (88bca99)
•  *4개 기능 전부 전환* — 수발신문서, 계약, 사건 Drive 패널, 수기일정. 같은 구조에 같은 위험이라 한 곳만 고치면 나머지 3곳이 그대로 남음 (3755c88, d7c3873, 008b76f, da1989c)
•  *스코프 확대가 숨은 선행 조건* — 기존 Drive Picker 토큰은 읽기 전용이라 업로드가 403. 이슈 계획에 없던 전제라 먼저 확인해 공유 (ae4e4c0)
•  *하드 컷오버 회피* — 재동의 전 사용자와 합계 25MB 이하는 기존 서버 경유로 폴백. 배포 시점에 전원이 동시에 재로그인할 필요가 없음
•  *서버가 폴더를 재검증* — 클라이언트가 이미 올린 결과를 기록하는 구조라, 검증이 없으면 파일은 개인 드라이브에 남았는데 대장만 정상으로 보임
•  *업로드 진행률 표시 추가* — 직접 업로드 경로에서만 표시. 서버 경유에 붙이면 전송이 끝나는 순간 100%가 찍히고 남은 구간 내내 멈춰 있어 오히려 거짓말이 됨 (abfdb3a, 8009dba)

🔐 *〔사건관리 : 재동의가 먹지 않던 버그를 배포 전에 발견〕*

•  *로그아웃 후 재로그인으로도 해결되지 않는 상태였음* — 구글은 새 동의를 받을 때만 토큰을 재발급하는데, 동의 이력이 있으면 동의 화면을 건너뛰어 옛 읽기 전용 토큰이 그대로 남음 (cf4ed75)
•  *로컬 실측으로 확정* — 저장된 토큰으로 직접 갱신해보니 7월 발급 스코프가 그대로였고, 재동의 뒤에도 새 경로가 한 번도 실행되지 않았음
•  *조치* — 로그인에 강제 동의 옵션 추가, 권한이 모자라면 안내 토스트를 세션당 1회. 강제 리다이렉트는 하지 않음 (폴백이 있어 무시해도 파일은 올라감)
•  *남은 한계는 숨기지 않고 이슈에 기록* — 32MB 한계 자체는 로컬 검증 불가(Cloud Run 제약), 진행률 토스트가 실제로는 뜨지 않는 것도 원인 미확인으로 후속 과제에 남김

🧭 *〔CRM : 로그인 진입 차단 복구와 문구 정정 (#14)〕*

•  *로그아웃 이력이 있는 브라우저는 영영 못 들어갔음* — 차단 플래그가 브라우저에 영구 저장돼, 한 번이라도 로그아웃하면 진입 시 구글에 세션을 물어보지도 않았음. 탭 수명 저장으로 이동 (481d982)
•  *이미 각인된 플래그까지 처리* — 판정 시 예전 플래그를 발견하면 지우고 무시. 사용자가 따로 할 조치 없음. 운영 로그에서 1초 만에 로그인된 사례로 복구 확인
•  *테스트가 통과하던 이유까지 교정* — 모바일 세션 저장소 스텁이 항상 빈 값을 돌려줘 차단 로직이 동작하지도, 검증되지도 않고 있었음
•  *회생 안내 문구 오기* — '별도 채무자'를 '별도 채권자'로 정정. 같은 문구가 입력 화면, 결과 화면, PDF, 이미지 4곳에 복사돼 있어 전부 함께 수정 (2d6caf2)
•  *운영 DB 읽기 전용 조회 스크립트* — 진입점을 파일 하나로 고정해 허용 규칙을 걸 수 있게 하고, 쓰기 SQL과 다중 문장은 거부. 비밀번호는 Secret Manager에서 그때그때 (e13d7b9)

🖼 *〔메인보드와 홈페이지 V2〕*

•  *운영에서 아이콘 2개만 깨짐* — 호스트 정규화 프록시가 이미지 최적화기의 내부 요청까지 308로 튕겨, 최적화기가 이미지 대신 리다이렉트를 받고 400을 냄 (c6c55ea)
•  *왜 그 둘만이었나* — 사건앱과 CRM 아이콘만 PNG라 최적화기를 거치고 나머지는 인라인 SVG였음. 증상이 좁아 추적이 늦어지기 쉬운 형태
•  *범위만 좁히고 동작은 유지* — matcher에서 정적 이미지 확장자 제외. 호스트 정규화 자체는 로그인 완주에 필요하므로 그대로 둠. 재현 검증과 테스트 41건 통과
•  *상담봇 연결 점검 도구* — 서울 리전 생성, 임베딩 모델을 실제로 1회씩 호출하고 DB 확장과 코사인 거리를 읽기 전용으로 확인. 비밀은 출력하지 않고 실패 시 종료 코드 1 (9924417)

🛡 *〔운영 판단 : 커밋 없음 (#107)〕*

•  *SCC 암호화 경고 재출현은 오탐* — 9월 3일 조치가 그대로 살아 있고 공인 IP 허용 목록도 비어 있음. 조치 불필요
•  *왜 또 떴나* — 경고 패널의 마지막 새로고침이 8월 3일로 조치보다 앞선 캐시 판정이고, 디텍터가 폐기된 옛 필드를 볼 가능성
•  *음소거는 하지 않기로 선회* — 리스크가 0인 항목을 숨기려다 다른 경고까지 가릴 여지를 만들 이유가 없음. 대신 실측 로그를 이슈에 남겨 다음 확인 비용을 없앰
•  *원복 1건 남음* — 음소거 시도 중 켠 SCC API가 불필요하게 켜진 상태(요금 영향 없음, 위생 차원). 비활성화 명령은 자동승인 분류기가 막아 수동 실행 필요

✅ *〔금일 종합〕*

•  *가장 값어치 있던 것* — 기능 구현보다, 배포 전에 재동의 버그를 실측으로 잡아낸 것. 그대로 나갔으면 전 직원이 재로그인을 반복해도 새 경로가 열리지 않았음
•  *잘한 판단* — 문서대장 한 곳만 고치지 않고, 같은 릴레이 구조가 4곳에 있다는 것을 먼저 확인해 공통 해법으로 묶은 것
•  *되돌린 판단 1건* — SCC 경고 음소거. 실제 리스크가 0인 항목을 숨기는 편익보다 다른 경고를 가릴 위험이 큼
•  *오늘 배운 것* — 테스트가 통과한다고 검증된 게 아니라는 것. CRM 차단 로직은 스텁이 빈 값만 돌려줘 동작하지도 않으면서 통과하고 있었음
