- **대화 흐름 정비**: 새로고침 시 예전 대화를 이어받던 문제 수정, 기다리는 동안 실제 판단 과정 표시, 사례 카드 3건 고정.

## 📝 상세 업무 내역

### 1. 홈페이지 V2 — 상담봇 공개 범위·리전 (이슈 #125, #135)

- **상담봇 직원 전용 전환** — 고지·동의·파기 장치 없이 실제 의뢰인 사연이 운영 DB에 쌓이고 있어 외부 공개를 거뒀다.
  `frontend/src/components/chat/chat-provider.tsx`가 로그인 세션이 있을 때만 위젯을 세우고, `frontend/src/lib/chat-proxy.ts`와 `/api/chat/ask`·`intake` 라우트가 로그인 확인 후 백엔드로 넘긴다.
  백엔드 `/chat`에는 `x-admin-key` 가드를 붙이고, 사무실이 공인 IP 하나를 나눠 써서 직원 한도는 사람 단위로 세도록 했다. (`001e24e`)

- **생성 리전만 도쿄로 분리** — 서울 `gemini-2.5-flash`가 공유 쿼터 소진으로 당일 실측 전부 429, 도쿄는 전부 성공한 결과를 근거로 생성 호출만 옮겼다.
  `backend/src/chat/chat-vertex.service.ts`에서 생성은 `CHAT_GENERATE_LOCATION`, 임베딩·DB는 서울을 쓰게 나눴다.
  값을 비우면 한 리전으로 돌아가 환경변수 하나로 되돌릴 수 있다. (`bfb050b`)

**운영 조치** — Cloud Logging 14일치를 확인해 가드 차단 0건, 모델 429 6건으로 원인이 가드가 아님을 확정했다. 두 변경을 당일 배포하고 외부에서 로그인 없이 호출하면 401이 나는 것을 확인했다. 오후에는 도쿄에서도 429가 간헐적으로 관측돼 턴 예산 확대로 이어졌다. (이슈 `#125`)

### 2. 홈페이지 V2 — 상담봇 실패 처리·가드 (이슈 #125)

- **실패와 차단의 안내 분리** — 모델 실패와 가드 차단이 같은 거절 문구를 써서 의뢰인에게 상담을 떠넘기는 것처럼 읽히던 문제를 고쳤다.
  `backend/src/chat/chat-output-guard.ts`·`chat.service.ts`에서 실패 턴은 다시 보내기 버튼을 세우고 저장하지 않아 되묻기 횟수를 쓰지 않게 했다.
  가드 차단은 되묻기·지점 묻기·사례 안내별 대체 문구로 나누고, 걸린 규칙을 `evidence.hits`에 남겼다. (`6ad4c6f`)

- **실패 문구 사실대로 정정** — "문의가 몰려"라는 안내가 사실과 다르고 광고처럼 읽힐 소지가 있어 "일시적인 오류"로 바꿨다. (`751bbfc`)

- **가드에 걸린 답 한 번 고쳐 쓰기** — 첫 답이 가드에 걸리면 곧바로 대체 문구로 끝나던 것을, 걸린 표현을 모델에 알려 한 번 처음부터 다시 쓰게 했다.
  `chat.service.ts`·`chat-prompt.ts`에 재작성 경로를, 프론트 `use-chat.ts`에 흐르던 글을 지우는 `restart` 이벤트를 추가했다. 두 번째도 걸리면 무한 재시도 없이 대체 문구로 간다.
  도쿄에서도 429가 나 재시도 여유가 없던 턴 예산은 8초에서 15초로 늘렸다. (`d4f9b34`)

- **재작성 경로 테스트 고정** — 운영에서는 모델이 규칙을 지켜 일부러 걸리게 하기 어려워, 가짜 모델로 고쳐 쓰기 성공·두 번 차단·정상 답 세 경로를 단위 테스트로 고정했다. (`backend/src/chat/chat.service.rewrite.spec.ts`, `a7913fe`)

### 3. 홈페이지 V2 — 상담봇 대화 흐름·화면 (이슈 #125)

- **새로고침 시 새 대화로 시작** — 대화 키가 `sessionStorage`에 남아 강력 새로고침 뒤에도 서버가 예전 대화를 이어받고, 되묻기·지역 묻기를 건너뛰던 문제를 고쳤다.
  `frontend/src/features/chat/use-chat.ts`·`consent.ts`에서 대화 키와 동의를 메모리에만 두고 남은 기록을 지웠다.
  서버가 실제로 판단한 내용(짚은 말·지역·찾은 글·가장 가까운 사건)을 `step` 이벤트로 보내 대기 화면에 한 줄씩 보이고, 답하는 턴에는 관련도순으로 사례 카드 3건을 늘 세웠다. 창 크기와 본문 글자도 키웠다. (`07a1482`)

- **짚은 말 표시 정제** — 검색 키워드의 서술어·군말을 화면 표시에서 걷어내고 이번 메시지 말을 먼저 보이게 했으며, 답변 목록 기호가 그대로 찍히지 않게 했다. (`backend/src/chat/chat.service.ts`, `c3f1502`)

- **상담 신청 이동 시 스크롤 잠금 해제** — 창이 열린 채 이동해 배경 스크롤 잠금이 남던 문제를, 이동 전에 창을 닫도록 고쳤다. (`frontend/src/components/chat/chat-panel.tsx`, `2020886`)

### 4. 홈페이지 V2 — 상담봇 개인정보 요건 (이슈 #135)

- **대화 전 3종 동의·90일 파기** — 생성을 도쿄로 옮기며 국외 이전이 새로 생겨, 첫 메시지 전에 수집·이용, 민감정보, 국외 이전을 각각 동의받는 카드를 띄웠다.
  서버는 동의 판본이 없거나 다르면 요청을 거절하고, 판본을 매 턴 `evidence.consent`에 남긴다.
  `backend/src/chat/chat-retention.controller.ts`에 Cloud Scheduler 전용 파기 엔드포인트를 열고, `docs/ai-chat-privacy-amendment.md`에 처리방침 개정안 초안을 남겼다. (`ca32390`)

- **품질 개선 선택 동의 분리** — 검색 선택·차단 단어 기록은 튜닝용인데 동의 목적에 없어, 선택 동의로 따로 받고 거부해도 상담은 똑같이 되게 했다.
  동의 버전을 올려 기존 동의는 다시 묻는다. (`frontend/src/features/chat/consent.ts`, `e03d896`)

- **고지 전환 스위치 → 서버 자동 판정** — 수집·국외 이전은 처리방침 공개로 갈음할 수 있다는 검토에 따라 먼저 코드 스위치를 두고(`c3b32ef`), 이어 사람 실수 위험을 없애도록 서버 판정으로 바꿨다.
  `backend/src/chat/chat-consent.service.ts`가 게시된 처리방침에 국외 이전 조항이 있는지 1분 캐시로 읽고, 읽지 못하면 전부 동의받는 쪽으로 남는다. 게시 전 고지 판본은 서버가 거절해 체크박스가 먼저 빠질 수 없다.
  보유 기간은 품질 개선 동의 90일 / 미동의 24시간으로 나누고 파기를 매시간 돌렸다. (`832ccbc`)

- **처리방침 보관·개정본 작성** — 어드민 저장이 본문을 제자리 수정해 이전본이 사라지므로 현행본을 `docs/policy-archive/`에 보관하고, `scripts/build-privacy-amendment.py`로 개정본(국외 이전·AI 이용 조항 신설, 민감정보 문장 모순·깨진 글자 정정)을 만들었다. (`a766a96`)

- **검토 요청서 수신·안내 정정** — 법무팀이 없어 처리방침이 지정한 개인정보 보호책임자를 수신으로 적고, 외부 상담 창구 안내를 바로잡았다. (`docs/ai-chat-legal-review-request.md`, `df908a4`, `4c4e633`)

**운영 조치** — 공개 기간(9/23~28) 대화는 동의 없이 수집됐다는 판단으로 파기를 결정했다. 보관 시간을 잠시 1시간으로 줄이고 파기를 즉시 돌려 6건을 지운 뒤 24시간으로 복구했다. 남은 일은 보호책임자 검토와 개정 처리방침 게시다. (이슈 `#135`)

### 5. 홈페이지 V2 — 변호사 데이터 누락 (이슈 #131)

- **레거시 전용 변호사 V2 이관** — 레거시에 9/16 등록된 변호사가 V2에 행이 없어 12일간 홈페이지에서 빠져 있던 것을 채웠다.
  V2 어드민에서 고친 값이 덮어써지는 것을 실측으로 확인해 자동 동기화에 넣지 않고 `migration/sql/20260928_lawyer_leehyeongki.sql` 일회성 SQL로 처리했다.
  레거시 키를 그대로 써 게시물 참조를 유지하고, 지사별 정렬과 시퀀스를 맞춰 어드민 신규 생성 충돌을 막았다. 운영 DB 적용 완료. (`7ae0c82`)

**운영 조치** — 새벽 동기화가 아직 사무실 PC에서 돌아 추석 연휴(9/24~27) 동안 미실행됐다가 9/28에 밀린 분이 한꺼번에 들어온 것을 확인했다. 유실은 없었고, 레거시 서버 설치가 남은 과제다. (이슈 `#131`)
