📋 *일일 업무 보고 (2026. 09. 10.)*

서로 다른 두 앱이 같은 원인으로 매일 로그인을 강요하고 있던 것을 찾아 같은 날 양쪽 다 제거했습니다. 인증 URL에 박힌 prompt 파라미터 한 줄이 "브라우저에 이미 구글 세션이 있어도 화면을 띄워라"고 지시하고 있었고, 값이 consent와 select_account로 달라 별개 문제처럼 보였을 뿐입니다. 이제 크롬에 업무용 구글 계정이 로그인돼 있으면 화면 없이 통과합니다. 금일 커밋 5건(2개 repo), 이슈 3건 신설 : 코멘트 7건.

🔐 *〔CRM : 크롬 구글 세션으로 자동 로그인 (#11)〕*

•  *원인은 한 줄* — prompt: 'consent'가 이미 동의를 마친 사용자에게도 매번 동의화면을 강제. 제거하니 크롬 세션만으로 화면 없이 통과 (c7be844)
•  *로그인 버튼 클릭도 제거* — JWT가 없으면 버튼을 기다리지 않고 즉시 구글로 리다이렉트
•  *로그아웃 차단이 필수였음* — 이 가드가 없으면 로그아웃 직후 자동으로 다시 붙어 로그아웃이 영구히 불가능해짐
•  *리프레시 토큰 방식은 배제* — 프론트와 백엔드가 크로스 사이트라 SameSite=None 쿠키가 브라우저 정책에 취약
•  *prompt 제거의 부작용도 함께 처리* — 이게 드라이브 refresh_token을 매번 재발급받던 유일한 경로였음. 권한 없을 때 스낵바의 권한 동의 버튼으로 재동의하고 원래 화면 복귀
•  *자체 버그 1건 발견 후 재배포* — 자동 로그인 조건이 배포 이후에만 생기는 키를 필수로 요구해 기존 브라우저가 영구 차단. 사용자 확인으로 30분 안에 수정 (c997877)

🕐 *〔CRM : 8시간 세션아웃 유지 확인〕*

•  *세션아웃은 그대로 있고 서버가 강제* — JWT 수명이 정확히 8시간이고 미들웨어가 만료 토큰을 403으로 거부. 만료 토큰으로는 API를 한 건도 호출할 수 없음
•  *우회 경로가 없음* — 토큰 갱신 엔드포인트가 존재하지 않아 8시간마다 반드시 구글을 왕복
•  *실질 재인증 주기는 구글이 결정* — 워크스페이스 4시간 세션 정책이 우리 8시간보다 짧고, 세션이 죽어 있으면 구글이 비밀번호를 다시 물음

🔐 *〔사건관리 앱 : 같은 원인 같은 처방 (#524)〕*

•  *같은 증상 다른 파라미터* — CRM은 prompt=consent, 사건관리는 prompt=select_account. 둘 다 기존 세션을 무시하라는 같은 지시 (f835fa8)
•  *hd 도메인 힌트 추가* — 업무 도메인 계정만 후보로 좁혀 개인 계정 오선택 차단. 도메인은 설정으로 분리해 하드코딩 회피
•  *무한 왕복 가드 3중* — 콜백 error : 직접 로그아웃 : 이미 시도함. 성공 시 플래그를 풀어 다음 만료 때 다시 동작 (94f62f1)
•  *StrictMode 이중 실행 회피* — 세션 플래그를 읽고 지우는 부수효과라 effect가 아니라 렌더 전 모듈 스코프에서 한 번만 판단
•  *access_type=offline은 유지* — 드라이브 refresh_token이 이 값에 의존. 콜백이 없으면 기존 토큰 유지로 처리해 기존 사용자 영향 없음

🗂 *〔CRM : 회생 상담 채권자수 진행내역 컬럼 (#10)〕*

•  *진행내역 필드 신설* — 기존 진행 컬럼은 총채무 소득 변제예상을 조합한 파생값이라 사람이 경과를 적을 자리가 없었음. 직접 입력 저장하는 필드를 추가 (47c477f)
•  *목록 상세 검색 추출까지 한 번에 연결* — 컬럼 추가로 끝나지 않고 검색 대상과 엑셀 CSV 구글시트 추출 컬럼에도 반영
•  *PDF 출력은 의도적으로 제외* — 내부 관리 항목이라 의뢰인 공유 PDF에서 빼고, 어떤 항목이 PDF에서 빠지는지 전수 조사해 이슈에 기록
•  *멱등 마이그레이션 + DB 모의 테스트* — 재실행 안전하게 작성하고, 컨트롤러 저장 수정 검색 추출을 DB 없이 2건으로 검증

🚀 *〔운영 배포 : 후속 과제〕*

•  *CRM 운영 배포 3회* — 백엔드 2개 리비전, 프론트 3회. 배포 전 기준 리비전을 기록해 롤백 지점 확보
•  *배포 반영을 해시로 확정* — 배포본 main.dart.js의 SHA-256을 로컬 릴리스 빌드와 대조
•  *배포가 최대 1시간 늦게 도달함* — Firebase Hosting이 index.html에 max-age=3600을 내림. index.html만 no-cache로 분리하는 정리를 후속 과제로 남김
•  *미해결* — 회생 컬럼 배포 직후 운영 로그인 1건에서 invalid_grant로 HTTP 500. 이후 로그인은 정상이나 반복 여부 관찰 필요
•  *이슈 종료 2건* — #522 수납 진행률 분리, #360 VAPID 시크릿 버전 고정. 구현 커밋은 동료 작업이고 금일 몫은 검증과 종료 정리
