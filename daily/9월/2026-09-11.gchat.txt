📋 *일일 업무 보고 (2026. 09. 11.)*

세 앱(메인보드, 사건관리, CRM)이 각기 다른 코드베이스에서 똑같이 "구글 세션이 없는 사람을 구글 로그인 페이지에 떨어뜨리는" 문제를 안고 있던 것을 찾아, 같은 날 셋 다 사일런트 인증(prompt=none)으로 교체했습니다. 이제 세션이 있으면 클릭 없이 통과하고, 없으면 우리 로그인 화면이 뜹니다. 그 외 사내 포털을 Vercel에서 Cloud Run으로 이관해 월 $20을 0원으로 낮췄고, 그 이관이 만든 마지막 결함(Firebase Hosting이 쿠키를 지워 로그인이 끝나지 않던 것)까지 잡았습니다. 금일 커밋 13건(3개 repo), 이슈 6건 신설 : 코멘트 4건.

🚀 *〔메인보드 : Vercel에서 Cloud Run으로 이관 (#11, #13)〕*

•  *월 $20에서 $0으로* — Vercel Pro는 트래픽과 무관한 고정 플랫폼 요금이고 Hobby는 상업적 이용 불가. 실제 컴퓨트 비용은 $0.84였음 (4a33434)
•  *서울 무료 한도 안에 들어감* — 84명 하루 8회 기준 월 요청의 3%, 메모리의 16%. 트래픽이 30배로 늘어도 무료
•  *DB가 없어서 가능했던 선택* — 세션은 JWT 쿠키, 조직도는 30KB JSON 하나. 사건관리앱처럼 상시 켜진 Cloud SQL이 없음
•  *저장소는 3중 어댑터로 분리* — Cloud Storage : Vercel Blob : 로컬 파일. Vercel 경로는 걷어내지 않고 남겨 되돌릴 여지를 둠
•  *도메인은 우회 경로가 필요* — Cloud Run 도메인 매핑이 서울 리전을 지원하지 않아, Firebase Hosting이 portal.lawwin.co.kr을 서비스로 rewrite
•  *배포 후 결함 3건, 원인은 모두 하나* — standalone 서버가 헬스체크용으로 0.0.0.0에 바인딩해, 요청에서 뽑은 origin이 전부 0.0.0.0:8080이 됨. 앱은 멀쩡히 뜨고 로그인만 실패하는 형태라 발견이 늦음 (240d733, d3d8b55)

🍪 *〔메인보드 : Firebase Hosting 쿠키 제거로 로그인 실패 (#14)〕*

•  *정규 호스트로 모아도 안 끝났음* — 위 프록시 이후에도 운영에서 InvalidCheck: pkceCodeVerifier 500이 남음. 앞서 세운 "쿠키가 시작한 호스트에 남는다"는 설명으로는 안 풀리는 증상 (eb980c0)
•  *진짜 원인은 Firebase Hosting* — 요청 쿠키 중 __session 외를 전부 제거함(공식 문서에 명시). 운영 CSRF 응답 쿠키를 재전송해도 토큰이 바뀌고 signin POST가 MissingCSRF로 거절되는 것을 재현해 확정
•  *쿠키는 서버에 두고 브라우저엔 손잡이만* — 비공개 GCS에 Auth.js 쿠키 스냅샷을 보관하고 __session에는 256비트 임의 식별자만 전송. 객체 키는 그 SHA-256, 인증 응답마다 식별자 회전
•  *4KB 초과 분할 JWT도 지원* — 브라우저 쿠키 한도를 넘는 세션도 스냅샷에 그대로 담김
•  *장애가 조용한 로그아웃이 되지 않게* — 저장소 읽기는 404만 없음으로 처리하고 나머지 오류는 던짐. 대신 서버 측 세션 강제 폐기는 제공하지 않으며 그 한계를 문서에 명시
•  *검증* — 실제 Auth.js와 모의 OAuth로 CSRF부터 로그아웃까지 41건 통과. 배포 후 Firebase 경유 왕복 확인 스크립트 별도 작성

🔐 *〔메인보드, 사건관리, CRM : 사일런트 인증 3종 (#12, #524)〕*

•  *같은 증상 세 코드베이스* — 세션 유무를 모르는 채 구글로 넘기니, 세션 없는 사람은 우리 로그인 화면을 구경도 못 하고 구글 페이지에 떨어짐
•  *prompt=none으로 교체* — 구글이 화면을 일절 띄우지 않고 즉답. 세션 있으면 code, 없으면 error=login_required. 둘 다 리다이렉트라 왕복이 안 보임 (c1c0cbf, 7f4d92d, 2c83ada)
•  *iframe 사일런트 인증과는 다름* — 그쪽은 X-Frame-Options와 3자 쿠키 차단으로 막혔지만, 최상위 리다이렉트는 두 제약 모두 해당 없음
•  *거절은 실패가 아님* — login_required 같은 응답은 오류 문구 없이 통과시키고, 사유별로 버튼이 계정 선택을 건너뛸지 결정 (8f8a010, 9c7155b)
•  *계정 선택을 남기는 예외 2개* — 로그아웃 직후(생략하면 계정 전환이 아예 불가) : 인증 실패 복귀(도메인 불일치 등 계정 자체가 원인일 수 있음)
•  *탭 복귀 재시도는 채택 후 철회* — 띄워놓고 보니 탭을 옮겼다 왔다는 이유만으로 화면이 구글로 날아감. 재진입은 사용자 클릭으로 받는 쪽으로 선회 (d1e6385, 4839051)

💰 *〔CRM : 목록 폴링 비용 절감 (#13)〕*

•  *응답 27KB에서 3.2KB로 88% 감소* — 백엔드에 gzip 미들웨어 추가. 컬럼 별칭이 한글이라 UTF-8에서 키가 행마다 3바이트씩 반복돼 압축 효과가 특히 컸음 (70b3a27)
•  *갱신 주기 15초에서 20초로* — 상담, 당사자, 회생 3화면 공통. 60명 기준 월 $22에서 $10으로 감소
•  *SSE 전환은 기각* — 연결을 계속 열어두면 Cloud Run 활성 단가 구간이 34%에서 100%로 올라가 오히려 비싸짐

🛡 *〔운영 점검 : 커밋 없음〕*

•  *KISA 보안권고 1048, 1049 영향도 점검* — PostgreSQL CVE 6건과 Linux Kernel 1건. 운영 Cloud SQL이 이미 16.14(해결 버전)이고 직접 운영하는 리눅스 호스트가 없어 조치 불필요 (#133, #540)
•  *사건관리 SSE 운영 로그 점검* — 최근 24시간 연결 620건 중 즉시끊김 0건. 7일간 에러 1건은 설계된 백오프로 자동 복구. 조치 불필요 (#518)
