🤖 *〔AI 상담봇 스펙 3차 검토 : 이슈 125〕*

•  *플랫폼은 옮기지 않음* — Vertex를 고른 근거가 "대화 원문이 민감정보라 국외이전 고지 문제를 아예 만들지 않는다"인데, 엣지 실행으로 바꾸면 그 근거가 통째로 무효가 되고 키 없는 인증도 잃음. 바꿔서 나아지는 항목이 없음 (1f42041)
•  *"Agent"라고 부르지 않기로* — 자율 목표 루프는 스펙이 "의도적으로 하지 않는 것"으로 정해 둔 것과 정면충돌. 우리 것은 툴 3종을 가진 대화형 검색 퍼널이며 대외 설명에서도 이 표현을 유지
•  *정작 짚어낸 빈칸은 관측* — 검색, 비용, 가드레일, 품질측정은 강의보다 깊은데 "돌아간 뒤에 무엇이 남는지"만 비어 있었음. 이 한 축으로 4건 채택
•  *추적 ID로 두 영역 로그 연결* — Cloud Run이 이미 주는 트레이스 헤더를 공통 식별자로 써서, 추가 계측 비용 없이 어드민 대화 로그에서 로그 콘솔로 바로 넘어감
•  *검색 근거 보존이 가장 값어치 있는 채택* — 실패한 답변에 무엇이 검색됐는지 기록이 없으면 튜닝이 오프라인 50문항에 갇힘. 지금은 컬럼 하나지만 Phase 2 이후엔 마이그레이션
•  *출시 게이트 추가* — "이걸 만족하면 공개한다"가 없었음. 지금 값을 정해야 하는 것은 Recall 목표치와 kill switch 두 가지로 좁힘

⚠️ *〔착수 전에 정해야 할 분기점이 새로 드러남〕*

•  *상담봇 API에 앞단 통제 계층이 없음* — 브라우저가 백엔드를 직접 호출해 앱 코드가 1차 방어선. 프론트 쪽 경로에만 방화벽을 붙일 수 있는 구조
•  *이게 곧 금액* — 스펙이 스스로 "인스턴스가 여러 개라 메모리 기반 호출 제한은 장시간 창에서 사실상 무방비"라고 적어 둠. LLM 호출은 상담 접수보다 건당 비용이 큼
•  *선택지 3안을 스펙에 기록* — 프론트 경유 프록시, 로드밸런서에 백엔드 추가, 현행 유지. 스트리밍 경로를 짜기 전에 정해야 해서 착수 전 결정 항목으로 등록
•  *확인 못 한 것도 명시* — 모델 호출 직전 검사에 쓸 GCP 관리형 제품은 서울 리전 가용성과 한국어 품질 미확인. 확인 전까지 앱 내부 방어가 우리 방식

🔍 *〔Phase 1 선행 확인 : 운영 DB 실측〕*

•  *운영 DB 쓰기 없이 착수 가능* — vector, pg_trgm, unaccent 전부 이미 설치 확인. 패치 버전 차이는 우리 용도에 영향 없어 지금 올릴 이유 없음 (083ef04)
•  *점검 도구가 원인을 숨기고 있었음* — 실패 사유를 통째로 버려 오류 종류만 출력. 비밀번호만 가리고 사유는 남기도록 수정. 이게 없었으면 타임아웃이라는 것조차 못 봤고 원인도 못 찾음
•  *미설치와 미지원을 구분* — 기존엔 설치된 것만 조회해서, 확장이 없을 때 서버가 제공을 안 하는 건지 이 DB에 생성만 안 한 건지 알 수 없었음
•  *접속 경로 4가지 실측* — 공개 IP 직결은 승인된 네트워크가 0개라 타임아웃. 일회성 조회에 운영 방화벽을 여는 선택은 하지 않고 Cloud SQL Studio로 조회
•  *직결을 택하면 인증서에서 한 번 더 막힘* — 서버 인증서가 인스턴스 전용 내부 CA 서명이라 IP를 열어도 검증에서 실패. 이 함정을 문서 부록에 남겨 다음 사람 시간을 아낌

📱 *〔CRM : 모바일 상담 등록 화면〕*

•  *입력폼이 40px 남짓으로 찌그러져 있었음* — 방문상담 유형에서 캘린더 미리보기가 가로 폭을 차지해, 정작 입력해야 할 폼이 사실상 보이지 않았음 (62a6e33)
•  *좁은 화면에서는 미리보기를 표시하지 않도록 변경* — 데스크톱 좌우 2단 배치는 기존 그대로. 미리보기는 보조 정보이고 입력폼이 이 화면의 목적
