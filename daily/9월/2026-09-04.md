# 일일 업무 보고 (2026. 09. 04.)

> **만든 것보다 재본 것이 많은 하루**였다. AI 상담봇을 화면 시안 → 대화 설계 → 발주서 → 제안서 편입까지 밀어 붙였고, 그 과정에서 **「초기 대응 안내 31건」 목록의 근거가 공급 통계(해결사례 분포)라는 것**을 스스로 의심해 레거시 상담 6,204건을 직접 집계했다. 결과는 **보정 불가**였지만(86%가 분야 미태깅) 대신 **설계 판단 세 가지가 실측으로 검증**됐다 — 어휘 분산이 극심해 pgvector 가 맞고, 사람들이 가장 많이 묻는 것이 우리가 답하지 않기로 한 「결과」이며, 초기 대응 수요는 실재한다. 상담봇 근거를 찾다가 **인프라 구멍 5개가 연달아 드러났고**(자산 복구 누락 · 이틀간 미배포 · 검색어 미저장 · 상담 DB 이원화 · 자동화 전무) 전부 이슈로 세웠다. 사건관리 앱에서는 **8월 미수금 차액 10,836,000원을 1원 단위까지 원인별로 분해**해 동기화 결함 3건을 세웠고, 그 조사를 전 기간으로 넓혀 **DB 자체의 미수금 중복 27쌍 43,818,000원**을 따로 찾아냈다 — 금일 커밋 3건(1개 repo), 이슈 10건 생성 · 코멘트 9건

### 1. BS_MAIN_HOMEPAGE_V2 — AI 상담봇 설계 확정 (`#125`)

#### 화면 시안 — 개발 착수 전에 그림부터 만들었다

- **9/2 자 제안서에 화면 그림이 한 장도 없었다** — A4 7면인데 무엇이 어디에 붙는지 볼 수 없고, 초기 대응 안내 20~30건은 예시 5줄뿐이라 **변호사 발주가 불가능한 상태**였다. 개발 착수 전 마케팅·대표 검토를 먼저 받기로 하고 그중 첫 번째(화면)를 만들었다. 클릭 가능한 인터랙티브 목업으로, 기기 3종(데스크톱 / 태블릿·세로모니터 / 휴대폰) 전환과 시나리오 2종을 담았다.
- **시나리오 두 번째를 「답변 범위 밖 질문」으로 잡았다** — 승패·형량·수임료를 물었을 때 봇이 멈추는 모습. 뒤의 실측에서 이 선택이 우연이 아니었음이 드러난다.
- **무대 안은 운영 중인 메인을 그대로 옮겼다** — v1·v2 는 우하단 채널을 2개로 잘못 그렸고, 코드·라이브 대조 후 v3 에서 고쳤다(상단 진홍 유틸 바, 헤더·GNB·폰트 Geist, 히어로 문구·검색바, 진홍 통계 판, 우측 플로팅 5개, 하단 바 / xl 미만 dock).
- **마케팅이 결정할 항목은 스위치로 만들었다** — 사례 결과 뱃지 표시 ON/OFF 를 눈으로 비교하게 했다(spec §6-7 / §12.2).

#### 시안을 만들다 spec §8 의 심각도가 드러났다 — 런처 배치

- **§8 은 「자리 충돌 검토 필요」 한 줄이었는데 실측하니 훨씬 심각했다** — xl 이상은 우측 플로팅 **5개** + 하단 빠른 상담 바 **상시 노출**, xl 미만은 **5칸 dock**. 게다가 `floating-actions.tsx` 주석에 「다섯 개가 넘어가면 고르는 데 시간이 든다」는 이유로 법승TV를 **의도적으로 뺐다**고 명시돼 있다. AI 단추를 여섯 번째로 그냥 얹으면 그 판단을 정면으로 뒤집는 것이고, dock 은 `grid-cols-5` 고정이라 칸을 늘릴 자리도 없다.
- **3안을 올린 뒤 1안+3안 혼합으로 확정** — 데스크톱은 우측 채널 묶음 **맨 위 첫 번째**, 태블릿·휴대폰은 칸을 늘리지 않고 **dock 위 오른쪽 빈자리에 아이콘 하나로 따로**. **기존 채널의 자리·색·순서를 하나도 건드리지 않는다**는 것이 이 안의 값어치다. 그 자리가 빈 것도 우연이 아니다 — 통계 카드가 가운데로 올라가 있고 dock 이 고정 그리드라 **우하단이 구조적으로 빈다.** 새 자리를 만드는 게 아니라 이미 빈 자리를 쓴다.
- **남은 확인**: 지점을 고르면 dock 이 5칸으로 늘어난다. 그 화면에서 아이콘이 안 겹치는지 실기기 확인 필요.

#### 대화 설계 — 6턴을 3턴으로, 서식을 대화체로

- **되묻는 단계를 없앴다** — 시안 초기 흐름이 6턴이었다(사연 → 안내 → "사례 볼래?" → "사무소 알려줘?" → "지역 어디?" → 수원 → 접수). 되묻는 단계가 전환을 갉아먹는다. **사연 한 번 → 답변 한 번 → 접수** 3턴으로 확정하고, 답변 한 통에 안내·유사 사건·못 하는 것·담당 사무소를 전부 담는다.
- **지역 질문은 물을 이유가 없었다** — `/{region}/…` URL 구조라 **지금 보고 있는 페이지가 이미 지역**이다. `useRegion()` 값을 쓰면 되고, 이것만으로 2턴이 사라졌다.
- **⚠️ 한 번 잘못 만들고 되돌렸다** — 발주서의 작성 양식(지금 하실 것 / 하지 마실 것 / 준비 자료 …)을 **그대로 화면 카드로 뿌렸다가 회수**했다. 의뢰인은 자연어로 물었는데 정해진 서식 한 장을 받으면 그건 **FAQ 조회이지 대화가 아니다** — 자기 질문에 대한 답이 아니라 문서를 받은 것이 된다. **원고의 서식과 화면에 말하는 방식은 별개**라는 것이 결론이고, 화면은 질문에 맞춰 풀어 쓴 문장으로 답하되 근거는 한 줄로만 표시한다(`초기 대응 안내 · 형사 / 첫 경찰 조사 통보를 받으셨다면 / 전문 보기 →`). 시안 코드에 이 경고를 주석으로 박아 뒀다.
- **명세에 없던 누락 — 만 14세 확인 게이트** — 경쟁사 상담봇을 참고하다 발견했다. 개인정보보호법상 만 14세 미만은 법정대리인 동의가 필요한데, **법무법인 챗봇에서 미성년자가 사건 내용을 적어버리면 그 자체가 문제**가 된다. 동의 전에는 입력창과 답변 버튼을 잠가 **입력 자체를 앞단에서 막는 것**이 맞다. spec §6 추가 필요.

- **이슈 ① 역방향 동기화가 없다 (`#474`)** — 동기화가 DB → 시트 **단방향(push only)** 이고 pull 경로가 없다. 서비스 헤더 주석에 `Phase 2(예정): 시트 → DB 풀`로 적힌 채 운영에 들어갔고, 실무는 시트를 계속 손으로 고치고 있어 격차가 누적된다. 불일치 6건은 **전부 시트 최종수정이 DB 최종수정보다 늦다** — **앱이 못 쓴 게 아니라 사람이 시트에 쓴 걸 앱이 못 읽는 것**이다.
- **🔴 더 위험한 건 반대 방향이다** — 매핑이 `"balance": lambda r: _fmt_int(r.paid_amount)` 이고 `None → ""` 이라, 시트에 1,000,000 이 적혀 있고 DB 가 NULL 인 상태에서 **누군가 앱에서 메모 한 줄만 고쳐도 `balance` 셀에 빈 문자열이 기록되어 시트 금액이 소멸한다. 경고도 로그도 없다.** 위 6건이 전부 이 상태로 대기 중이다. 단기 조치로 **시트에 값이 있는데 DB 가 NULL/0 이면 덮어쓰지 않고 보존 + 경고 로그**(최소한 조용한 유실은 막는다)와 정기 대조 리포트를 제안했고, Phase 2 구현 여부는 **「시트 수기수정을 금지하고 앱을 단일 입력창구로 할 것인가」라는 업무 정책 결정이 먼저**다.
- **이슈 ② 시트 중복 3건 = 209,000원 이중계상 (`#475`)** — 같은 `OS_key` 가 두 번 등장한다. **세 행 모두 `2026-09-03 14:38:09` 로 초 단위까지 동일**해 배치성 실행 1회가 만든 것이고, `AR_key` 가 원래 계약에서 월별 더미계약으로 바뀌어 있다. 9/3 의 `#457` 재동기화 스크립트 커밋 시각이 **중복 생성 2분 전**이라 유력하나 미확정이다. **핵심은 「멱등」의 범위다 — 스크립트는 "여러 번 돌려도 결과가 같다"로 기술돼 있지만 `push_single_*` 이 기존 행을 못 찾으면 append 하는 구조라 DB 기준 멱등이 시트 기준 멱등을 보장하지 않는다.** 이 3건은 `legacy_key` 가 정상 8자리라 `#462`(앞자리 0 유실) 조건에도 해당하지 않아 **매칭 실패 원인은 아직 미규명**이다. 함께 미수금 1건(`id=1916`, 2,000,000원) 시트 완전 누락도 발견했다.
- **⚠️ 시점이 문제다** — 중복 3행이 `#458` 조사·정정 작업(9/2~9/3) **뒤에** 생겼다. **이미 정정한 내용이 재동기화로 다시 어긋났을 가능성**이 있어 `#458` 정정 결과 재확인이 필요하다.
- **이슈 ③ 취소·삭제가 시트에서 안 지워진다 (`#476`)** — 비활성 상담료 13건 중 **`FALSE` 로 정상 반영된 건이 0건**이다(TRUE 로 남음 2 · 행 자체가 없음 11). 원인이 둘로 갈린다. **하나, 취소하는 순간 `AR_key` 를 만들 수 없게 된다** — `delete_consultation_fee()` 가 `is_active=FALSE` 와 **함께 `contract_id` 를 해제**하는데, resolver 는 계약이 없으면 입금일로 대체하고 **미납 취소건은 입금일도 None** 이라 `None` 을 반환한다. 그러면 push 가 `no_ar_key_match` 로 **스킵되어 시트에 아무것도 안 쓴다** — `#458` 에서 DELETE 에 push 를 추가했는데도 안 지워진 이유가 이것이다(**구조적으로 취소를 쓸 방법이 없다**). **둘, 비활성 미수금이 push 제외 조건에 걸린다** — 소유권이 상담료 쪽에 있는 행은 미수금 서비스가 안 건드리고, 상담료 서비스는 원본이 **활성**이라 `TRUE` 로 계속 쓴다. **아무도 그 행을 FALSE 로 만들지 못한다.**
- **이슈 ④ 시트가 아니라 DB 자체에 중복이 있다 (`#477`)** — 조사를 8월에서 전 기간으로 넓히자 `receivables` 에 **같은 사무소·같은 입금인·같은 금액·같은 입금일인 활성 행이 2건(일부 3건)씩** 있었다. **27쌍 / 합계 43,818,000원**(2024년 1쌍 · 2025년 21쌍 · **2026년 5쌍**). 윤한수 400,000원 건은 3건 전부 활성인 그룹이 두 개(`347·348·349`, `351·491·492`)다.
- **먼저 자동 생성 경로부터 지웠다 — 원인이 아니다.** 수임전환 시 만들어지는 공제 수납행은 `source_consultation_fee_id` 가 **UNIQUE** 이고 그 키로 upsert 하므로 **중복을 만들 수 없다**(실측 공제행 4건, 중복 0). 연결 해제·비활성·미납이면 정상적으로 `is_active=FALSE` 로 내린다. 중복처럼 보였던 김호아·박상훈도 **DB 에서는 수기 행이 이미 비활성**이고, 그게 중복으로 보이는 이유는 **취소가 시트에 반영되지 않기 때문**(`#476`)이라 본 이슈와 별개다. 남은 27쌍은 **전부 수기 입력 행이 양쪽 다 활성**인 것만 추린 것이다.
- **원인은 미확정이고, 2025년에 21쌍이 몰려 있다** — 레거시 마이그레이션 중복 삽입이 유력하나(각 행이 서로 다른 `legacy_key` 를 가져 **애초에 별개 레코드로 생성**됐다), 앱에 동일 건 중복 입력을 막는 검증이 없어 **2026년 5쌍은 수기 이중 입력** 쪽일 수 있다.
- **⚠️ 다만 중복으로 단정하면 안 된다** — 분납이나 별건 수임으로 **같은 날 같은 금액을 두 번 받는 경우가 실제로 있다.** `#458` 에서 박상훈 8/11 2건이 "정당한 별도 결제, 중복 아님"으로 확인된 전례가 있어, **영수증·통장 대조 없이 비활성화하면 안 된다.** 실무자 확인을 1단계로 뒀고, 앱에는 막지 않고 **경고만 띄우는 중복 입력 확인**을 제안했다.
- **영향은 시트까지 이어진다** — 앱 미수금·수납 집계와 대시보드, 계약 완납여부 판정이 부풀려질 수 있고, 이 중복 행들은 **각각 별도 `OS_key` 로 push 되므로 매출대장에도 그대로 이중 반영**된다.
- **네 방향이 동시에 어긋나 있다** — 취소가 시트에 남아 **매출대장 과다계상**, 시트 수기 입금이 앱에 없어 **앱 미수금 과다계상**, 시트 중복 행으로 **이중계상**, 그리고 **DB 자체 중복**으로 양쪽 모두 과다계상. **어느 숫자도 단독으로는 신뢰할 수 없는 상태**이고, 이것이 "입금 기록은 있는데 미납으로 뜬다"는 실무자 체감과 정확히 맞는다.
- **조사 방법 — 운영 DB(`flutter-crm-e44f5:asia-northeast3:lawwin` / `case_management`)와 운영 시트 대조. SELECT·시트 read 만 수행했고 DB·시트·저장소 모두 변경 없음.** 잔여 데이터 정리(상담료 543·571, 미수금 2067·2073·2074, 시트 중복 3행, **중복 27쌍**)는 운영 데이터라 **별도 승인 후**로 남겼다.
