📋 *일일 업무 보고 (2026. 09. 03.)*

회계 단위와 DB 구조를 맞춘 하루. 사건관리 앱에서 예약금과 상담료를 한 행에 합쳐 담던 구조를 행 2개로 분리해 "행 1개 = 영수증 1장"을 성립시켰다. 스키마:API:CRM 동기화:시트 내보내기:프론트까지 한 줄로 꿰는 작업이었고, 계기는 구글시트가 한 행에 결제 한 세트만 담아 예약금의 입금일:결제방법이 내보낼 때 사라지던 실제 사고였다. 홈페이지는 Cloud SQL 보안 경고를 전수 검토해 7개 항목 중 4건을 조치하고 3건은 하지 않거나 보류로 정리했다. 금일 커밋 10건(2개 repo), 이슈 1건 생성, 코멘트 6건.

🗂 *〔사건관리 앱 : 예약금 상담료 레코드 분리〕*

•  *문제* — 회계상 별개 입금 2건을 DB 1행에 합쳐 뒀다. 시점도 결제방법도 다르고 영수증도 2장 끊긴다
•  *터진 곳은 앱이 아니라 내보낼 곳* — 구글시트 AR DB 는 한 행에 결제 한 세트만 담는다. 대전 8월 김석호 건에서 예약금 계좌 8/18 과 상담료 카드 8/24 중 한쪽이 소실됐다
•  *조치* — fee kind 와 fee group id 를 넣어 예약금을 별도 행으로 분리. 원본 컬럼은 롤백 여지로 남겼다 (39e9779)
•  *실행 순서를 못박았다* — 029 다음 신규코드 배포 다음 030. 구코드가 원본 컬럼과 새 행을 둘 다 세면 시트 금액이 2배가 된다
•  *DB는 행 단위, API와 화면은 상담 단위* — 직원이 한 화면에서 둘을 함께 처리하므로 목록 건수가 53건에서 72건으로 바뀌면 안 됐다 (68a13a0)
•  *CRM 은 그룹 단위 유지* — 단건으로 두면 예약금만 저장했을 때 캘린더 제목이 반쪽만 갱신된다 (5387773)
•  *시트는 행 단위로 각각* — 합치기와 우선순위 로직을 전부 제거. 합계 불변, 이중계상 없음 (9ab4429)
•  *곁가지 버그 수정* — 입금상태:결제방법 필터가 상담료 쪽만 보고 판정해 예약금만 미입금인 건이 필터에서 새고 있었다
•  *후속* — 공제 수납행 재동기화 스크립트(멱등), Windows 콘솔에서 이모지 때문에 거짓 실패로 끝나던 문제 수정 (1e669a0, 200443c)

↩️ *〔사건관리 앱 : 목록 하위 행 표시 후 되돌림〕*

•  *분리했더니 화면에서는 여전히 안 보였다* — 시트엔 2행으로 나가는데 앱에서는 수정 모달을 열어야 예약금 입금일:결제방법을 알 수 있었다 (이슈 #463)
•  *구현* — 결제 관련 셀마다 둘째 줄을 그렸다. DataTable 의 확장행은 전체 폭이라 컬럼 정렬이 안 돼 쓰지 않았다 (ffbdac7)
•  *같은 날 28분 뒤 되돌림* — 되돌린 사유가 커밋과 이슈 어디에도 없다. 재작업 시 근거가 없어 보완 필요 (14aae1a)

🔐 *〔홈페이지 V2 : Cloud SQL 보안 경고 전수 검토〕*

•  *삭제 보호가 꺼져 있었다* — 클릭 한 번에 운영 DB 와 백업 7일치가 함께 영구 삭제될 수 있던 상태. 비용과 다운타임 0 이라 즉시 활성화
•  *평문 접속을 허용하고 있었다* — 그 구간으로 쿼리문과 상담자 PII, DB 비밀번호 본체가 평문으로 흘렀다. ENCRYPTED ONLY 로 차단
•  *운영 무영향을 사전 확증* — Cloud Run 이 커넥터 소켓 경유임을 먼저 확인한 뒤 실행. 백엔드 health 와 공개 사이트 정상
•  *부작용을 같은 날 발견해 수정* — SSL 강제로 마이그레이션 스크립트 12개가 접속 실패 상태가 됐다. pg 가 sslmode require 를 verify full 로 해석해 죽는다. 런북에 libpq 호환 플래그 반영 (2d9b5d7)
•  *비밀번호 정책도 적용* — 인스턴스 정책(최소 12자:복잡도:재사용금지)과 사용자별 정책. 만료와 실패잠금은 미설정이라 운영 정지 위험 없음을 실측 확인
•  *멀티리전은 하면 안 되는 항목* — 한국 GCP 리전이 서울 하나뿐이라 복제본이 일본에 놓인다. 상담자 개인정보 국외이전 사안
•  *HA 와 pgaudit 2건은 보류* — SCC 는 ISO:PCI 벤치마크 기준이고 당사는 인증 대상이 아니다. HA 는 요금 2배라 경영 판단, pgaudit 는 재시작 필요 (이슈 #107)
•  *집계 주의* — 콘솔은 한 번에 6건씩 보이지만 항목이 닫히면 목록이 교체돼 실제 검토는 7개 항목. 4건 조치, 1건 미실행, 2건 보류
•  *SCC 가 지적 안 한 실질 약점 2건* — DB 비밀번호가 사람에 묶이지 않은 공용 비밀인 구조, 기본 컴퓨트 서비스 계정에 editor 과다부여
•  *IAM* — 박준수 실장에 소유자 부여. 프로젝트 소유자 2명 구성

✅ *〔금일 종합〕*

•  *두 갈래였다* — 구조를 회계 단위에 맞추는 일과, 경고를 판단하는 일
•  *이원 구조를 의도적으로 세웠다* — DB 는 영수증 단위, API 와 화면은 상담 단위. 직원의 입력 동선과 회계의 기록 단위가 애초에 다르다
•  *판단이 실질이었다* — 멀티리전이 국외이전으로 이어진다는 점은 경고 문구만 보고 실행했다면 되돌리기 어려웠다
•  *놓친 것도 있었다* — SSL 강제 후 마이그레이션 도구가 깨진 것은 사전 판단의 누락. 같은 날 실측으로 잡아 런북에 반영
