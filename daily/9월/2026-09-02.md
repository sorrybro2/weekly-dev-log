### 2. BS_MAIN_HOMEPAGE_V2 — 어드민 모바일·태블릿 대응

어드민 셸(`admin-shell.tsx`)은 이미 반응형이었다. **문제는 셸이 아니라 페이지 내부**였고, 목록 12개가 전부 `<table>` + `overflow-x-auto` 였다. 열이 최대 9개(문의 관리: 선택·이름·전화·상담분야·지사·유입·상태·접수일·삭제)라 좁은 폭에서는 스크롤해도 읽히지 않았다.

- **기준을 세움 — md(768px) 미만은 카드, 이상은 표** — 기존 모바일 패턴이 grep 0건이라 이번에 처음 정했다. 지사·약관(`7c24c77`), 계정·변호사·센터·문의·게시물·센터블로그·웹훅·카운트·이메일(`8388008`) 순으로 적용.
- **저장 바 태블릿 폭 유출** — 저장 바가 `-mx-4 … sm:-mx-6` 인데 셸 `main` 은 `p-4 lg:p-6` 이다. **640~1024px 구간에서 main 은 16px 인데 바가 24px 을 빼서** 좌우로 8px 씩 삐져나왔다. 5개 화면에서 `lg:-mx-6` 로 교정.
- **터치·오탭** — 정렬 화살표(약 22px)·체크박스(16px)를 36px·44px 로 키우고, 삭제 계열을 `order-last` 로 모바일 맨 아래 줄에 분리했다. 문의 관리 카드에서는 전화번호를 `tel:` 링크로 — 모바일에서 이 화면을 여는 목적이 대체로 "접수 보고 바로 전화" 라고 봤다. **DOM 순서는 건드리지 않았다**: 바꿨더니 "저장하지 않은 변경사항" 문구가 삭제 버튼 쪽으로 밀리는 자기 회귀가 나서 커밋 전에 되돌렸다.
- **컨텐츠 목록은 카드가 아니라 목록 행** — 글마다 카드를 세우면 한 화면에 몇 건 안 들어온다. 구분선 행으로 바꿔 건수를 두 배로 늘리고 제목은 2줄로 잘랐다. 맨 위에 전체선택·총 건수를 두어 모바일에서도 일괄 노출·삭제를 쓸 수 있게 했다. `bbs-list.tsx` (`e776f40`)
- **카테고리 관리** — 미룬 3개 중 하나를 해치웠다. 표를 목록 행으로 바꿔 메인 뱃지가 줄바꿈되지 않게 하고, 편집 패널을 선택한 행 아래에 펼쳤다. **색상 입력 옆에 현재 색상값을 적었다** — 그전엔 흰 칸만 보였다. (`21f0c82`)
- **배포·이슈** — 프론트 리비전 `lawwin-homepage-00113-sxb`. 남은 2개(게시물 폼 771줄, 질문 관리 565줄)는 상태가 많아 화면을 보면서 해야 해 미뤘다. 곁가지로 **`account-list.tsx`(170줄)가 임포트 0건**인 죽은 코드임을 발견(6/24 `518919d` 로 `/admin/account` 를 `/admin/google-roles` 로 리다이렉트한 뒤 파일만 남음). 검증은 `tsc --noEmit` 까지 — 이 저장소는 **ESLint 가 실행되지 않고 Prettier 도 없다.** 이슈 `#124`

- **⭐ 진실의 위치를 나눴다** — 구글 어드민 → CRM DB 는 Directory 웹훅 + 시간당 폴링으로 이미 동기화되고 있다. 그러니 **사람에 관한 정보(이름·내선·직위)는 CRM 을 진실로 삼고**, CRM 에 없는 **배치(트리·배지·순서)만 조직도 JSON 이 계속 소유**한다. `src/lib/crm/client.ts` · `src/lib/org/reconcile.ts` (`356e902`)
- **이름이 아니라 키로 잇는다** — `Person.employeeKey` 로 CRM 과 연결해 개명·표기 흔들림에 안 깨지게 했고, 사진은 이름 대신 `gws_id` 로 찾아 구글 표시 이름이 바뀌어도 사라지지 않게 했다. 직위는 `position` 컬럼이 지사장·파트너변호사 같은 **직책**이거나 낡은 값이라, `employee_name` 뒤 접미사("고수연 과장")에서 뽑고 `position` 은 참고 보고로만 돌린다.
- **실측 검증** — 88명 × CRM 377명 대조 결과 **매칭 실패 0**, 내선 12건 반영, 신규 21명. `npx tsx scripts/crm-reconcile-check.mts` 로 언제든 다시 볼 수 있게 스크립트로 남겼고, `/org` 툴바에 CRM 대조 패널(신규·퇴사·확인필요)을 붙였다.
- **편집 범위 축소** — CRM 이 주는 값의 입력란을 없앴다. **여기서 고쳐 봐야 다음 새로고침에 덮인다.** 구성원 추가는 CRM 재직 명단에서 골라 넣게 해 오타로 매칭이 깨지지 않고 `employeeKey` 가 처음부터 박힌다. 배지(광고·회계·IT·협조·CS·중국어 37건)는 수기 유지 — CRM `duty_label` 은 121명 중 95명이 비어 있고 값 체계도 다르다. `inspector.tsx` (`154751c`)
- **대조 패널에서 바로 넣기** — 보기만 하던 "조직도에 없는 재직자" 를 그 자리에서 추가할 수 있게 했다. CRM 소속 이름에서 접미사·괄호를 떼어 들어갈 박스를 미리 고른다(서울본사→서울, 정보실→정보실 (대전)). **21개 소속 중 10개가 자동으로 잡히고**, 조직도에 박스가 아예 없는 소속(마케팅팀·전문위원 그룹·자문위원·경영지원실·제주지사)은 **자동으로 넣지 않는다** — 어디에 놓을지는 CRM 이 모르는 정보다. (`dc7ad73`)
- **PNG·PDF 내보내기 제거** — 조직도가 파일로 밖에 나가는 경로 자체를 없앴다(화면 워터마크는 유지). `html-to-image`·`jspdf` 의존성도 정리. 8/31 에 padding 버그로 열어 뒀던 `#1` 을 기능 제거로 종결한 셈이다. (`1ffce81`)

### 6. BS_MAINBOARD — 일정 필터 두 겹의 원인

- **1차 원인 — 부서 이름을 제목 아무 데서나 찾았다** — 8/31 에 "내 일정 판별에 부서를 포함" 하게 했는데, 그 needle 이 제목 전체에서 매칭돼 `[혜미] 대전 서구 주민세 납부기한` 이 `대전` 에 걸렸다. 그 한 건 때문에 **대전사무소 캘린더가 통째로 통과**했다. 부서로 거르는 규칙을 없앴다. (`e64d5b4`)
- **남기는 규칙을 다시 정의** — 본인이 만들었거나 참석자인 일정, 제목에 본인 이름이 있는 일정, **대괄호·꺾쇠 안에 줄여 적은 이름**(`[준수, 솔] 지노아이티 정기점검` — 한 글자여도 그 자리는 사람 이름 자리라 믿을 수 있다), 그리고 남의 것이라도 알아야 하는 근태·회의·[전직원]·출장. 실제 제목 34건으로 확인해 14건만 남았다. 캘린더당 20건 제한을 바쁜 하루가 다 먹어 뒷날이 안 오던 것은 250건으로, 월~금 고정이라 금요일엔 하루만 남던 것은 당일 기준 7일로 고쳤다. 골라낸 게 없을 때 전체를 보여 주던 대비책도 뺐다 — **사무소 캘린더를 통째로 쏟는 것보다 빈 화면이 낫다.**
- **⭐ 2차 원인 — 구글 캘린더의 `self` 는 "나" 가 아니다** — `creator.self` 는 로그인한 사람이 아니라 **"이 일정이 실린 캘린더"** 기준이다(*Whether the creator corresponds to the calendar on which this copy of the event appears*). 그래서 법승_대전사무소 같은 공유 캘린더 일정은 **누가 만들었든** `creator.self`·`organizer.self` 가 true 로 와서 필터 첫 줄 `event.mine` 을 전부 통과했다. 공판기일·제출기한이 규칙에 안 걸리는데도 대시보드에 뜬 진짜 원인이다. 이메일을 직접 맞추도록 고쳤다. `src/lib/calendar.ts` (`388e923`)
- **그 위에 세 가지** — 남의 일정은 회의·전직원·출장까지 넣어 보니 여전히 남의 사건으로 덮여 **근태만** 남겼다. 같은 근태가 법승연차·소속 사무소·HQ 에 삼중 등록돼 `[정혜미] 연차` 가 세 번 나오던 것을 제목+시작 시각으로 합쳤다. `<연차취소> [강수현] 연차` 는 **그날 자리에 있다는 뜻**인데 연차 글자만 보고 통과했으므로 제외했다.
- **앱 런처 아이콘** — 배경 타일을 벗기고 선 아이콘만 남겨 구글 아이콘과 눈높이를 맞췄다. (`dd7ee8e`)

### 7. BS_CRM — 구글 어드민 권한·조직단위 동기화

- **받아 놓고 버리던 값을 저장** — 구글 디렉터리 응답에 있으면서 쓰지 않던 `isAdmin`·`isDelegatedAdmin`·`orgUnitPath` 를 `employee_info` 에 보관한다. 어드민에서 관리자 권한을 주거나 빼는 것, 조직단위를 옮기는 것도 변경 감지에 넣었다. **권한·조직단위는 구글이 원본**이므로 CRM 값을 보존하지 않고 덮어쓴다. 마이그레이션 전에 배포돼도 동기화가 죽지 않도록 컬럼 존재를 확인하고 건너뛰며 실행할 명령을 안내로 돌려준다. `googleDirectorySyncService.js` (`11f0ce3`)
- **왜 하는가** — 사내 포털의 **조직도 편집 권한을 수기 이메일 목록(`ORG_EDITORS`) 없이 판정**하기 위한 사전 작업이다. 5번 항목에서 사람 정보를 CRM 으로 일원화한 것과 같은 줄기 — 권한도 구글을 진실로 삼는다.
- **조회 API 3종** — `GET /api/employee/admins`(위임 관리자·퇴사자 포함 옵션), `/admin-status`(생략 시 본인 기준), `/org-units`(권역 경로를 세그먼트로 쪼개 트리용 목록). 직원 목록·로그인 응답에도 관리자 여부와 조직단위 경로를 함께 실었다. **미등록 계정은 오류가 아니라 "권한 없음" 으로 응답**해 호출측 분기를 단순화했다. (`0199385`)
- **상담사를 구글 캘린더 참석자로 자동 추가** — 상담을 등록하면 선택한 상담사가 이벤트 참석자로 들어가고 참석 확정으로 표시된다. 상담사를 바꾸면 참석자도 갱신되며, 회의실과 캘린더에서 직접 추가한 외부 참석자는 유지한다. **초대 메일은 보내지 않고** 캘린더에만 반영하고, 구글 계정 이메일이 없는 직원은 제외한다. `googleCalendarService.js` (`465022e`)
