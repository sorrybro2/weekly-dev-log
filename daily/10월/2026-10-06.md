### 2. 홈페이지 V2 — 조회수 자체 집계 (이슈 #144)

- **문제와 결정** — V2에는 조회수를 올리는 코드가 없어서, 화면의 조회수와 FAQ 생성 순서가 쓰는 `tbl_bbs.viewcount`가 이관 때 복사한 값에 멈춰 있었다. 레거시 조회 로그도 8/5 이관 시점(약 830만 행)에서 멈췄다. 레거시 숫자를 매일 끌어오는 대신 V2가 직접 세기로 했다. (이슈 `#144`)
- **1차: 레거시 규칙 그대로** — `POST /api/views`가 봇 UA를 빼고, 같은 IP의 같은 글은 KST 하루 1회만 올린다. 판정은 새 표 `tbl_view_daily`의 기본키 충돌로 한다. 830만 행짜리 레거시 표에는 인덱스가 없어 쓰지 않았다. 봇 목록에는 GPTBot·ClaudeBot·Perplexity 같은 AI 크롤러를 더했다. 공개 엔드포인트가 IP 헤더를 믿으면 위조로 제한을 우회할 수 있어서, 프론트 서버만 `x-admin-key`로 부르게 막았다. (`views.service.ts`, `views.bots.ts`) (`74722b0`)
- **브라우저 신호** — 상세 페이지는 캐시돼 렌더 때 셀 수 없다. 그래서 화면이 열릴 때 브라우저가 한 번 알리고(`ViewBeacon`), Next route가 접속자 IP·UA를 붙여 백엔드로 넘긴다. 사례·칼럼·후기·소식 상세와 변호사 상세에 붙였다. (`view-beacon.tsx`, `app/api/views/route.ts`) (`47411af`)
- **2차: 들어올 때마다 +1** — "나갔다가 다시 눌러도 오르지 않는다"는 지적을 받아 하루 1회 규칙을 없앴다. 이제 무시하는 것은 봇과 같은 IP·같은 글의 10초 안 중복뿐이고, 판정 표는 `tbl_view_hit`(10초 칸 기본키, 2일 뒤 정리)로 바꿨다. 응답에 올라간 값을 실어, 상세 데이터의 5분 캐시를 기다리지 않고 숫자를 바로 바꿔 보인다. 운영에서 12초 간격 두 번 호출로 `20474 → 20475`를 확인했다. (`8e97a9d`, `6fe4d43`)

### 3. 홈페이지 V2 — 검색 표시·운영 문의

- **요약문 띄어쓰기** — 레거시 요약문이 "…아닙니다.사법경찰관은…"처럼 문장 사이 공백 없이 저장돼 검색 결과에 그대로 나갔다. 한글 문장 끝 부호 바로 뒤에 한글이 오면 한 칸 띄운다. 숫자(3.5)와 주소는 앞뒤가 한글이 아니라 바뀌지 않는다. (`content-seo.ts`, `bbs-card-grid.tsx`) (`804df08`)

- **"오늘 글이 V2에 없다" 확인** — 원인은 배치 고장이나 예약 글 숨김(`#142`)이 아니라 하루 1회(09:15) 배치 주기였다. 대상 글은 작성일이 09:00으로 찍혔지만 실제 등록은 09:16 이후였다. 15:29에 수동으로 다시 돌려 5건을 반영했다. 대책으로 작업 스케줄러 반복 트리거(09:15~19:15 매시간)를 제안했다. 배치는 멱등이라 여러 번 돌아도 안전하다. (이슈 `#131`, 커밋 없음)
- **AI 검색 재측정** — SearchTune 기준 브랜드명 없는 "형사전문 법무법인" 질의에서 20회 중 3회(15%), 처음으로 노출됐다. 서버 로그로는 ChatGPT 클릭 유입이 주 30건 안팎으로 평탄했고, OpenAI 색인 크롤은 4주 새 2.5배로 늘었다. (이슈 `#91`, 커밋 없음)

### 4. BS_MAINBOARD(사내 포털) — 조직도 그 자리 편집 (이슈 #28)

- **메뉴 → 사이드 패널** — 처음에는 사람 칸을 누르면 관리 화면으로 보내는 메뉴를 만들었다(`d8b6774`). 같은 날 그 자리 편집으로 바꿨다. 정보실만 사람 칸을 누르면 오른쪽 패널에서 역할·배지·순서·빼기·숨기기를 고치고, 박스 안에서 끌어 놓아 순서를 바꾼다. 바뀐 것은 초안으로 모았다가 확인 창을 거쳐 `PUT /api/org`로 한 번에 저장하며, 세대 번호로 동시 저장을 막는다. 편집 함수는 `lib/org/edit.ts`로 빼서 관리 화면과 같이 쓴다. (`org-chart.tsx`, `person-panel.tsx`) (`768bc9a`)
- **구성원 정보 탭** — 패널에 탭을 둘로 나눠 그림(배치)과 사람 정보를 한 화면에서 고친다. 관리 화면 수정 폼을 패널 안에 그려 모달이 두 겹으로 뜨지 않고, 열 수는 화면 폭이 아니라 놓인 자리 폭(컨테이너 쿼리)으로 정한다. 저장은 구성원 정보는 구글 어드민에 바로, 배치는 위쪽 저장 줄로 따로 간다고 탭에 적었다. (`b215803`)
- **조직 패널** — 박스 머리를 누르면 대표번호·CRM 조직 연결(조직도 파일)과 CRM organization의 이름·분류·보임·달력 URL·사업자번호·case_root(CRM DB)를 그 자리에서 고친다. 확인 창에는 다른 앱 영향(달력 URL = CRM 상담 일정 동기화, case_root = 사건앱 Drive 폴더)을 적는다. `diffOrg`가 박스 자체 변경을 보지 않아 대표번호를 바꿔도 이력에 안 남던 빈틈도 막았다. (`unit-panel.tsx`, `lib/org/diff.ts`) (`3fd1a06`)
- **박스에 사람 넣기** — 고문 위원처럼 CRM 조직과 연결되지 않아 자동으로 서지 않는 박스는 조직 패널에서 CRM 재직자를 검색해 넣는다. 한 사람을 여러 박스에 세울 수 있고, 역할은 목록 대신 직접 입력한다("금융 / 경영" 같은 고문 설명). (`employee-picker.tsx`) (`364529a`)
- **퇴사자 제외** — `reconcileOrg`가 퇴사자를 알아보고도 그대로 그려 조직도와 명부에 남았다. 사원키나 이름+내선으로 맞은 퇴사자는 모든 박스에서 뺀다. 이름만으로 맞출 때는 퇴사자를 후보에서 빼서, 사원키 없는 외부 고문이 이름 같은 퇴사자로 덮이는 일을 막았다. (`reconcile.ts`) (`7b283bf`)
- **수정 즉시 반영** — 구글 어드민 저장은 바로 끝나는데 포털이 CRM 명단(1~5분)과 지사별 내선(30분)을 기억하고 있어 화면에는 늦게 보였다. 저장 뒤 그 기억을 버리고 웹훅이 따라오는 30초 동안은 3초만 기억하며, 패널에서 저장한 값은 조직도 칸에 먼저 입힌다. 이제 남는 지연은 구글 쪽 전파(메일·챗 표시 이름)뿐이다. (`roster.ts`, `fresh.ts`) (`43da0f9`)
- **화면 잔손질** — 지사별 내선 줄이 `w-24`와 `w-full` 충돌로 427px까지 늘어나 패널 밖으로 넘치던 것(`0f05df4`), 메뉴를 접은 채로 탭을 누르면 한 번 더 눌러야 이동하던 것(`3154245`), 7일 전체를 골라도 첫날만 고른 것처럼 보이던 일정 칸(`b631061`)을 고쳤다.

### 5. BS_MAINBOARD — 화면 전환·첫 화면 속도 (이슈 #29)

- **측정부터** — 운영 요청 로그 일주일치를 나눠 보니 인스턴스가 막 켜진 직후 중간값 8.3초, 첫 화면의 약 30%가 콜드스타트였다. 켜져 있을 때도 `/members` 중간값이 5.7초였다. (이슈 `#29`)
- **CRM 캐시가 한 번도 맞지 않았다** — `fetch`의 `next.revalidate`로 캐시를 걸었지만, Next는 요청 헤더까지 캐시 열쇠에 넣는다(`generateCacheKey`). CRM 토큰의 `iat`(초)와 이메일 때문에 열쇠가 매번 달라, 명부를 그릴 때마다 변호사 1명당 1번씩 처음부터 조회했다. CRM 응답이 보는 사람과 무관하다는 것을 BS_CRM 코드로 확인한 뒤 인스턴스 메모리에 하나만 두고 같이 쓴다. 로그인 쿠키 스냅샷도 요청마다 GCS에서 받던 것을 만료 전까지 메모리에 두고, 대시보드 일정은 Suspense로 따로 그린다. 테스트 70개 통과, 배포 후 `/signin` 0.2~0.3초. (`crm/client.ts`, `auth-cookie-store.ts`) (`3cd33aa`)

**운영 조치** — 운영 조직도의 기준이 `seed.ts`에서 GCS `org/current.json`으로 넘어갔다(11:58 첫 저장). 앞으로 `seed.ts`를 고쳐도 운영에는 반영되지 않는다. 포털의 만들기·고치기·지우기는 모두 정보실만 한다는 권한 원칙을 정리하고 쓰기 API 9개 전부가 가드를 거치는 것을 확인했다. 최신 조직도 PDF와 운영 조직도를 대조한 정정 목록(이승우 대표 내선 2440 → 2121 등, 원천인 구글 어드민을 고쳐야 함)과, 자동 채움 범위·남은 결정도 이슈로 남겼다. Cloud Build 폰트 다운로드 일시 실패는 같은 커밋 재배포로 넘겼다. (이슈 `#30`, `#31`, `#32`, `#11`)
