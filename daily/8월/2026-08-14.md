### 1. 홈페이지 V2 — 메인 랜딩 장표 전환

- **메인을 다섯 장면 장표로 재구성** — 기존 메인은 세로로 길게 이어지는 일반 페이지라 각 섹션이 스치듯 지나갔다. 레거시가 쓰던 fullPage.js + GSAP 조합을 라이브러리 없이 재이식해, 휠·키보드·터치 입력을 받아 목적지 인덱스를 정하고 `transform`으로 화면을 넘긴다. 떠난 장은 되감겼다가 돌아오면 처음부터 재생돼, 위아래로 몇 번을 오가도 항상 같은 연출이 나온다. 신규 `components/home/home-deck.tsx`, 레이아웃·연출 규칙은 전부 `app/globals.css`의 `.deck*`가 담당. 서버 렌더 시점에 장표 여부를 알 수 없어 JS로 레이아웃을 켜면 첫 페인트가 튀므로, JS는 입력 제어와 인덱스만 맡겼다. (`5c8fddb`)
- **장별 배경 톤과 커서 물감 원** — 장마다 배경을 흰색·붉은색·검은색으로 바꿔 "넘어간다"는 감각을 배경색만으로 만들었다. 커서를 따라오는 단색 원을 넣되, 글자 위를 덮으면 본문이 사라지므로 판의 `background-image`로 그려 배경과 본문 사이에 넣었다. 붉은 판에서는 흰 원 안쪽 글자를 붉게 뒤집기 위해 같은 마크업을 한 벌 더 깔아 원 모양으로 잘라 포갠다(`components/ui/cursor-paint.tsx`, `.paint-invert`). blend 모드로는 브랜드 두 색의 맞교환이 표현되지 않아 배제. (`5c8fddb`)
- **분야 오목판으로 통합** — 사례 탭과 지식센터 탭 두 컴포넌트를 분야 판 하나로 합치고 삭제했다. 분야를 고르면 그 분야의 실제 수행 사례와 지식센터 글이 함께 나온다. 최근 글 한 뭉치를 받아 분야로 나누던 방식은 최근 N건에 안 걸린 분야가 글이 있는데도 빈칸이 되므로, 분야별로 직접 조회해 그 구멍을 없앴다(`components/home/field-board.tsx`). (`5c8fddb`)
- **실물 확인 피드백 3종 반영** — 브라우저로 처음 굴려본 뒤 나온 지적을 반영했다. ① **장 넘김이 정신없다** → 500ms를 1000ms로 늦추고 이동 곡선을 power3.out에서 시작·끝이 모두 눌린 곡선으로 교체. 시간을 800·1100·2000ms까지 올려봐도 체감이 안 바뀌었는데, power3.out이 거리의 8할을 앞 3할 시간에 몰아 가는 곡선이라 늘려도 초반 급가속이 남기 때문이었다 — 실제 원인은 시간이 아니라 곡선이었다. 곡선용 CSS 변수를 `--deck-ease`(요소 등장)와 `--deck-ease-move`(판 이동) 둘로 분리. ② **배경이 극한이라 멀미난다** → 판 순서가 순백→진홍→순흑이라 명도가 0과 100을 오갔다. 흰 판을 `zinc-50`, 검은 판을 `zinc-900`으로 양 끝만 안으로 당기고 붉은 판은 브랜드 면이라 유지. ③ **분야 칸 구분이 안 된다** → 격자선을 `white/15`에서 `white/30`으로 올리고 안 고른 칸에 면을 깔아 누를 수 있는 상자로 읽히게 했다. (`689667c`)
- **장표 경계값 버그 교정** — 장표 적용 기준이 "세로 700px 이상"이었는데, 정작 배제하려던 대상인 태블릿 가로(1024×768)가 `768 ≥ 700`이라 그대로 통과하고 있었다. 한 장이 `768 − 헤더 64 = 704px`로 눌린 채 변호사 카드와 분야 판이 들어가던 상태. 800px로 올려 768 세대를 실제로 걸러내고 iPad Air(820)·Pro(834)는 장표로 남겼다. 이 조건 문자열은 CSS 3곳과 JS 1곳이 반드시 같아야 하며 한쪽만 고치면 레이아웃은 장표인데 휠 제어가 없어 스크롤이 먹통이 된다. (`689667c`)

### 2. 홈페이지 V2 — 히어로 법승 VV 마크 3D

- **Blender GLB 제작 → three.js 적용** — 히어로 오른쪽에 법승 VV 심볼을 입체로 세웠다. `logo.svg`가 path 2개뿐이라 Blender 압출이 정석이라 판단, Gemini로 Blender 파이썬 스크립트 초안을 받아 정리한 뒤(`tools/blender/logo-to-glb.py`) Scripting 탭에서 실행해 `public/models/vv-mark.glb`를 뽑았다. 한 번 말아먹은 지점이 있다 — Blender SVG 임포트는 0.001 스케일이라 로고가 1.65cm로 들어오는데, 커브의 `extrude`/`bevel_depth`는 오브젝트 스케일이 아니라 커브 데이터의 로컬 단위를 쓴다. 100배 확대를 데이터에 굽기 전에 extrude를 넣으면 폭의 3배 두께가 되어 알약 모양이 나온다. `임포트 → 100배 → transform_apply → extrude` 순서로 고정했다. 보조 스크립트로 복구·경량화(`repair-glb.py`, `thin-glb.py`)도 함께 뒀다. (`bc720ca`, `639e582`)
- **크로스페이드 교체 구조** — 히어로가 LCP 요소라 무거운 것을 첫 페인트에 얹을 수 없다. 기존 CSS 압출판(`vv-mark-3d.tsx`)을 먼저 그리고, 준비되면 WebGL판(`vv-mark-gl.tsx`)으로 갈아끼우는 감싸개(`vv-mark.tsx`)를 뒀다. 두 구현의 정지 각도가 다르면 교체되는 순간 마크가 튀므로 `BASE_RY`/`BASE_RX`/`TILT` 상수를 `export`로 열어 공유하게 했다. 마크가 3D가 되면서 그 자리가 "로고를 놓는 여백"이 아니라 장면이 되어, 히어로 오른쪽 컬럼을 `0.9fr`에서 `1fr`로 넓히고 `items-stretch`로 세로 여유를 줬다. (`bc720ca`)
- **AI 3D 생성(Tripo3D) 검토 후 불채택** — GLB 익스포트가 유료라 턴테이블 영상만 확보해 16컷을 뽑아 검토했다. ① 흰 획 전체에 세로 골(AI 추론 메시 특유, 후처리 불가) ② 특정 각도에서 마크가 얇은 막대로 붕괴해 360° 회전 시 로고가 주기적으로 사라짐 ③ 검은 바닥·반사가 베이크돼 밝은 배경안에 키잉이 필요한데 흰 획과 배경 밝기가 겹침 ④ 실제 로고는 각진 직선 획인데 Tripo는 휘어 벌어진 리본 — 네 가지 이유로 불채택하고 아트디렉션 레퍼런스로만 썼다.
- **3D 확인용 스크린샷 도구** — 3D는 값을 바꿔도 결과를 코드로 확인할 수 없어 매번 사람에게 새로고침·캡처를 요청하는 왕복이 생긴다. 실행 중인 dev 서버 화면을 playwright로 직접 찍는 `frontend/tools/shot.mjs`를 만들어 그 왕복을 없앴다. (`270dc49`)
- **이슈 등록** — 시안 결정부터 Blender 제작·three.js 적용까지 전 과정과 남은 일(실물 육안 검증, LCP 방어 확인, 반응형, 증거판 배치 미결)을 이슈 #113으로 등록.

### 3. 홈페이지 V2 — 개발환경·안정성

- **dev 서버가 계속 죽던 원인 제거** — 작업 중 메인 페이지가 반복적으로 500(Internal Server Error)을 뱉었다. 프로세스는 살아 있는데 `.next` 매니페스트가 사라지는 증상이라 처음엔 Windows 파일 경합·좀비 프로세스를 의심했으나, 프로세스 목록을 확인하니 **다른 세션에서 `next build`가 동시에 돌고 있었다.** `next build`는 시작할 때 `.next`를 통째로 비우는데 dev 서버가 바로 그 폴더를 읽고 있어 매니페스트가 눈앞에서 사라진 것. dev는 `.next-dev`, 빌드는 `.next`로 출력 폴더를 분리해 근본 제거했다. 함께 `standalone` 출력을 빌드에서만 켜 Windows 경로길이 제한으로 `.next` 정리가 막히던 문제를 피하고, Turbopack 워크스페이스 루트를 저장소로 고정해 상위 폴더까지 감시하지 않게 했다(lockfile이 3개라 상위 폴더를 루트로 오인하고 있었다). (`994d0f5`)
- **유튜브 목록 실패 시 빈 화면** — 홈 보도 섹션의 법승TV 칸이 가끔 "등록된 게시물이 없습니다"로 비었다. 원인은 두 겹이었다. ① `YOUTUBE_API_KEY`가 어디에도 설정돼 있지 않아 1순위인 Data API가 한 번도 쓰인 적이 없고 항상 RSS 폴백만 탔다 ② 그 RSS가 실측 6회 중 5회 404를 뱉는다. 게다가 1차 시도만 `revalidate: 3600`이라 404 응답이 1시간 캐시되고, 재시도로 겨우 받아낸 성공은 `no-store`라 저장이 안 되는 구조 — 실패만 들러붙었다. 마지막으로 성공한 목록을 1시간 보관해 실패 시 대신 내보내고, RSS 요청을 전부 `no-store`로 바꿔 실패가 캐시되지 않게 했다. 654개 영상이 있는 채널이 "게시물 없음"으로 보이던 문구도 채널 링크로 교체. (`6adde6b`)
- **커밋 규칙 문서 변경** — `docs/git-commit-rule.md`가 "실행 가능한 명령어만 출력"이었던 것을 "직접 커밋·푸시하고 결과만 보고"로 바꿨다. 명령어를 사람이 대신 실행하는 왕복이 불필요하다는 판단. (`20e2d52`)

### 4. 사건관리 앱 — 기록신청·사건목록

- **기록신청 상태 변경 오조작 차단** — 목록에서 드롭다운을 고르는 즉시 PATCH가 나가 행을 잘못 눌러 엉뚱한 사건의 상태를 바꾸는 사고가 나기 쉬웠다. 추가입력이 없는 전환은 `AlertDialog`로 "현재상태 → 변경상태"와 함께 사건·의뢰인·관할·신청서류·신청일을 보여주고 확인해야 저장하게 했다. 취소하면 PATCH를 보내지 않고 드롭다운은 `record.status`로 제어되므로 원래 값으로 되돌아간다. 재신청·완료는 기존 추가입력 팝업의 저장·취소가 이미 확인 절차라 확인창을 겹쳐 띄우지 않고 같은 식별 정보를 팝업 상단에 넣었다. 식별 정보 블록은 `RecordSummary`로 뽑아 양쪽이 공유한다(`RecordRequestListPage.tsx`). 이슈 #336. (`43ca773`)
- **법원사건진행내역 날짜 선택 잔류** — 고른 날짜를 필터와 무관하게 들고 있어 조회범위·구분·지사를 바꿔도 이전 선택이 붙잡혔다. 새 목록에 우연히 같은 날짜가 있으면 거기 눌러앉고 없으면 조용히 다른 날짜로 튀는 구조 — 구분을 바꿨다 되돌렸을 때 엉뚱한 날이 다시 선택되던 원인이다. 선택을 "어느 필터 조합에서 골랐는지"(`filterSig`)와 함께 저장해 지문이 다르면 선택 없음으로 본다. `useEffect` + `setState` 대신 순수 파생이라 렌더 낭비도 없다(`CourtProgressRecentPage.tsx`). 백엔드는 무관함을 확인(recent/dates와 recent 모두 같은 KST→UTC 변환 사용). 제보된 "오늘 필터 오류"가 이 증상인지는 미확정이라 이슈 #335에서 계속 확인. (`9241383`)
- **사건목록 병합 셀 기일충돌 배경 누락** — 병합된 당사자 셀은 그룹 첫 행에만 속하는데 충돌 판정을 행 단위로만 해서, 겹침이 그룹의 2번째 이후 행에 걸리면 첫 행 `tr`의 흰 배경이 그대로 비쳤다. 그룹 안에 충돌 행이 하나라도 있으면 병합 셀도 충돌로 보도록 `groupConflict`를 행에 내려준다. 소유 행 자체가 충돌이면 `tr` 배경이 이미 분홍이라 알파가 쌓이므로 그때는 셀을 따로 칠하지 않는다(`CaseListTable.tsx`). (`20df54c`)

### 5. 사건관리 앱 — 공통 UX

- **사이드패널·드로어 ESC 닫기** — 공용 훅 `useEscapeClose`를 신설해 두 가지를 처리했다. ① **중첩** — 열린 오버레이를 모듈 스택으로 관리해 가장 나중에 열린 하나만 ESC를 처리한다. 사건패널 위에 계약패널이 떠 있을 때 한 번에 둘 다 닫히지 않는다. ② **수정 중 차단** — 수정 모드면 ESC를 그 자리에서 삼킨다. 그냥 무시하면 아래 패널로 흘러가 그쪽이 닫혀버린다. 적용 대상은 사건·계약 사이드패널, 계약 미리보기, Drive 파일, 기록신청 상세 드로어, 문서수발신 상세 드로어 6개이며 각각 차단 조건이 다르다(읽기 전용인 미리보기·Drive는 차단 없음, Drive는 PDF 미리보기가 위에 있으면 그것부터 닫음). 상세 드로어 2개는 이슈 목록에 없었지만 같은 우측 슬라이드 UI라 함께 넣었다. 이슈 #331. (`e572d63`)

### 6. 사건관리 앱 + CRM — 상담 예약금 입금여부 표기 (양쪽 연동)

- **캘린더 제목에 입금여부 명시 (사건앱)** — 상담 예약을 잡으면서 금액만 먼저 적어두는 경우가 많아, 제목에 금액이 있어도 실제로 받은 돈인지 구분되지 않았다. 예약금·상담료 두 항목 모두 앞에 `*`를 붙이고 뒤에 입금여부를 항상 명시하도록 했다(`*예약금 55,000원 미입금 *상담료 110,000원 입금완료`). 입금여부 출처는 사건앱이다 — 이슈 #320 작성 시점에는 예약금 금액만 있었지만 이후 #327(마이그레이션 027)로 예약금도 상담료와 동일한 결제 컬럼 세트를 갖게 됐고, 상담료 입력창에서 직원이 직접 고르는 값이라 이게 가장 최신이다. 예약금 "금액"만 종전대로 CRM 값을 쓴다. 정규식은 접두 `*`와 입금여부 꼬리를 모두 optional로 둬서 이전 형식으로 이미 나가 있는 제목도 걷어내고 새 형식으로 교체한다(idempotent 유지). 매칭 시작을 `\s*`에서 `\s+`로 조였는데, `*`를 매칭 대상에 넣으면서 `**{특이사항}`의 별표를 잡아먹을 수 있기 때문이다(`consultation_crm_sync_service.py`). 이슈 #320. (`e9f528e`)
- **입력 UI를 스위치로 교체 (CRM)** — 예약금 미입금 체크박스를 입금완료/미입금 스위치로 바꾸고(초록/빨강) 예약금 라벨 줄 오른쪽으로 옮겼다. 상세 보기에서는 스위치 대신 상태 텍스트만 표시하고, 항목명을 "예약금(선입금)"에서 "예약금"으로 통일했다. 캘린더 제목이 입금 시에도 `*예약금 55,000원 입금완료`로 나가도록 백엔드(`googleCalendarService.js`)와 미리보기를 함께 수정. 상담일정 폼도 같은 스위치와 명칭으로 맞췄다. (`aca3767`)
- **스위치 노출 조건 수정 (CRM)** — 금액이 비어 있으면 스위치가 숨겨져 입금 상태를 못 정하던 것을 항상 노출로 변경. 상세 보기에서는 금액도 없고 미입금도 아니면 상태 표시를 생략하고, 입금완료는 회색으로 낮추고 미입금만 빨간색으로 남겨 눈에 띄게 조정했다. (`7c7ca8b`)
