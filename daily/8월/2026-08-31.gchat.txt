📋 *일일 업무 보고 (2026. 08. 31.)*

오전에 문의 관리 일괄 상태 변경을 붙여 배포하고, 오후에는 사내 포털을 새로 세운 하루. 기존 Google Sites 포털은 조직도를 PDF 썸네일로 박아 둔 구조라 편집도 검색도 안 됐다. 조직도 데이터는 39차 배포본 PDF에서 텍스트를 좌표째 추출해 옮겼고 1차 전사 오탈자 8건을 바로잡았다. 인증에서는 매번 로그인을 누르게 만든 범인이 내 설정이었다는 것을 실제 인증 URL로 확인해 걷어냈다. 금일 커밋 16건(2개 repo), 이슈 8건 생성.

🌐 *〔홈페이지 V2 : 문의 관리 일괄 처리〕*

•  *일괄 상태 변경* — 한 건씩 눌러 바꾸던 것을 체크박스로 골라 대기:완료:보류:이메일답변 일괄 변경 (b39c4eb)
•  *인덱스 열 제거* — 굳이 볼 일 없는 번호 열을 없애고 그 자리를 체크박스로
•  *전체 선택 범위 제한* — 필터에 걸린 수천 건을 되돌릴 수 없이 뒤집는 사고를 막기 위해 현재 페이지까지만
•  *서버측 재검증* — 담당 지사 밖이거나 삭제된 건은 서버가 걸러내고 실제로 바뀐 건수를 알림
•  *배포* — 백엔드 다음 프론트 순서. 프론트가 먼저 뜨면 새 엔드포인트가 없어 적용 버튼이 404 (이슈 #123)

🏢 *〔사내 포털 : 신규 구축〕*

•  *Google Sites 대체* — 조직도 PDF 썸네일 구조를 Next.js 앱으로. 조직도:사내 앱:일정을 한 화면에 (9b8fee0)
•  *DB 없이 구성* — 조직도를 JSON 스냅샷으로 관리. 저장할 때마다 변경 내역과 함께 버전이 쌓임
•  *원본 PDF에서 데이터 추출* — 스크린샷 대신 PDF 텍스트를 좌표째 뽑아 88명 이관. 오탈자 8건 교정 (문월성:문필성, 법조:협조 등)
•  *대외비 처리* — 조직도 PDF가 public에 있으면 로그인 없이 URL만으로 받아진다 : reference로 이동 (a0f37dc)
•  *파비콘* — 흰 여백이 절반 넘어 16px에서 점처럼 보이던 원본을 잘라 다시 앉힘. 3.3MB에서 104KB (cb04bc2)

🔐 *〔사내 포털 : 로그인 클릭 제거〕*

•  *원인은 내 설정이었다* — prompt=consent를 넘기고 있어 구글이 세션 유무와 무관하게 매번 동의 화면을 띄웠다 (53336b3)
•  *실물 검증* — CSRF 토큰을 받아 authorize URL을 직접 확인. prompt 없음, hd 지정, access_type=offline, PKCE 확인
•  *조용한 재인증 방어* — 그때는 refresh token이 다시 오지 않는다. 최초 동의 때 받은 값을 덮어쓰지 않도록 처리
•  *로그인 페이지* — 버튼 없이 도착 즉시 구글로. 오류일 때만 멈춰 무한 왕복 방지 (18d74a7)
•  *허용 도메인 다중화* — 계정 도메인과 웹 도메인이 달라 한쪽이 통째로 잠길 수 있었다 (10670f5)

🗂 *〔사내 포털 : 조직도와 명부〕*

•  *그림과 명부 분리* — 그림에서는 대표가 다섯 박스에 나온다. 명부에서는 한 번만 싣도록 중복 제거 (18eb602)
•  *사무소를 루트로* — 권역 묶음을 없애고 서울:회생:남양주 순서로 평평하게. 12개 루트 (6286560)
•  *실 소속 자동 배치* — 정보실 (대전)은 대전으로, 재무실:홍보실 (서울)은 서울로. 괄호를 읽는 규칙이라 새 실도 먹는다 (3013e09)
•  *구성원 클릭시 상세와 통화* — 대표번호로 연결한 뒤 내선을 눌러 주는 형식. 사내 전화기용 내선만 걸기도 제공
•  *편집 범위 축소* — 조직 구성은 확정본. 구성원만 편집하고 직위:직책:배지는 드롭다운, 순서는 끌어서 변경
•  *변경 이력* — 누가 언제 무엇을 바꿨는지 남기고 그 시점으로 되돌릴 수 있다

🔗 *〔사내 포털 : 구글 연동〕*

•  *관리자 권한 없이 프로필 연동* — Admin SDK는 도메인 위임이 필요하지만 People API는 본인 권한으로 같은 도메인 프로필을 읽는다 (92d2642)
•  *캘린더 구독 전체 합산* — primary 하나만 읽어 공유 캘린더 일정이 통째로 빠졌었다. 90일치 조회해도 1건이었다 (7a7ada0)
•  *내 일정 판별에 부서 포함* — 사내 일정이 부서 이름으로 적혀 이름만으로는 안 걸렸다 (10670f5)
•  *GCP 확인* — 프로젝트 flutter-crm-e44f5로 확정. 필요한 API가 이미 전부 켜져 있어 켤 것이 없었다 (이슈 #3)

🐞 *〔사내 포털 : 자초한 결함 3건〕*

•  *일정 카드가 사라짐* — AppLauncher의 h-full이 오른쪽 단 높이를 통째로 먹어 일정이 높이 0으로 눌림 (a665694)
•  *카드가 200px 떨어져 나옴* — position fixed가 transform 걸린 조상 기준으로 잡히고 있었다. body 포털로 해결 (8fede5c)
•  *내보내기가 백지로 저장됨* — getViewportForBounds의 padding은 픽셀이 아니라 비율. 24를 넘겨 배율이 1/49로 뭉개짐 (이슈 #1)

•  *확인 필요* — 내보내기 실물 검증 (#1), 시드 오탈자 전수 확인 (#2), 캘린더 소스 (#4)

✅ *〔금일 종합〕*

가장 값이 나간 것은 기능이 아니라 원인 규명 두 건이다. prompt=consent가 앱마다 로그인을 누르게 만든 범인이었다는 것, position fixed가 transform 걸린 조상 아래에서는 뷰포트 기준이 아니라는 것. 둘 다 코드는 맞는데 화면이 틀린 종류라 좌표를 아무리 고쳐도 안 잡혔을 문제였다. 데이터는 스크린샷 전사를 PDF 추출로 대체해 오탈자 8건을 걷어냈고, 구글 연동은 관리자 권한 없이 도메인 프로필을 읽는 경로를 찾아 서비스 계정 도메인 위임이라는 큰 설정 작업을 당장은 피했다. 화면 배치가 요구에 따라 네 번 바뀌며 자초한 버그가 세 건이라 배치 변경의 비용을 과소평가했다. 금일 2개 repo에 걸쳐 커밋 16건, 이슈 8건 생성.
