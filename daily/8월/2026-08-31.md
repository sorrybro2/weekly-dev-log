# 일일 업무 보고 (2026. 08. 31.)

> 오전에 문의 관리 **일괄 상태 변경**을 붙여 배포하고, 오후에는 **사내 포털을 새로 세운** 하루였다. 기존 Google Sites 포털은 조직도를 PDF 썸네일로 박아 두는 구조라 편집도 검색도 안 됐고, 오늘 이것을 Next.js 앱으로 대체해 **조직도 · 사내 앱 · 일정을 한 화면에** 모았다. 조직도 데이터는 39차 배포본 PDF에서 텍스트를 좌표째 추출해 옮겼고, 손으로 옮겼던 1차 전사의 오탈자 8건(문월성→문필성, 법조→협조 등)을 그 과정에서 바로잡았다. 인증에서는 **`prompt=consent` 가 매번 동의 화면을 강제로 띄우고 있었다**는 것을 실제 인증 URL로 확인해 걷어냈고, 이것이 "앱마다 로그인 딸깍" 의 원인이었다. 그 밖에 구글 도메인 프로필(사진 · 이메일)을 **관리자 권한 없이** 붙이는 경로를 찾았고, 화면 배치는 4번 갈아엎었다 — 금일 커밋 16건(2개 repo), 이슈 8건 생성

## ⏱️ 10초 핵심 요약

**[홈페이지 V2 / 문의 관리 일괄 처리]**
- **한 건씩 눌러 바꾸고 있었다**: 문의가 쌓이면 상태를 하나하나 바꿔야 했다 → 행 체크박스 + 선택 시에만 뜨는 일괄 변경 바
- **인덱스 열을 체크박스로 대체**: 굳이 볼 일 없는 번호 열을 없애고 그 자리를 썼다
- **🔴 전체 선택은 현재 페이지까지만**: 필터에 걸린 수천 건을 되돌릴 수 없이 뒤집는 사고를 막기 위해 의도적으로 범위를 좁힘
- **서버에서도 다시 거른다**: 담당 지사 밖이거나 이미 삭제된 건은 서버가 걸러내고 **실제로 바뀐 건수**를 알린다
- **배포 순서가 곧 안전장치**: 백엔드 → 프론트 순. 프론트가 먼저 뜨면 새 엔드포인트가 없어 `적용` 이 404

**[사내 포털 / 신규 구축 — Google Sites 대체]**
- **왜 새로 만드나**: 기존 포털은 조직도를 PDF 뷰어에 박아 둔 썸네일이라 편집 · 검색 · 연동이 전부 불가능
- **DB 없이 간다**: 조직도를 JSON 스냅샷으로 관리(Vercel Blob / 로컬 파일). 저장할 때마다 **변경 내역과 함께** 버전이 쌓인다
- **원본 PDF에서 데이터 추출**: 스크린샷 OCR 대신 PDF 텍스트를 좌표째 뽑아 88명을 옮김. 1차 전사 오탈자 8건 교정
- **대외비 처리**: 조직도 PDF가 `public/` 에 있으면 로그인 없이 URL 만으로 받아진다 → `reference/` 로 이동

**[사내 포털 / 인증 — 로그인 클릭 제거]**
- **🔴 원인은 내 설정이었다**: `prompt=consent` 를 넘기고 있어 구글이 세션 유무와 무관하게 매번 동의 화면을 띄웠다
- **실제 인증 URL로 검증**: CSRF 토큰을 받아 authorize URL 을 뜯어보니 `prompt` 없음 · `hd` 지정됨 · `access_type=offline` 확인
- **조용한 재인증의 함정**: 그때는 refresh token 이 다시 오지 않는다 → 최초 동의 때 받은 값을 덮어쓰지 않도록 방어
- **도메인 검증은 서버에서**: `hd` 파라미터는 계정 선택창 힌트일 뿐 차단 수단이 아니다

**[사내 포털 / 조직도 · 명부]**
- **그림과 명부를 분리**: 조직도 그림은 한 사람이 다섯 박스에 나온다(대표 · 이사회 · 총괄 · 회생 · 서울). 명부에서는 **한 번만** 싣는다
- **사무소를 루트로**: 권역 묶음을 없애고 서울 · 회생 · 남양주 … 순서로 평평하게. 표시 순서가 곧 중복 제거 우선순위
- **실 소속은 이름으로 배치**: `정보실 (대전)` → 대전, `재무실 (서울)` → 서울. 괄호를 읽으므로 새 실이 생겨도 규칙이 먹는다
- **구성원 클릭 → 상세 + 통화**: 대표번호로 연결한 뒤 내선을 눌러 주는 `tel:0421234567,,7012` 형식

**[사내 포털 / 구글 연동]**
- **⭐ 관리자 권한 없이 프로필을 읽는 경로**: Admin SDK 는 도메인 위임이 필요하지만 People API 의 `listDirectoryPeople` 은 **본인 권한으로** 같은 도메인 프로필을 읽는다
- **캘린더는 구독 전체를 합산**: `primary` 하나만 읽어 공유 캘린더 일정이 통째로 빠졌었다
- **내 일정 판별에 부서를 포함**: 사내 일정은 `<승우, 정보실, 마케팅팀> 홈페이지 회의` 처럼 부서로 적힌다. 이름만으로는 안 걸림

**[사내 포털 / 화면 결함 — 자초한 것들]**
- **일정 카드가 사라짐**: `AppLauncher` 의 `h-full` 이 오른쪽 단 높이를 통째로 먹어 일정이 실선 하나로 눌림
- **⭐ 카드가 200px 떨어져 나옴**: 좌표 계산은 맞았는데 `position: fixed` 가 **transform 걸린 조상 기준**으로 잡히고 있었다(등장 애니메이션) → body 포털
- **내보내기가 백지로 저장됨**: `getViewportForBounds` 의 padding 은 픽셀이 아니라 **비율**. `24` 를 넘겨 배율이 1/49 로 뭉개짐

#### 기반

- **DB 없는 구조를 택함** — 조직도를 JSON 스냅샷 하나로 관리한다. 배포는 Vercel Blob(`org/current.json`), 로컬은 `data/org.json`. 스키마 · 마이그레이션이 없고, 저장할 때마다 버전 파일이 쌓여 이력이 공짜로 따라온다. 인증도 Auth.js JWT 세션이라 DB 어댑터가 필요 없다. `src/lib/org/storage.ts` (`9b8fee0`)
- **조직도 렌더링** — React Flow + dagre 로 원본 PPT 와 같은 박스 · 연결선 구조를 재현. 부문 블록과 권역 블록을 위아래 단으로 나누고, 권역 헤더가 소속 지사 폭을 덮으며 그 아래 지사별 대표번호가 한 줄로 늘어선다. `src/lib/org/layout.ts` · `unit-node.tsx` (`9b8fee0`)
- **데이터 이관** — 39차 배포본 PDF 에서 텍스트를 좌표째 추출해 88명을 옮겼다. 스크린샷으로 먼저 옮겼던 1차 전사에서 문월성→**문필성**, 법조→**협조**, 유진용→**유진웅**, 고경화→**고경환**, 전규성→**전금성**, 오동은→**오용문**, 성정민→**임정민**, 김보연→**김봉연** 8건이 잡혔다. `src/lib/org/seed.ts` (`9b8fee0`)
- **대외비 처리** — 조직도 PDF 를 `public/` 에 두면 인증을 거치지 않고 URL 만으로 받아진다. `reference/` 로 옮기고 취급 주의사항을 함께 남겼다. (`a0f37dc`)
- **파비콘** — 원본이 2048px 중 마크가 1728×949 뿐이고 나머지가 흰 여백이라 16px 에서 점처럼 보였다. 여백을 잘라 꽉 차게 다시 앉히고(3.3MB→104KB) `icon.png` · `apple-icon.png` · `favicon.ico`(16/32/48) 세 벌을 만들었다. (`cb04bc2`)

#### 인증 — 로그인 클릭 제거

- **원인 규명** — 앱마다 로그인을 누르던 문제의 원인이 내 OAuth 설정이었다. `prompt=consent` 를 넘기고 있어 구글이 세션 유무와 관계없이 매번 동의 화면을 띄웠다. 이 값을 빼면 기존 세션을 보고 화면 없이 되돌려 보낸다. `src/lib/auth.ts` (`53336b3`)
- **조용한 재인증의 부작용 방어** — 그 경로에서는 refresh token 이 다시 오지 않는다. 최초 동의 때 받아 둔 값을 덮어쓰지 않도록 `account.refresh_token` 이 있을 때만 갱신하게 했다. 이걸 안 하면 캘린더 연동이 하루 만에 끊긴다. (`53336b3`)
- **실물 검증** — 자격증명을 넣은 뒤 CSRF 토큰을 받아 authorize URL 을 직접 뜯었다. `prompt` 없음 · `hd=law-win.co.kr` · `access_type=offline` · PKCE(S256) 확인. 리디렉션 URI 도 콘솔 등록값과 일치.
- **로그인 페이지** — 버튼을 없애고 도착 즉시 구글로 넘긴다. 도메인 거부 등 오류가 있을 때만 멈춰 무한 왕복을 막고, 자동 이동이 4초 안에 안 되면 수동 버튼을 보여 준다. 자격증명이 없으면 무엇을 넣어야 하는지 안내한다 — 이전에는 빈 화면에서 계속 돌았다. `src/app/signin/page.tsx` · `auto-signin.tsx` (`18d74a7`)
- **허용 도메인 다중화** — 계정 도메인(`law-win.co.kr`)과 웹 도메인(`lawwin.co.kr`)이 달라 한쪽 계정이 통째로 잠길 수 있었다. 쉼표로 여러 도메인을 받게 함. (`10670f5`)

#### 조직도 · 명부

- **그림과 명부를 분리** — 조직도 그림에서는 이승우 대표가 대표 · 이사회 · 총괄 · 회생 · 서울 다섯 박스에 나온다. 그림에서는 맞지만 명부에서는 같은 사람이 다섯 번 나오는 셈이라 읽을 수 없다. 이름+내선으로 중복을 걷어 사무소에 한 번만 싣는 `roster` 를 따로 만들었다. `src/lib/org/roster.ts` (`18eb602`)
- **사무소를 루트로** — 권역 묶음을 없애고 서울 · 회생 · 남양주 · 수원 · 인천 · 부천 · 천안 · 대전 · 청주 · 광주 · 부산 + 지사 미소속 12개를 평평하게 세웠다. 표시 순서가 곧 중복 제거 우선순위라 이승우 대표는 서울에 실린다. (`6286560`)
- **실 소속 편입** — `정보실 (대전)` → 대전, `재무실 (서울)` · `홍보실 (서울)` → 서울. 실 이름의 괄호에 위치가 들어 있으니 그걸로 배치한다. 하드코딩이 아니라 규칙이므로 새 실이 생겨도 먹는다. 서울 22→25명, 대전 11→13명, 지사 미소속은 고문 위원 2명만 남는다. (`3013e09`)
- **구성원 상세 + 통화** — 이름을 누르면 상세 카드가 열리고 거기서 전화를 건다. 대표번호로 연결한 뒤 내선을 눌러 주는 `tel:0427161190,,7012` 형식이고, 사내 전화기용 `내선만 걸기` 도 함께 둔다. `person-card.tsx` (`18eb602`)
- **편집 범위 축소** — 조직 구성은 확정본이므로 하위 조직 추가 · 조직 삭제 · 상위 조직 변경 · 순서 이동을 걷어내고 **구성원만** 편집하게 했다. 직위 · 직책 · 배지는 자유 입력을 없애고 드롭다운으로, 순서는 손잡이를 잡고 끌어서 바꾼다. `inspector.tsx` (`9b8fee0`)
- **변경 이력** — 저장 한 번이 스냅샷 하나다. 이전 상태와 비교해 구성원 추가 · 삭제 · 항목 수정 · 순서 변경 · 기준일 변경을 사람이 읽을 수 있는 목록으로 남기고, 그 시점으로 되돌릴 수 있다. 되돌리기는 과거 스냅샷을 현재로 되돌린 뒤 다시 저장하는 방식이라 이력을 덮어쓰지 않는다. `src/lib/org/diff.ts` (`9b8fee0`)

#### 구글 연동

- **⭐ 관리자 권한 없이 프로필을 읽는 경로** — 사진 · 이메일을 붙이려면 Admin SDK 가 필요한 줄 알았으나, 그건 관리자 권한이나 서비스 계정 도메인 위임을 요구한다. People API 의 `listDirectoryPeople` 은 **로그인한 본인 권한으로** 같은 도메인 프로필을 읽는다. 별도 관리 콘솔 작업 없이 동작한다. `src/lib/directory.ts` (`92d2642`)
- **캘린더를 구독 전체로** — `primary` 하나만 읽어 "법무법인 법승" 같은 공유 캘린더 일정이 통째로 빠졌다(90일치를 조회해도 1건). `calendarList` 로 구독 중이고 화면에 켜 둔 캘린더를 받아 합친다. 숨김 · 선택 해제 · `freeBusyReader`(제목을 못 읽어 "바쁨" 으로만 나옴)는 제외. `src/lib/calendar.ts` (`7a7ada0`)
- **내 일정 판별** — 공유 캘린더를 다 합치면 남의 반차로 화면이 찬다. 본인 기본 캘린더의 일정 + 본인이 참석자인 일정 + 제목에 이름이 든 일정으로 좁혔는데, 사내 일정이 `<승우, 정보실, 마케팅팀> 홈페이지 회의` 처럼 **부서로 적혀** 안 걸렸다. 조직도에서 본인 소속을 찾아 판단 근거에 넣었다(진솔 → 정보실). 그래도 하나도 안 걸리면 전체를 보여 주고 그 사실을 알린다 — 빈 화면이 되는 것보다 낫다. (`10670f5`)
- **GCP 확인** — 프로젝트를 `flutter-crm-e44f5` 로 확정. Calendar · People · Drive · Sheets · Identity Toolkit 이 이미 켜져 있어 **켤 API 가 없었다**. OAuth 클라이언트 생성만 웹 콘솔 작업. 기존 `lawwin_portal` 클라이언트는 Chrome 확장 프로그램 유형이라 서버 앱에 쓸 수 없어 웹 애플리케이션으로 새로 만들었다. 이슈 `#3`

#### 화면 배치와 결함

- **2단 배치** — 왼쪽 한 면을 구성원이 차지하고, 오른쪽 위에 앱 8개를 한 줄로, 그 아래를 일정이 채운다. 앱은 카드 테두리를 걷어내고 아이콘 + 이름만 남겼으며, 8열에 긴 이름이 안 들어가므로 짧은 이름을 따로 뒀다(고객관리 CRM → CRM). `src/app/page.tsx` · `app-launcher.tsx` (`6286560`, `f9256ef`)
- **일정이 사라진 버그** — `AppLauncher` 에 `h-full` 이 남아 오른쪽 단 높이를 통째로 가져갔다. 일정 카드가 높이 0 으로 눌려 실선 하나만 남았고, `mt-auto` 가 바로가기를 바닥까지 밀어냈다. 두 증상이 같은 원인. (`a665694`)
- **⭐ 카드가 200px 떨어져 나온 버그** — 좌표 계산은 맞았는데 `position: fixed` 가 뷰포트가 아니라 조상 기준으로 잡히고 있었다. 대시보드 컨테이너의 등장 애니메이션이 `transform` 을 걸어 컨테이닝 블록을 만들기 때문이다. body 로 포털해 해결. (`5035e87`, `8fede5c`)
- **내보내기가 백지로 저장되던 버그** — `getViewportForBounds(bounds, w, h, minZoom, maxZoom, padding)` 의 padding 은 픽셀이 아니라 **비율**인데 `24` 를 넘겼다. 배율이 `1/(1+2×24)` ≈ 1/49 로 뭉개져 도표가 점만 하게 나왔다. `0.04` 로 수정. 이슈 `#1` (미검증 — 헤드리스에서 다운로드를 못 잡아 실제 파일은 확인하지 못함)
- **연결선 정리** — React Flow 기본 간선은 간선마다 가로줄 높이를 따로 잡아 형제끼리 계단처럼 어긋난다. 경로를 직접 그려 `내려가기 → 공유 가로줄 → 내려가기` 세 구간만 남겼고, 고문 위원 · 인사위원회는 원본처럼 선 없이 배치했다. `org-edge.tsx` (`9b8fee0`)
