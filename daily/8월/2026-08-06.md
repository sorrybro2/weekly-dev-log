## 📝 상세 업무 내역

### 1. 홈페이지 V2 — 도메인 컷오버 실행

> 배경: 어제 작성한 런북대로 가비아 A 레코드 2줄을 교체해 실서버를 V2로 넘기는 날. 런북의 전제(Cloud Run 도메인 매핑)가 실행 단계에서 무너져 인프라 경로를 바꿔야 했다.

- **ALB + Certificate Manager로 경로 전환** — `asia-northeast3`에서 도메인 매핑 생성이 `501 UNIMPLEMENTED: Creating domain mappings is not allowed in asia-northeast3`로 거절된다. **어제 「리전 지원 확인됨」이라고 적은 것은 오판**이었다 — 그때는 도메인 소유 확인 에러가 먼저 떠서 그 뒤의 리전 제약이 가려져 있었다. 글로벌 외부 ALB를 새로 구성했다(고정IP `lawwin-lb-ip` = **35.186.226.100**, serverless NEG → backend service → url-map → https-proxy + cert-map, 443 전달규칙, 80은 301 리다이렉트용 별도 프록시). 인증서 `lawwin-cert`는 `lawwin.co.kr` + `*.lawwin.co.kr`을 **DNS authorization** 방식으로 발급했다. 함정 하나 — `backend-services create`에 `--protocol=HTTPS`를 주면 gcloud가 portName을 자동 설정하는데 **서버리스 NEG는 portName을 받지 못해** `add-backend`가 실패한다(플래그를 빼야 한다). 결과적으로 이 경로가 더 나았다 — 도메인 매핑은 DNS가 Google을 먼저 가리켜야 발급이 시작돼 15분~24시간 HTTPS 오류 구간이 있지만, Certificate Manager는 **전환 전에 발급을 끝낼 수 있어 다운타임이 0**이 됐다. 비용은 전달규칙 + 고정IP 월 $20~25.
- **런타임 env가 컷오버의 실제 변경점이었다** — 코드 변경은 0건이 맞았다(canonical·sitemap·robots가 이미 `https://www.lawwin.co.kr` 하드코딩, `lib/host.ts`가 호스트 기준으로 noindex를 자동 해제). 그런데 프론트 Cloud Run의 `AUTH_URL`이 `https://lawwin-homepage-umde422lkq-du.a.run.app`으로 고정돼 있어 **NextAuth가 어드민 로그인 콜백을 run.app으로 만들고 세션이 엉뚱한 도메인에 붙을** 상태였다. `AUTH_URL=https://www.lawwin.co.kr`로 교체하고 Google OAuth 클라이언트에 `https://www.lawwin.co.kr/api/auth/callback/google`을 등록, `/api/auth/providers` 응답으로 callbackUrl 반영을 확인했다. 교훈은 **도메인이 바뀌는 작업에선 앱 코드보다 런타임 env의 절대 URL을 먼저 뒤져야 한다**는 것. 어제 미리 고쳐둔 백엔드 `CORS_ORIGIN`(`*.run.app`만 허용 → 도메인 전환 순간 브라우저→API 전부 CORS 차단될 상태)도 같은 종류의 문제였다.
- **컷오버 결과 검증** — `verify-cutover.sh` **15/15 PASS**(noindex 해제, HSTS, robots, 레거시 301 4건, 주요 페이지 200). 컷오버는 "가비아 닫기"가 아니라 A 레코드 2줄 교체이고, 가비아는 도메인 등록·DNS 존을 계속 가져야 하며 **레거시 IIS(139.150.69.177)도 끄면 안 된다** — bare 업로드 파일이 아직 가비아 원본을 참조한다(GCS 이관 Phase 2 미완). 존의 `CNAME crm`(CRM)·`CNAME case-manager`(사건관리)·`A *`·`A test`는 손대지 않았다.
- **런북에 실행 결과 반영** — 리전 제약과 8/5 판단이 오판이었음, ALB 실제 구축 순서, 가비아에 넣을 값을 고정 IP로 갱신, 소유 확인 완료 상태, TTL 최소값이 600초라 **롤백 소요를 5분 → 10분으로 정정**, 소유확인 TXT와 인증서 CNAME은 삭제 금지 항목으로 표시. (`docs/cutover-runbook.md`) (`6657ab9`)

### 2. 홈페이지 V2 — 지사별 URL 체계 정리

> 배경: 컷오버로 실서버가 되자마자 드러난 문제. 지역을 **쿠키로 기억**하는 구조가 `lawwin.co.kr` 진입 자체를 지사 화면으로 튕기고 있었다. 판정 기준을 URL로 단일화하면서, 그동안 쿠키가 가려주던 "지역 접두사가 새는 링크"가 전부 드러났다.

#### 2-1. 판정 기준 단일화

- **지역을 URL로만 판단하도록 변경** — 지역 URL 방문 시 1년짜리 `region` 쿠키를 심고, 접두사 없는 경로로 들어오면 쿠키의 지역으로 307 리다이렉트하고 있었다. 그래서 **한 번 지사 페이지를 본 방문자는 `lawwin.co.kr`로 들어와도 전국 기본판을 볼 수 없었다.** 쿠키 발급과 307을 제거하고 `useRegion`의 쿠키 폴백도 없애 **URL 첫 세그먼트로만** 현재 지역을 판정한다. 헤더 지점 드롭다운은 쿠키를 쓰지 않고 이동만 하며, 기존 방문자에 남은 쿠키는 응답마다 만나는 즉시 삭제한다. 지역 URL의 rewrite와 `x-region` 헤더 주입은 그대로 유지. (frontend `middleware.ts`·`region-provider.tsx`·`region-switcher.tsx`) (`e7d1134`)
- **접두사가 새던 링크 전수 수정** — 지사 페이지에서 링크를 누르면 지역이 풀려 전국판으로 빠지던 곳을 훑었다. 사례·후기 상세의 담당 변호사 링크, 목록으로 돌아가기, 뉴스 탭, 지식·후기 목록의 페이지 이동과 검색·분류, 메인 히어로의 상담 신청·해결 사례 버튼, 전문센터의 사례·칼럼 더보기와 상담 신청, 변호사 상세의 전체 사례·상담 신청·대표사례, 상담 게시판 본인확인 후 상세 이동, 상담폼의 게시판·처리방침 링크, **전 페이지 상단 경로표시(홈·상위 메뉴)** 까지 지역을 유지하게 했다. `/news`로 들어오면 지역이 사라진 채 미디어 탭으로 넘어가던 문제도 함께 잡았다. (30여 개 파일) (`1208006`)
- **푸터 사업자정보를 보고 있는 지사 값으로** — 지점을 바꿔도 푸터가 서울(본사)로 남았다. 원인은 지점 전환이 클라이언트 이동이라 **주소가 접두사 없는 경로로 재작성돼 머리말·꼬리말이 재사용**된 것 — 지점 전환을 전체 새로고침으로 바꿔 서버가 지역을 다시 읽게 했다. 상호와 사업자등록번호는 **분사무소마다 별도 등록된 표시사항**이므로 본사 값으로 대체하면 부정확한 표시가 된다(전국 기본판에서만 본사 값 사용). 푸터 정책 링크에도 현재 지역 접두사를 유지했다. (`154bb8f`)
