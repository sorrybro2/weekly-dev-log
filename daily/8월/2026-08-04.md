### 1. 사건관리 — 모바일 정렬 지원 (#240)

(frontend `common/data-table/MobileSortMenu.tsx`·`types.ts`) (`670956d`)
- **사건목록 정렬 상태를 페이지로 승격** — 정렬 상태가 `CaseListTable` 안에 갇혀 있어 헤더 없는 카드 리스트는 정렬을 쓸 수 없었다. 상태를 페이지로 올려 **표와 카드가 같은 값·같은 비교 함수**를 쓰게 했다. `SortState`·`cycleSort`·`NO_SORT`를 export(오름→내림→해제 순환 유지), `sortItems`도 export하고 `employees` 기본값을 `[]`로 둬 출석비고 컬럼이 없는 화면도 쓸 수 있게 했다. 카드 리스트는 **고른 정렬 기준이 있으면 당사자 병합보다 우선**한다 — 표와 같은 규칙. 같은 파일 범위라 분리할 수 없는 변경(샘플데이터 토글 주석 처리, 모바일 「모두 접기/펼치기」 숨김, 필터 바텀시트 등장 모션, 담당사건 트리 툴바 한 줄 유지)도 함께 들어갔다. ### 3. 사건관리 — 기간 조회 방식 일원화 (#243)

> 배경: 월 선택과 시작~종료 달력이 **동시에 떠 있어** 무엇이 지금 조회 기준인지 화면만 봐서는 알 수 없었다.

- **수발신 문서 기간 지정 토글** — 「기간 지정」 체크박스로 둘 중 하나만 보여준다. 핵심은 **모드가 켜져 있고 실제로 날짜가 들어왔을 때만** 기간으로 조회하는 것 — 모드만 켜고 비워두면 월 조회를 유지해 빈 기간으로 전체를 긁지 않는다. 끌 때는 넣어둔 날짜를 비워 월 조회로 확실히 되돌리고, `localStorage`에 `rangeMode`를 저장한다(예전 저장값에는 없으므로 날짜가 남아 있으면 기간 모드로 이어받음). 필터 초기화 판정(`hasActiveFilters`)에도 포함했다. (frontend `features/document-logs/*`) (`bf36d19`)
- **최근 진행내역 월 단위 조회** — 수발신 문서와 같은 방식으로 맞췄다. `monthRange()`로 'yyyy-MM' → 1일~말일을 만들고(달은 최대 31일이라 서버 제한 안에 들어온다), 월 입력이 비거나 깨지면 이번 달로 본다 — **빈 날짜로 서버를 때리지 않게**. 기간 모드를 켤 때는 지금 보고 있는 월 범위를 그대로 이어받고, 시작/종료 핸들러가 상대 날짜가 빈 상태에서 Date 비교로 들어가지 않도록 가드를 넣었다. (frontend `features/cases/*`) (`4f6896e`)

### 4. 사건관리 — 결재 흐름 사고 3건 (#233 / #237)

- **삭제된 문서로 결재요청이 나가던 문제** — 삭제 성공 시 체크 선택에서 빼지 않아 **유령 문서로 요청이 나갔다.** 삭제 시 선택 해제, 결재요청 실패 시 서버가 준 사유를 토스트에 그대로 노출, 404(이미 삭제됨)는 건너뛰고 선택 해제하되 **그 외 실패건은 남겨** 팝오버를 유지해 재시도할 수 있게 했다. (frontend `features/document-logs/components/DocumentApprovalPopover.tsx`·`DocumentLogListPage.tsx`) (`85690b1`)
- **결재자 스냅샷 불일치** — 문서에 저장된 `approver_key`는 **등록 시점 스냅샷**이라, 그 뒤 사건 주담당 변호사가 바뀌면 문서 상세에서는 옛 변호사로 결재요청이 나갔다. 목록 툴바의 결재요청 팝오버는 항상 자동 매핑을 쓰므로 **같은 문서인데 결재자가 서로 달랐다.** 아직 요청 전(미발송·보류)이면 자동 매핑값을 기본값으로 쓰고, 이미 요청이 나간 문서(대기·완료)는 실제로 요청이 간 결재자를 그대로 보여준다. 셀렉트로 직접 고른 값은 언제나 우선. (frontend `features/document-logs/components/DocumentLogDetailDrawer.tsx`) (`2a9a01c`)
- **수발신방법 드롭다운이 다시 열리지 않던 문제** — 한 번 고르면 값을 지우기 전에는 목록이 다시 뜨지 않아 방법을 바꿀 수 없었다. 원인 두 개 — 열기가 `onFocus`에만 걸려 **포커스가 남은 상태의 재클릭이 무시**됐고, 열려도 이미 고른 값으로 목록을 걸러 **그 항목 하나만 남았다.** 입력창 클릭을 `mousedown`에서 잡아 토글하고, 다시 열 때는 전체 목록을 보여주며 현재 값에 커서를 맞춘다. 입력값 필터는 직접 타이핑할 때만 적용(직접 입력 기능은 유지), 아래 화살표로도 열린다. (frontend `features/document-logs/components/pickers.tsx`) (`2dbad4b`)

### 5. 사건관리 — 안내 메일 제목 규칙 (#233)

- **제목 태그를 수발신방법 기준으로 변경** — 태그를 문서 구분(자료수령/자료송부)에서 **수발신방법(method)** 으로 바꾸고 당사자명을 덧붙였다. 문서명은 그대로 뒤에 오고, 문서명이 없을 때만 예전처럼 "수발신 문서"가 그 자리를 대신한다. 방법이 한 통 안에서 섞이거나 비면 예전 구분 태그로 폴백해 #219 규칙을 유지한다. 당사자 여럿은 「홍길동 외 1명」, 문서 여럿은 「양형자료 외 1건」. 당사자명은 체크박스로 뺄 수 있고(기본 포함) `include_party_name`으로 서버에 넘긴다. **프론트 미리보기와 백엔드 발송이 같은 규칙이어야 하므로 양쪽을 함께** 고쳤다. (backend `core/gmail.py`·`document_logs_api.py`, frontend `lib/mailFormat.ts`·`DocumentLogAddModal.tsx`) (`d1655c1`)

### 6. 사건관리 — 시스템 설정 라우트 분리 (#244)

- **4개 영역을 각각 페이지로** — 한 페이지에 네 영역을 쌓아두고 좌측 메뉴가 **앵커 스크롤만** 하던 구조를 라우트 분리로 바꿨다. `/admin/contract`·`/admin/record-requests`·`/admin/document-logs`·`/admin/organizations`를 신설하고 `/admin`은 첫 영역으로 리다이렉트해 **기존 북마크를 보존**했다. 설정 영역별 URL이 생겨 북마크·공유가 되고, 스크롤 위치로 활성 메뉴를 추적하던 로직(`scrollToSection`·IntersectionObserver·`activeId`·`goSection`·`navigate(state:{scrollTo})` 우회)이 전부 소멸했다. 설정 UI 본체는 그대로 재사용하고 제목·도움말만 붙이는 얇은 래퍼(`SettingsPages.tsx`)를 뒀다. 지사 관리는 화면 단에서도 super_admin을 차단했다. lg 미만에서는 앱 헤더에 이미 전역 햄버거가 있어 같은 모양을 또 두면 역할이 헷갈리므로, **지금 보고 있는 설정 이름을 트리거로 쓰는** 드롭다운으로 만들었다. (frontend `features/admin/*`·`AppLayout`) (`fcbba6a`)
- **모바일 설정 네비에서 섹션 이동 칩 제거** — 스크롤에 따라 하이라이트가 따라다니기만 하고, 모바일에선 그냥 아래로 스크롤하면 되는 자리 낭비였다. 다른 화면으로 가는 링크(계약 매핑·목표/달성율·감사 로그)는 남겼다 — 사이드바에는 `/admin` 하나뿐이라 여기가 유일한 통로다. (`801dbd0`)

### 7. 사건관리 — 모션·레이아웃 정리

- **드롭다운 등장 모션 공용 토큰** — 즉시 나타나던 커스텀 드롭다운·자동완성 패널이 딱딱하게 느껴졌다. 클래스 묶음을 `lib/motion.ts` 한 곳에 모아 **세기를 한 지점에서 조절**할 수 있게 하고 커스텀 패널 17곳에 적용했다. `dropdownMotion`(origin-top + fade/zoom/slide, 150ms ease-out), `sheetMotion`·`backdropMotion`(모바일 바텀시트, 200ms). shadcn Popover/DropdownMenu 래퍼도 duration-100 → 150 ease-out으로 통일해 같은 래퍼를 쓰는 팝오버·컬럼설정·모바일 정렬 메뉴가 함께 반영된다. `prefers-reduced-motion` 사용자에게는 모션을 끈다. 조건부 렌더라 **등장에만** 걸리고 사라질 때는 즉시 닫혀 반응이 빠르게 느껴진다. (`1956fa5`)
- **죽은 '제목 비고' 입력란 제거**(#236) — #221에서 캘린더 제목을 직접 편집하게 바뀌면서 수정 모드는 저장된 `calendar_title`로 `titleOverride`가 채워진 채 시작한다. 그래서 한 번이라도 저장된 일정은 '제목 비고'를 고쳐도 `autoTitle`만 다시 계산될 뿐 **제목에 반영되지 않아 입력란이 사실상 죽어 있었다.** 입력란과 `memoRef`만 제거하고 memo 값 자체는 폼 상태·payload에 남겨 기존 값과 백엔드 fallback을 보존했다. (frontend `features/cases/components/CaseScheduleModal.tsx`) (`13f4649`)
- **결재함 탭 제목·카운트 정리** — 제목이 줄바꿈되며 옆 카운트와 섞여 읽히지 않았다. 좁은 화면에서는 제목을 한 줄(`whitespace-nowrap`)로 두고 카운트를 아래 줄로 내린다. (`37b3e3c`)
- **지사 칩 라벨 정렬** — 칩을 별도 컨테이너로 감싸고 있어 좁은 화면에서 칩이 여러 줄로 접히면 「지사」 라벨이 `items-center`로 **가운데 줄에 떠 보였다.** 수발신 문서와 동일하게 라벨과 칩을 한 `flex-wrap`에 같이 뒀다. (frontend `features/record-requests/*`) (`9101237`)

**금일 종합:** 베타테스트 이틀째, 실사용자가 **폰으로** 쓰기 시작하면서 드러난 문제를 집중적으로 걷어낸 날이다. 가장 컸던 건 카드 모드의 정렬 부재 — 정렬 로직은 이미 있었는데 **고를 UI가 없어서** 기능이 없는 것과 같았다. 정렬 상태를 페이지로 올려 표와 카드가 같은 함수를 쓰게 한 것이 이 날의 구조적 개선이다. 조회 UI에서는 "무엇이 지금 기준인지" 화면으로 알 수 없던 월/기간 이중 상태를 토글로 갈랐고, 빈 기간으로 전체를 긁지 않게 방어했다. 결재 쪽은 눈에 안 보이던 사고 두 건이 실질적이다 — 삭제된 문서로 요청이 나가던 것, 주담당이 바뀐 뒤에도 **등록 시점 결재자**로 요청이 가서 같은 문서의 결재자가 화면마다 다르던 것. 마지막으로 시스템 설정을 앵커 스크롤에서 라우트로 분리해 URL·북마크가 생기고 스크롤 추적 로직이 통째로 사라졌다. 금일 1개 repo에 걸쳐 커밋 20건.
