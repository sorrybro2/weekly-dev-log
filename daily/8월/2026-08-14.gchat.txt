📋 *일일 업무 보고 (2026. 08. 14)*

홈페이지 메인을 한 화면씩 넘기는 다섯 장면 장표로 전면 재구성하고, 히어로 로고를 Blender와 three.js로 실물 3D로 세웠습니다. 사건앱과 CRM 양쪽의 상담 예약금 입금여부 표기도 하나로 맞췄습니다. 금일 커밋 15건 (홈페이지 V2, 사건관리 앱, CRM), 이슈 신규 7건

🌐 *〔홈페이지 메인 장표 전환 (이슈 112번)〕*

•  *메인을 다섯 장면으로 재구성* — 레거시가 쓰던 fullPage.js와 GSAP 조합을 라이브러리 없이 재이식. 휠:키보드:터치로 한 화면씩 넘기고 떠난 장은 되감겼다가 돌아오면 처음부터 재생 (5c8fddb)
•  *적용 범위* — 가로 방향이면서 세로 여유가 있는 화면에서만 켜고 그 밖에서는 평범한 세로 스크롤 유지
•  *사례 탭과 지식센터 탭을 분야 판 하나로 통합* — 분야를 고르면 그 분야의 실제 수행 사례와 지식센터 글이 함께 노출. 분야별로 직접 조회해 최근글에 안 걸린 분야가 빈칸이 되던 구멍 제거
•  *선행 이슈 88번과 106번 종결* — 요청이 전부 구현돼 닫고 후속 112번으로 이어받음

🎨 *〔실물 확인 피드백 반영〕*

•  *너무 빨라 정신없다* — 장 넘김을 500ms에서 1000ms로 늦춤. 다만 시간을 2000ms까지 올려도 체감이 안 바뀌었고, 원인은 시간이 아니라 이징 곡선이었음. 초반에 거리의 8할을 몰아 가는 곡선을 시작과 끝이 모두 눌린 것으로 교체하니 1초로 되돌려도 차분해짐 (689667c)
•  *배경이 극한이라 멀미난다* — 판 순서가 순백에서 진홍, 순흑으로 이어져 명도가 0과 100을 오감. 흰 판과 검은 판 양 끝만 한 단계씩 안으로 당기고 붉은 판은 브랜드 면이라 유지
•  *분야 칸 구분이 안 된다* — 격자선 불투명도를 두 배로 올리고 안 고른 칸에 면을 깔아 누를 수 있는 상자로 읽히게 함
•  *장표 경계값 버그* — 기준이 세로 700px이라 정작 배제하려던 태블릿 가로 768이 그대로 통과해 한 장이 704px로 눌리고 있었음. 800px로 교정

🧩 *〔히어로 법승 마크 3D (이슈 113번)〕*

•  *Blender로 GLB 제작* — 로고 SVG가 path 2개뿐이라 압출이 정석. Gemini로 스크립트 초안을 받아 정리한 뒤 Blender에서 실행해 추출 (bc720ca, 639e582)
•  *한 번 말아먹은 지점* — Blender SVG 임포트가 0.001 스케일이라, 100배 확대를 데이터에 굽기 전에 두께를 넣으면 폭의 3배 두께가 되어 알약 모양이 나옴. 임포트에서 확대, 적용, 두께 순서로 고정
•  *three.js 적용* — 히어로가 LCP 요소라 기존 CSS 압출판을 먼저 그리고 준비되면 WebGL판으로 크로스페이드 교체. 두 구현이 정지 각도 상수를 공유해 교체 순간 마크가 튀지 않게 함
•  *AI 3D 생성 도구는 불채택* — 회전 시 마크가 얇은 막대로 붕괴하고 형태가 실제 로고와 달라 레퍼런스로만 사용
•  *3D 확인용 캡처 도구* — 3D는 값을 바꿔도 코드로 결과를 볼 수 없어, dev 서버 화면을 직접 찍는 스크립트를 만들어 사람에게 캡처를 요청하는 왕복 제거 (270dc49)

🚀 *〔홈페이지 개발환경 안정화〕*

•  *dev 서버가 반복적으로 죽던 원인* — 메인이 계속 500을 뱉었는데, 다른 세션에서 돌던 빌드가 dev 서버와 같은 출력 폴더를 통째로 비우고 있었음. 출력 폴더를 분리해 근본 제거 (994d0f5)
•  *유튜브 빈 화면* — 홈 보도 칸이 가끔 게시물 없음으로 비었음. API 키가 설정된 적이 없어 항상 RSS 폴백만 탔고, 그 RSS가 실측 6회 중 5회 404. 게다가 실패 응답만 캐시되고 성공은 저장이 안 되는 구조였음. 마지막 성공분을 보관해 실패 시 대신 노출 (6adde6b)

🗂 *〔사건관리 앱〕*

•  *기록신청 상태 오조작 차단* — 드롭다운을 고르는 즉시 저장돼 엉뚱한 사건의 상태를 바꾸기 쉬웠음. 사건:의뢰인:관할:신청일을 보여주는 확인창을 거치게 함 (이슈 336번, 43ca773)
•  *법원사건진행내역 날짜 잔류* — 필터를 바꿔도 이전 날짜 선택이 남아 엉뚱한 날이 다시 잡히던 문제. 선택을 필터 조합 지문과 함께 저장해 지문이 다르면 선택 없음으로 처리 (이슈 335번, 9241383)
•  *사이드패널과 드로어 ESC 닫기* — 공용 훅 신설. 중첩 시 맨 위 하나만 닫고, 수정 중이면 ESC를 그 자리에서 삼켜 아래 패널이 닫히지 않게 함. 6개 화면 적용 (이슈 331번, e572d63)
•  *사건목록 병합 셀 기일충돌 배경* — 충돌이 그룹의 2번째 이후 행에 걸리면 병합 셀이 안 칠해지던 문제 (20df54c)

💰 *〔상담 예약금 입금여부 표기 통일 (사건앱 + CRM)〕*

•  *캘린더 제목에 입금여부 명시* — 금액만 먼저 적어두는 경우가 많아 실제로 받은 돈인지 구분되지 않았음. 예약금과 상담료 모두 입금여부를 항상 표기 (이슈 320번, e9f528e)
•  *입금여부 출처는 사건앱* — 상담료 입력창에서 직원이 직접 고르는 값이라 가장 최신. 예약금 금액만 종전대로 CRM 값 사용
•  *CRM 입력 UI 교체* — 미입금 체크박스를 입금완료:미입금 스위치로 바꾸고 항목명을 통일 (aca3767)
•  *스위치 노출 조건 수정* — 금액이 비어 있으면 스위치가 숨겨져 입금 상태를 못 정하던 문제. 입금완료는 회색으로 낮추고 미입금만 빨간색으로 남김 (7c7ca8b)

✅ *〔금일 종합〕*

홈페이지 메인 랜딩이 가장 큰 축이었습니다. 장표로 재구성한 뒤 실물로 굴려보고 나온 지적을 되짚는 과정에서, 전환 속도는 시간을 4배로 늘려도 체감이 안 바뀌고 원인이 이징 곡선이었다는 것을 확인한 게 컸습니다. 히어로 로고는 AI 3D 생성을 검토했다가 형태 붕괴 문제로 접고 Blender로 직접 뽑아 three.js로 세웠습니다. 사건앱과 CRM 쪽은 상담 예약금 입금여부를 양쪽에서 맞추는 작업과 실사용 마찰 제거가 중심이었습니다. 금일 3개 repo에 걸쳐 커밋 15건
