# 진솔 | 풀스택 개발자

사내 업무 시스템과 고객 접수 서비스를 개발하고 운영합니다. 구글시트 업무를 CRM으로 옮기고, 레거시와 연동하는 신규 홈페이지·CMS를 구축했습니다. 화면·API 구현부터 데이터 이관, 외부 연동, 배포와 장애 대응까지 담당합니다.

법무법인 법승에서 CRM·홈페이지 V2·사내 포털을 단독 개발하며, 사건관리 앱은 2인 팀에서 상담·문서·전자결재·정산 도메인과 배포를 담당합니다. 이전에는 웹 유지보수와 운영 시스템 분석을 수행했습니다.

## 사내 CRM | 업무 전환과 외부 서비스 연동

**기간:** 2026.01 ~ 운영 중 / 정식 오픈 2026.05  
**구성:** Flutter(PWA·Android), Express, PostgreSQL, Google Workspace API, NCP SENS  
**담당:** 화면·API·데이터 구조·이관·배포를 단독 개발

지사별 고객 유입·변호사 배정·상담 예약·문자 안내를 연결하는 CRM입니다. 구글시트와 신규 시스템이 공존하도록 연동 구조를 만들고, Google Sheets → MySQL → PostgreSQL로 저장소를 전환했습니다.

- **데이터 이관:** 당사자·상담·문자 및 전화 기록 약 **9.8만 건**을 초기 적재하고, Apps Script 트리거와 웹훅으로 시트·DB 동기화를 구현했습니다. 초기 적재부터 PostgreSQL 전환까지 직접 수행했습니다.
- **상담 일정:** 다중 상담사 선택과 종료시간 입력을 지원하고 상담 등록·수정·삭제를 Google Calendar에 반영했습니다. 상담 시트와 DB를 연결해 기존 시트 사용 단계에서도 변경 내용을 교환하도록 구성했습니다.
- **동시 접수 처리:** 처리자가 접수 건을 점유하고, 미조작 시 자동 회수하는 흐름을 구현했습니다. 다른 직원에게 처리 중 상태를 표시해 중복 처리를 제한했습니다.
- **외부 연동·발송:** Google Calendar·Admin Directory·People API로 상담 일정·계정·연락처를 동기화하고 직원 연결을 이름에서 고유키로 전환했습니다. 바이트 기준 SMS·LMS·MMS 판정과 예약·템플릿 발송, Flutter Google 로그인·문서 출력을 구현했습니다.
- **입력 중단과 복구:** 상담·당사자·문자 입력을 사용자별로 임시저장하고, 화면을 다시 열면 복원 여부를 선택하도록 했습니다. 저장 성공 후에는 초안을 지우고, 세션 만료로 로그인하면 작업하던 화면으로 돌아오도록 처리했습니다.

## 홈페이지 V2 | 신규 사이트·CMS 구축과 레거시 연동

**기간:** 2026.05 ~ 진행 중  
**구성:** Next.js App Router, NestJS, Prisma, PostgreSQL, Turborepo, Cloud Run·Cloud Build·GCS  
**담당:** 공개 사이트·운영 CMS·API·이관·배포를 단독 개발

ASP.NET·SQL Server 홈페이지를 기반으로 신규 공개 사이트·CMS를 구축했습니다. 주 도메인 전환 후 운영 판단에 따른 롤백을 수행했으며, 현재 레거시·V2 병행 조건에서 데이터 동기화와 콘텐츠·상담 운영을 담당합니다.

- **편집과 저장:** 콘텐츠 유형별 폼, 공용·개인 템플릿, 자동 목차, 이미지·PDF 첨부를 구현했습니다. 저장 요청이 실패해도 작성 내용을 유지하고 오류 사유를 안내했습니다. 편집기와 공개 화면의 정렬·링크 표현을 맞췄습니다.
- **발행 상태:** 미래 예약과 과거 소급 등록을 구분하고 기존 글의 작성일을 유지하도록 처리했습니다. 운영자가 예약·공개·숨김 상태를 관리하는 화면과 공개 사이트의 노출 조건을 연결했습니다.
- **지사·센터별 운영 설정:** GTM 스니펫을 통째로 입력하는 방식 대신 검증한 컨테이너 ID를 저장하고 코드가 스니펫을 생성하도록 했습니다. 원래 지역 경로로 컨테이너를 결정하고, 화면 DOM에 의존하던 전환 신호를 `dataLayer` 이벤트로 정리했습니다.
- **레거시 병행 동기화:** SQL Server에서 PostgreSQL로 데이터를 이관하고, 운영 단계에는 레거시에서 신규 백엔드 HTTPS API로 변경 내용을 전달하도록 구성했습니다. 양쪽이 자체 번호를 발급하는 조건에서 원본 키·접수 고유키로 대조하고, 기존 예약 글의 공개 상태 변경도 재반영했습니다.
- **반응형 화면:** 어드민 목록을 화면 폭에 따라 카드·표로 전환하고 터치 영역과 저장 바를 정리했습니다. 공개 사이트의 지역 전화 버튼은 보고 있는 지사로 연결되도록 서버 헤더와 클라이언트 동작을 분리했습니다.
- **검색과 기존 주소 유지:** 레거시 상세 주소를 301 이전하고 사이트맵을 동적으로 통합했습니다. 구조화 데이터를 적용하고 콘텐츠 변경을 IndexNow와 사이트맵 수정일에 반영했습니다.
- **접근 제어:** 상담 내용 마스킹, 보안 헤더, 접수 빈도 제한, reCAPTCHA 실패 시 차단을 구현하고 어드민 Google 로그인을 일원화했습니다.
- **배포와 전환:** 프런트·백엔드 컨테이너와 빌드 파이프라인, 로드밸런서·인증서를 구성했습니다. 도메인 전환·롤백과 상담 데이터의 양쪽 반영을 처리하고, 프런트·백엔드 계약이 함께 바뀌는 변경의 배포 순서를 명시했습니다.

### RAG 상담봇 | 직원 대상 시범 운영

Vertex AI·pgvector 검색·생성 모듈을 구현했습니다. 외부 공개 후 운영 요건을 보강하며 직원 전용으로 전환했고, 현재 직원 대상 시범 운영 중입니다.

- 사이트 문서 **4,398건**을 **7,786개 조각**으로 색인하고 의미 검색과 글자 검색을 RRF로 결합했습니다. 실제 상담을 바탕으로 평가 문항을 구성해 검색 품질과 답변을 거부해야 할 질문을 점검했습니다.
- 생성 모델이 없는 연락처·지사를 만들던 사례를 확인해 연락처는 검증된 값을 코드에서 붙이고 실제 지사 정보를 모델에 주입했습니다. 스트리밍 누적문과 완료 후 연락처 검사를 구분하고 실패 문장을 회귀 테스트에 반영했습니다.
- 개인정보 동의·보관기간·파기를 구현하고, 내린 글은 질의 시 원본 공개 상태를 확인해 인용 대상에서 제외했습니다. 변경된 조각만 다시 색인하는 정기 갱신을 구성했습니다.

## 사건관리 앱 | 2인 팀의 담당 도메인과 전자결재

**기간:** 2026.06 ~ 진행 중 / 일부 지사 베타 운영  
**구성:** React·TypeScript·Vite, TanStack Query·Table, FastAPI, SQLAlchemy, PostgreSQL, Cloud Run  
**담당:** 상담·문서대장·전자결재·정산 도메인, 공통 화면, 인프라·배포

법률 실무를 연결하는 사내 도구를 2인 팀에서 개발하며 다음 업무를 담당했습니다.

- **상담료 처리 화면:** 처리 대기 목록에서 항목을 선택하면 상담 정보가 입력 폼에 반영되도록 구성했습니다. 상태 필터와 목록·입력 영역을 연결해 조회한 내용을 다시 입력하는 단계를 줄였습니다.
- **공통 UI와 상태 설계:** 공통 DataTable로 목록을 통합하고 컬럼 폭·순서·표시를 저장했습니다. 페이지에서 정렬 상태를 관리해 데스크톱 표·모바일 카드가 같은 값과 비교 함수를 사용하도록 구성했습니다.
- **감사로그·변경 전파:** SQLAlchemy 세션 훅으로 변경 내역을 수집하고 업무 데이터와 감사로그를 같은 트랜잭션에 기록했습니다. PostgreSQL `LISTEN/NOTIFY`와 SSE를 연결하고 브라우저에서 관련 쿼리 캐시를 갱신해 화면 변경을 전달했습니다.
- **전자결재 업무 흐름:** 기안·결재 요청·알림 발송을 분리하고, 메일은 안내에 사용하며 승인·반려는 앱에서 처리하도록 정리했습니다. 대기·완료·기안함을 URL 탭과 연결하고, 문서 처리 후 남은 업무로 이어지는 동선을 구성했습니다. 결재 상태는 Google Drive 라벨에도 반영했습니다.
- **업무 기록:** 수발신 문서와 열람등사 화면을 구현하고, 공휴일을 고려한 기한 알림을 구성했습니다. 회계 데이터의 차이를 읽기 전용으로 대조해 중복과 동기화 방향 문제를 확인했습니다.
- **배포 장애 대응:** 다른 이미지가 배포되어 API가 HTML을 반환한 원인을 분석했습니다. Dockerfile 명시 → 빌드 → 이미지 배포 → 본문·Content-Type 확인 절차를 정리하고 다른 시스템에도 적용했습니다.

## 사내 포털 | 구성원 입사·변경·퇴직과 조직도 편집

**기간:** 2026.08 ~ 운영 중  
**구성:** Next.js, Auth.js, React Flow, GCS, Google Workspace API, Cloud Run·Firebase Hosting  
**담당:** 화면·API·인증·저장 구조·배포를 단독 개발

Google Sites의 PDF 조직도와 별도 크롬 익스텐션에 나뉘어 있던 구성원 조회·계정 관리를 포털로 모았습니다. 일반 직원에게는 연락처와 일정·내선 통화를, 정보실에는 조직도 편집과 계정 관리를 제공합니다.

### 데이터별 원본과 저장 방식

| 데이터 | 원본과 처리 |
| --- | --- |
| 이름·직위 | CRM 연동 정보를 사원키로 연결해 표시하고, 변경 직후에는 Google 저장값 반영 |
| 조직도 배치·순서·배지 | 포털의 GCS JSON 버전 파일. 변경을 초안으로 모아 확인 후 저장 |
| 계정·소속·지사별 내선 | Google Admin에 반영. 화면에서 조직도 배치 저장과 구분 |

- **입사와 변경:** 구성원 추가·수정·정지 화면을 구현했습니다. 계정 생성 시 고유 사원키를 연결하고 임시 비밀번호를 표시하며, 소속·지사·직무 같은 맞춤속성은 구글 스키마 정의에 맞춰 검증합니다.
- **퇴직 예약:** 고용상태의 퇴직 전환과 계정 정지를 구분해 예약하도록 했습니다. 포털 요청 시 기한이 지난 작업을 처리하고, 실패 내역을 남겨 재시도하는 구조입니다.
- **조직도 편집:** 사람·조직을 선택하면 편집 패널이 열리고 배치·순서를 조정합니다. 배치 변경은 초안으로 모으고, 계정·조직 정보 변경은 저장 대상과 적용 시점을 안내합니다. 캘린더·사건 폴더 관련 값을 바꾸면 다른 앱에 미치는 영향을 확인창에 표시합니다.
- **권한과 충돌:** 쓰기 요청마다 정보실 재직 여부를 판정하고 원본 권한 정보를 읽지 못하면 차단합니다. 저장 시 GCS 세대 번호가 바뀌었으면 충돌로 거절해 다른 관리자의 수정 내용을 덮어쓰지 않도록 했습니다.
- **후속 반영:** 구성원 변경 후 화면 데이터를 갱신하고 수신 알림 번호표 작업을 다시 실행합니다. 일반 직원은 조직도의 같은 사람 칸에서 연락처·내선 통화·구글챗·이메일을 이용합니다.
- **인증과 실행 경로:** Firebase Hosting의 쿠키 처리 차이를 재현해 비공개 GCS 스냅샷 로그인 브리지를 구성했습니다. 서버 공통 값과 사용자별 일정 데이터를 나누고, 명부와 일정 영역을 분리해 불러옵니다.

## 레거시 홈페이지 | 유지보수 내재화와 운영 전환 대응

**기간:** 2026.01 ~ 진행 중  
**구성:** ASP.NET Core·CSHTML, JavaScript·CSS, SQL Server, Windows Server·IIS  
**담당:** 화면·백엔드 유지보수, 소스 이관, 배포·장애 분석, DNS·데이터 연동

- 외주 소스를 사내로 이관하고 WEB·BLL·DAL 구조와 빌드·업로드 절차를 문서화했습니다. 반응형 화면 오류, 검색용 URL과 목록 복귀 상태를 수정하고 외부 콘텐츠 업로드 API를 구현했습니다.
- 접속 오류를 IIS·호스팅 번들·DB 설정 등 계층별로 분석하고, FileZilla 업로드와 배포 확인 절차를 정리했습니다.
- DNS 전환·롤백 시 레거시 HTTPS 응답과 인증서, DNS 반영 상태를 확인했습니다. 롤백 이후 V2에만 남은 상담을 시간대와 번호 충돌을 처리하며 레거시 DB에 반영했습니다.
