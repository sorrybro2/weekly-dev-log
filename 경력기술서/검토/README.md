포털·홈페이지 CMS·Flutter CRM·사건관리의 실제 프런트엔드 컴포넌트를 작업용 소스에서 실행해 부분 캡처했습니다. 인증과 API 데이터는 샘플로 대체했으며, 구현한 내용과 로컬에서 확인한 동작을 구분했습니다. 포트폴리오는 화면·업무 흐름·처리 조건을 연결하고, 경력기술서는 프로젝트별 담당 범위와 구현 설명에 핵심 UI 부분을 삽화로 넣었습니다. HTML에서 캡처를 누르면 크게 볼 수 있습니다.

캡처본 편집 소스는 `../../portfolio/capture-content.json`, `민간풀스택_경력기술서_로컬캡처본.md`입니다. 서식은 `../../scripts/capture-print.css`, 출력 명령은 `node scripts/render-capture-portfolio.cjs`입니다. 이미지·폰트를 내장해 서버 없이 열 수 있고, `캡처미리보기/`에는 PDF 페이지별 이미지·추출 텍스트·검사 결과가 저장됩니다.

[캡처 설명](../../assets/portfolio/local-captures/README.md)과 `캡처근거/*.json`에 실행 소스 버전·샘플 대체 범위·확인 결과를 남겼습니다. 원본 회사 저장소에는 캡처용 변경을 넣지 않았습니다.

## 편집할 원본

- 포트폴리오 내용: `../../portfolio/review-fullstack.json`
- 경력기술서: `민간풀스택_경력기술서_개선본.md`
- 평가 보고서: `포트폴리오_경력기술서_평가_2026-10-12.md`

경력 Markdown의 `<!-- page-break -->`와 평가 Markdown의 `<div class="page-break"></div>`는 페이지 경계를 지정합니다. 프로젝트 수치의 출처는 기존 `../../portfolio/프로젝트_지표.md`를 유지합니다. 새 프로젝트 실측은 수행하지 않았습니다.

## 출력과 확인

저장소 루트에서 `node scripts/render-fullstack-review.cjs`를 실행합니다. marked 12.0.2, Playwright, PDF.js 3.11.174를 사용합니다. 기존 설치는 `MARKED_MODULE`, `PLAYWRIGHT_MODULE`, `PDFJS_MODULE`로 지정할 수 있습니다. 이번 작업에서 사용한 모듈은 사용자 임시 폴더의 `fullstack-review-tools/node_modules`에 설치했으며 렌더러가 해당 위치를 대체 경로로 사용합니다.

HTML에는 한글 폰트와 프로필 사진을 내장합니다. 지원용 개선본에는 기존 외부 출력의 익명화 규칙을 적용합니다. 렌더링 중 원격 요청을 차단하고, 인쇄 너비에서 포트폴리오 페이지 넘침과 모바일 화면 가로 넘침을 검사합니다. `미리보기/`에 PDF 페이지 이미지와 추출 텍스트, 결과 문서 목록을 저장합니다.

대표 사례는 일일·주간 업무 기록의 구현 파일과 운영 상태를 직접 확인해 선정했습니다. 포털의 계정·권한·조직도 저장·퇴직 예약에 대해서는 일부 회사 소스를 대조했습니다. 실서비스 조작이나 전체 코드·운영 로그 감사는 수행하지 않았습니다. 선정 근거와 날짜별 링크는 평가 보고서 마지막에 있습니다. 이전 직장 프로젝트의 세부 기간, 업무 시나리오별 확인 결과와 실제 협업 근거는 추가 확인해야 합니다.
