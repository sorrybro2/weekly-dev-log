## Q1. 높은 목표를 달성하기 위하여 다각도로 노력했던 경험 (659자 / 700)

```text
[업무의 연속성까지 책임진 CRM 전환]
입사 후 전국 지사가 구글시트로 관리하던 고객 접수, 상담 예약, 문자 기록을 사내 CRM으로 옮기는 일을 맡았습니다. 저는 기존 고객 기록과 예약 흐름을 유지하면서 현업이 새 시스템으로 전환하는 것을 목표로 정했습니다. 상담 접수는 개발이 끝날 때까지 기다릴 수 없었고, 혼자 개발과 운영을 맡아 데이터 이관부터 실제 사용 중의 문제까지 해결해야 했습니다.
목표를 데이터, 조회 성능, 동시 처리로 나눠 접근했습니다. 약 9만 8천 건을 이관하고 Apps Script 트리거와 웹훅으로 시트와 DB를 양방향 동기화해 과도기에도 기존 업무를 이어가게 했습니다. 목록이 무한 로딩되자 반복 서브쿼리를 JOIN으로 통합하고 복합 인덱스를 적용했습니다. 서버가 여러 인스턴스로 확장되면서 자동 작업이 중복 실행되는 문제는 DB 잠금으로 해결했습니다. 직원들이 같은 접수 건을 덮어쓰는 문제에는 점유 상태와 만료 처리를 도입해, 담당자가 자리를 비워도 다른 직원이 이어서 처리하게 했습니다.
그 결과 5월 정식 오픈 이후 전국 지사가 CRM으로 업무를 처리하고 있습니다. 기능 완성을 넘어 기존 데이터와 사용자의 업무 흐름까지 책임진 경험으로, 높은 목표를 달성하려면 전환 과정에서 발생할 문제를 여러 관점에서 해결해야 한다는 것을 배웠습니다.
```

## Q2. 현재에 안주하지 않고 기존과 다른 방식을 자발적으로 시도하여 문제를 해결한 경험 (676자 / 700)

```text
[성공 표시를 넘어 데이터 흐름을 바꾸다]
레거시 홈페이지의 게시물과 상담을 신규 홈페이지로 옮기는 배치는 매일 성공으로 표시됐습니다. 그러나 양쪽 데이터를 직접 대조하니 누락이 있었습니다. 로그를 확인해 실패한 배치가 성공 종료코드를 남기는 문제와 아예 실행되지 않은 구간을 찾았습니다.
기존 방식은 사무실 PC가 두 DB에 접속해 데이터를 옮겨, 외부 접속 허용 설정이 바뀌면 멈추는 구조였습니다. 접속 설정을 복구하는 데 그치지 않고 이 의존성을 없애려 했습니다. 고정 IP를 갖춘 클라우드 작업도 검토했지만, 기존 자원으로 운영할 수 있는 방식을 택했습니다. 레거시 쪽에서 데이터를 추출해 신규 백엔드의 HTTPS API로 보내고, 백엔드가 DB에 저장하도록 흐름을 바꿨습니다. DB를 외부에 직접 개방할 필요를 줄이고 API에는 인증과 요청 제한을 적용했습니다.
복구 중에는 두 시스템이 같은 상담 번호를 서로 다른 접수에 발급한 것도 발견했습니다. 접수 고유키로 대조하고 저장 시 새 번호를 발급하도록 바꿔 상담 305건과 게시물 61건을 복구했습니다. 재실행해도 중복 저장되지 않는지 확인하고, 실패 알림 외에 일정 시간 실행 기록이 없을 때 알리는 감시를 다른 기계에 두었습니다.
누락을 복구하는 데서 끝내지 않고, 연동 구조와 감시 방식까지 바꿔 같은 문제가 조용히 반복되지 않도록 했습니다.
```

## Q3. 본인에게 낯설었던 것 혹은 다양한 것을 마주하고 포용했던 경험 (668자 / 700)

```text
[낯선 전문성을 서비스 설계에 담다]
법무법인에 개발자로 입사해 홈페이지와 상담봇을 만들며, 기능뿐 아니라 표현과 공개 방식도 중요함을 배웠습니다. 법률 광고 규정은 낯선 분야였고, 기술적으로 가능한 기능이 곧바로 공개 가능한 서비스는 아니었습니다.
먼저 개정 규정과 소스, 게시물을 대조했습니다. '무료 상담' 표기는 제거하고 상담봇에서도 같은 표현을 막았습니다. 다만 의뢰인 사연 속 '무료 다운로드'까지 차단하지 않도록 문맥을 구분했습니다. 반면 사례 제목의 감면 비율이나 사무소 호칭처럼 해석이 필요한 사항은 일괄 수정하지 않고, 근거와 확인 질문을 정리해 광고책임변호사에게 판단을 요청했습니다.
어려웠던 점은 규정을 읽어도 적용 범위를 혼동할 수 있다는 것이었습니다. AI 관련 내용을 다시 확인하며 상위 규칙과 세부 규정의 적용 대상이 다르다는 점을 발견했습니다. 이에 사례 요약과 방문자가 직접 사용하는 상담봇을 같은 기준으로 다루지 않았습니다. 실제 검토한 변호사만 표시하도록 화면을 바꾸고, 상담봇은 외부 재공개 전에 변호사 판단을 받도록 조건을 추가했습니다.
그 결과 명확한 수정 사항은 서비스에 반영하고, 해석이 필요한 사항은 전문가가 판단할 수 있도록 구분했습니다. 낯선 분야에서는 전문가가 확인할 근거를 마련하고 그 분야의 기준을 설계에 담는 태도가 필요함을 배웠습니다.
```

## Q4. 업무 혹은 일상에서 AI를 활용하여 문제를 해결하거나 생산성을 향상시킨 경험 (686자 / 700)

```text
[LLM의 생성과 검증을 연결해 반복 작업을 자동화하다]
홈페이지의 공개 사례 3,358건에 요약과 FAQ를 붙여 독자가 사건의 핵심을 쉽게 파악하도록 하고 싶었습니다. 사람이 일일이 작성하기에는 양이 많았고, AI에 그대로 맡기면 원문에 없는 수치나 결과를 단정하는 표현이 생길 수 있었습니다.
기존 백엔드의 Vertex AI 연동을 재사용할 수 있는 Gemini를 선택했습니다. 소량 생성으로 토큰 사용량과 예상 비용을 확인한 뒤, 조회수 높은 사례부터 순차 처리하는 파이프라인을 만들었습니다. 입력은 해당 글의 공개 본문으로 제한하고 응답은 정해진 JSON 형식으로 받아 저장과 검사를 자동화했습니다.
생성 결과는 원문과 대조해 없는 숫자, 결과 보장 표현, 사건 범위를 벗어난 일반론이 포함되면 비공개로 분류했습니다. 처음에는 혈중알코올농도의 퍼센트 표기까지 과장 비율로 오인했습니다. 측정값과 홍보 표현의 문맥을 구분하도록 검사 규칙을 수정해 오탐을 줄였습니다. 생성 결과를 원본과 별도 테이블에 저장해 기존 데이터 동기화와 충돌하지 않도록 했습니다.
그 결과 하루 만에 3,038건의 요약과 FAQ를 공개했고, 검사에 걸린 303건은 비공개로 남겼습니다. 이후 원문이 바뀌면 재생성과 재검사를 수행하도록 연결했습니다. 반복 작성 작업을 자동화하면서도 결과를 검증하고 최신 상태로 유지하는 운영 과정까지 마련했습니다.
```

## Q5. 지원 직군에 필요한 역량을 향상시키기 위해 노력했던 경험 (1107자 / 1,200)

```text
[검색 품질을 측정하는 RAG 개발 역량]
LLM 답변의 신뢰도를 높이기 위해 관련 근거를 제대로 찾는 검색 역량을 키우고자 했습니다. 법률 상담봇을 개발하며 청킹·임베딩·pgvector 검색을 익히고, 의미 검색과 키워드 검색의 장단점을 실제 질문으로 비교했습니다. 실제 상담 내용을 바탕으로 개인정보를 제거한 골든셋 50문항을 구성해 검색 결과를 평가했습니다. 의미 검색은 사건번호에, 키워드 검색은 동의어에 약한 점을 보완하도록 두 검색의 순위를 결합해 Recall@5 95.8%를 기록했습니다. 답하지 않아야 하는 질문도 평가에 넣고, 검색 성능과 답변 품질을 구분했습니다. 현재 직원 대상 시범 운영을 통해 AI를 서비스에 연결하고 검증하는 역량을 쌓고 있습니다.

[Python과 SQL로 조회 병목을 해결한 경험]
2인 팀의 사건관리 앱에서 제가 맡은 상담료 처리 대기 조회가 8초씩 걸렸습니다. Python의 FastAPI·SQLAlchemy 코드와 SQL의 데이터 조회 경로를 추적했습니다. postgres_fdw를 익히며 CRM 데이터가 같은 DB의 일반 테이블이 아닌 원격 테이블임을 확인했습니다. 원격에 전달되지 않는 인라인 조인 때문에 필요한 데이터보다 많은 행을 가져와 다시 거르고 있었습니다. 스케줄을 먼저 조회하고 필요한 이름 정보를 묶어 가져오도록 Python CRUD와 SQL을 수정해 응답을 0.05초로 줄였습니다. 이 경험으로 데이터의 위치와 접근 방식까지 살피는 성능 분석 역량을 키웠습니다.

[GCP 학습을 운영 자동화로 연결]
입사 당시 클라우드 실무 경험이 없어, CRM을 구축하며 관리형 DB·컨테이너 실행 환경·비밀값 저장소의 역할부터 익혔습니다. 공식 문서와 실제 동작을 확인하며 Cloud Run·Cloud SQL·Secret Manager를 직접 구성했습니다. 이후 사건관리 앱에서는 Cloud Scheduler로 업무시간에만 인스턴스를 예열하도록 구성했습니다. 배포 오작동을 분석한 뒤에는 이미지 빌드와 배포를 분리하고 응답 본문을 검사하는 절차를 만들어 신규 시스템에도 적용했습니다. 통신 서비스에서도 고객 접점의 정보가 내부 업무로 정확히 이어지도록, AI와 데이터 연동을 활용하는 AT/DT 업무에 기여하고 싶습니다.
```
