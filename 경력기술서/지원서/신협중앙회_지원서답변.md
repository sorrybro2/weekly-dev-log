```
[아무도 맡지 않는 일은 대개 꼭 필요한 일입니다]

[지금의 일에서]
이 태도는 지금도 제가 일하는 방식입니다. 미수금 관리 화면을 만들던 중 한 달 미납액이 기존 장부와 1천만 원 넘게 차이 났습니다. 원인을 밝힌 뒤에도 멈추지 않고 조사 범위를 전 기간으로 넓혀, 같은 금액과 날짜로 이중 등록된 미수금 27쌍을 찾아냈습니다. 다만 운영 중인 회계 데이터였기에 임의로 고치지 않고, 건별 근거를 정리해 승인 절차로 넘겼습니다.
필요한 일은 먼저 맡되, 맡은 범위와 권한은 지킨다는 것이 제 기준입니다.
```

## 3. 직장 선택 기준과 신협중앙회의 부합점 (700자)

```
[만든 것이 누군가의 일을 실제로 받치는 곳]
저는 직장을 고를 때 제가 만든 시스템이 사람들의 일상 업무를 실제로 받치고 있는지, 그리고 그것을 오래 책임질 수 있는지를 가장 중요하게 봅니다.
이 기준은 지금 회사에서 전국 10개 지사가 쓰는 고객관리 시스템을 만들며 생겼습니다. 스프레드시트로 하던 업무를 시스템으로 옮기고 지사 실무자의 피드백을 직접 받아 고치면서, 기능을 만드는 것보다 매일 정확하게 돌아가게 하는 것이 더 어렵고 중요하다는 것을 알았습니다. 홈페이지의 상담 내용을 권한 없는 관리자에게는 가려 보이게 처리한 것도 같은 이유입니다. 사용자는 기능보다 먼저 시스템을 믿을 수 있어야 합니다.

[신협중앙회가 이 기준에 맞는 이유]
신협중앙회는 862개 조합과 1,702개 점포가 함께 기대는 기반을 운영합니다. 중앙회의 IT는 조합 직원이 매일 쓰는 업무 도구이자, 그 너머 조합원의 예금과 정보를 지키는 일입니다. 본사와 지사가 한 시스템으로 일하는 구조를 만들어 본 저에게 중앙회와 조합의 관계는 낯설지 않은 확장입니다.
또 신협은 이익보다 조합원을 먼저 두는 협동조합이고, 윤리강령은 조합원 정보를 정당한 절차 없이 외부에 내보내지 않는 것을 임직원의 의무로 둡니다. 신뢰를 기능보다 앞에 두는 제 기준과 같은 방향입니다. 한 조직의 시스템을 오래 맡아 깊어지는 개발자가 되고 싶어 지원했습니다.
```

## 4. 희망 직무와 쌓아온 역량 (700자)

```
[희망 직무: IT개발 및 관리]
조합과 중앙회가 쓰는 업무시스템의 개발과 운영, 그중에서도 데이터베이스를 중심으로 한 시스템 구축과 관리를 맡고 싶습니다.

[데이터를 옮기고 지키는 역량]
현재 회사에서 스프레드시트로 운영되던 지사 업무를 관계형 데이터베이스로 옮기며, 스키마 설계부터 약 9만 8천 건의 이관까지 단독으로 수행했습니다. 레거시 홈페이지의 데이터 730만 건도 검증을 거쳐 새 시스템으로 이관했습니다. 데이터 이관은 건수보다 빠짐과 어긋남이 없음을 증명하는 일이라는 것을 이때 배웠습니다.

[원인을 측정으로 찾는 역량]
업무시스템의 한 목록이 8초 넘게 걸렸습니다. 확인해 보니 다른 데이터베이스의 테이블을 원격으로 조인하면서 조회할 때마다 원격 테이블 전체를 가져오는 구조였습니다. 필요한 데이터를 먼저 조회한 뒤 묶어서 가져오도록 바꿔 0.05초로 줄였습니다. 비교하는 두 컬럼의 타입이 달라 인덱스를 쓰지 못하던 조회도 찾아내 1695ms에서 109ms로 줄였습니다.

[기초와 폭]
컴퓨터공학을 전공했고 정보처리기사를 취득했습니다. 이전 직장에서는 Java와 Spring 기반 시스템을 유지보수했고, 지금은 TypeScript, Python, SQL로 화면과 API, 데이터베이스, 클라우드 배포까지 직접 다룹니다. 전 계층을 다뤄 본 덕분에 문제가 생기면 어디를 열어봐야 하는지 빠르게 판단할 수 있습니다.
```

## 5. 입사 후 역량 개발 계획과 목표 (700자)

```
[먼저 이해하기]
입사 후에는 새로 만들기보다 중앙회와 조합이 쓰는 시스템과 데이터의 흐름을 먼저 익히겠습니다. 제가 주로 다뤄 온 데이터베이스는 PostgreSQL이므로, 중앙회 환경에 맞춰 Oracle과 Tibero의 실행계획과 운영 방식을 따로 학습하겠습니다. SQL과 성능 분석의 원리는 같기에 빠르게 옮겨 갈 수 있다고 생각합니다. 금융회사가 지켜야 하는 전자금융 관련 규정과 보안 기준도 함께 공부해, 규정을 먼저 두고 기술을 고르는 순서를 몸에 익히겠습니다.

[조합 현장의 불편을 줄이기]
업무가 손에 익으면 조합 직원이 매일 쓰는 화면에서 반복되는 불편을 찾아 줄이고 싶습니다. 지사 실무자의 피드백을 받아 고쳐 온 것처럼, 조합의 요청을 증상으로 듣고 원인은 데이터로 확인해 해결하겠습니다. 배포와 장애 대응 절차도 문서로 남겨, 한 사람의 기억이 아니라 절차가 시스템을 지키는 구조를 만들겠습니다.

[믿고 쓰는 시스템의 한 축]
장기적으로는 데이터 정합성과 성능을 책임지는 전문가가 되는 것이 목표입니다. 조합원이 신협을 믿는 이유 중 하나가 한 건도 어긋나지 않는 숫자라면, 그 숫자를 지키는 일을 맡고 싶습니다. 조합 직원이 시스템을 의심하지 않고 조합원에게 집중할 수 있도록 돕는 개발자가 되겠습니다.
```
