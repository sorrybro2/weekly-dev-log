## 2. 기술적 도전 및 트러블슈팅 (Technical Challenges & Troubleshooting)

- **DB 마이그레이션 및 P2002 장애 해결:** 기존 레거시(SQL Server)에서 신규 DB(PostgreSQL)로 증분 마이그레이션 후 발생한 상담 접수 실패(P2002 에러) 원인을 분석함. 밀려있던 테이블 시퀀스의 불일치 문제를 파악하고, 동기화 스크립트에 시퀀스 자동 정렬 로직을 내장해 장애를 원천적으로 해결함.
    
- **다중 작업자 충돌 방지 시스템 구축:** CRM 내 다수 직원의 동시 접수 처리 시 발생하는 데이터 덮어쓰기 및 충돌을 방지하기 위해, 당사자 등록 시 해당 건을 즉시 점유(Claim)하고 10분 방치 시 자동 회수되는 락킹(Locking) 시스템을 도입함.
    
- **구글 OAuth 로그인 간헐적 끊김(Premature close) 조치:** 백엔드 도커(Docker) 빌드 시 Node 버전을 고정(22.16.0-alpine)하고 의존성 설치 방식을 변경(npm ci)하여, 토큰 교환 단계에서 발생하던 네트워크 연결 끊김 현상을 완벽히 해결함.
    
- **데이터 추출 보안 및 감사 추적성 확보:** 엑셀/CSV 데이터 다운로드 시 성명 및 연락처의 기본 비식별 처리를 강제함. 사용자가 식별 상태로 추출을 시도할 경우 시각적 경고 UI를 노출하고, 서버 감사 로그(Audit Log)에 해당 이력이 정확히 기록되도록 보안 아키텍처를 고도화함.
    
- **상담지 텍스트 한계 극복 및 라우팅 오류 수정:** 자유 입력 필드에 긴 텍스트 입력 시 발생하던 저장 실패(길이 초과) 오류를 방지하고자 관련 컬럼을 확장하고 자동 마이그레이션 로직을 추가함. 또한, 8자리 당사자 키를 전화번호로 오인하여 신규 등록 폼으로 잘못 연결되던 라우팅 버그를 상세 화면으로 정상 진입하도록 수정함.
    

## 3. 총평 및 향후 과제 (Wrap-up & Next Steps)

> **"신규 비즈니스 랜딩페이지의 성공적 런칭 준비와 레거시 시스템의 구조적 안정화 및 데이터 보안 강화를 동시에 이뤄낸 한 주"**

CRM의 실시간 연동 강화와 다중 작업자 충돌 시스템(Claim) 도입을 통해 실무 운영의 효율성을 대폭 높였습니다. 더불어 신규 DB 마이그레이션 스크립트 안정화와 클라우드 기반 배포 자동화 파이프라인(Cloud Build)을 성공적으로 구축하여, 향후 트래픽 증가와 서비스 확장에 대비한 기술적 토대를 탄탄히 다졌습니다.

**향후 과제:**

- **랜딩페이지 법무 검토 및 리소스 현행화:** 광고 문구('완벽 보장', '국내 1%' 등)에 대한 법무 및 심의 검토 진행. 마스킹 처리된 인가결정문/언론보도 이미지 수급 및 변호사 프로필 배경 제거본 최종 교체 적용 예정
    
- **변제금 계산기 실무 정합성 검증:** 신규 개발된 계산기의 생계비 산정 기준(2026년 보건복지부 중위소득 60%)이 회생팀의 실제 실무 기준과 완벽히 부합하는지 최종 확인
    
- **운영 환경 최종 세팅:** 어드민 구글 로그인(OAuth) Secret Manager 연동 마무리 및 정식 오픈 시점에 맞춘 워드프레스 검색엔진 노출 설정(SEO) 활성화
