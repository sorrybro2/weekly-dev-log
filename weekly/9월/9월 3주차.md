# 주간 업무 회고 (9월 3주차)

> 이번 주는 월·수·목·금 4일 작업(9/14~9/18, 화요일 커밋 0). 커밋 52건 — 홈페이지 V2 33건, 사건관리 앱 13건, CRM 6건, 인프라 repo 0건. 이슈 코멘트 38건. 주의 축은 둘이었다 — **AI 상담봇을 설계 문서에서 실제로 도는 물건으로 끌어내린 것**, 그리고 **"조용히 실패해서 아무도 모르던 것" 세 건을 같은 주에 들춰낸 것**이다. 후자가 이번 주의 진짜 주제였다. 업로드가 32MB에서 소리 없이 실패하고 있었고, 게시물 동기화가 2주째 성공으로 보고하며 멈춰 있었고, 구글 권한 연동은 **운영에서 한 번도 동작한 적이 없었다.** 셋 다 화면이 멀쩡해 보였다는 공통점이 있다.

## 1. 주요 업무 성과 (Key Achievements)

**이번 주의 중심은 AI 상담봇이었다.** 9/16에 착수 직전 점검으로 하루를 쓰고, 9/17에 Phase 1(검색 층)을 하루에 완주했으며, 9/18에 마지막 미결 항목이 풀리면서 Phase 2에 들어갔다. 사이트 글 4,398건을 7,786조각으로 잘라 색인하고, 실제 상담 접수에서 말투를 뽑은 50문항으로 채점 체계를 만들어 **정답률 95.8%** 를 숫자로 확정한 뒤, 화면 없이 `질문 → 검색 → 답변`을 터미널에서 돌려 가드레일을 실측했다. 여기서 나온 것이 이 주에서 가장 값진 발견이다 — **프롬프트로 금지한 표현이 실제로 새어 나왔고, 봇이 없는 전화번호와 없는 지사 목록을 지어냈다.** 돌려보지 않았으면 출시 후에 알았을 일이다. 금요일에는 스펙이 "설계 분기점"으로 못 박아 둔 서울 리전 모델 가용성이 풀려(9/2 실측의 "비활성"이 뒤집혔다) Vertex AI 채택 근거가 그대로 유지됐고, 답변 검사층을 백엔드로 옮기며 Phase 2를 시작했다.

두 번째 축은 **조용한 실패**다. 월요일 사건관리 PC 업로드가 큰 파일에서 실패하던 원인이 Cloud Run 요청 본문 32MB 하드 제한이었고, 금요일에는 게시물 동기화가 2주째 멈춰 있었는데 배치 종료코드가 늘 0이라 스케줄러에는 성공으로 떠 있었으며, 같은 날 구글 권한 연동이 **맞춤정보 항목 이름 하나가 어긋나 109명 전원의 권한을 못 읽고 있었다.** 세 건 모두 실패가 조용히 다른 경로로 대체되는 구조(서버 경유 폴백 / `echo` 로 끝나는 배치 / DB 권한 폴백)여서 화면이 정상으로 보였고, 그래서 각각 며칠에서 몇 달을 갔다. 이번 주에 고친 것은 개별 버그라기보다 **"실패가 드러나는 구조"** 였다.

- **AI 상담봇 — 설계에서 동작으로 (9/16~9/18, 이슈 `#125`)**

    - **착수 전 점검에 하루를 썼다:** 외부 강의 자료(Cloudflare)를 599줄 스펙과 1:1로 대조해 **스펙에 관측 항목이 0건**이라는 빈칸을 찾아 4건을 채웠다. 플랫폼 이전은 "대화 원문이 민감정보라 국외이전 고지 문제를 아예 만들지 않는다"는 선택 근거를 통째로 무효화하므로 비채택 (`1f42041`)
    - **색인 7,786조각 적재:** 사이트 글 4,398건을 300~800자로 잘라 임베딩. 28분, 74MB. 내용이 그대로인 조각은 다시 계산하지 않아 재실행이 저렴하다 (`27b7585`·`e011133`)
    - **⭐ 정답률을 숫자로 만들었다 — Recall@5 95.8%:** 실제 상담 접수 본문에서 말투를 뽑은 24문항 + 분야를 메우는 24문항 + **아무 답도 안 해야 정답인 2문항**으로 채점. 개인정보는 전부 제거 (`82d23fe`)
    - **판정선 0.28은 표본 7개짜리 착각이었다:** 50문항으로 재보니 정답 구간과 무관 구간이 겹쳐, 양쪽을 다 지키는 유일한 지점 **0.32** 로 정정
    - **뜻 검색에 글자 검색을 합쳤다(RRF):** 뜻만으로는 사건번호·법조문에 약하고 글자만으로는 동의어를 못 찾는다. 순위를 합산해 93.8% → **95.8%** (`a5e7b0b`)
    - **🔴 법률 코퍼스에서는 교과서가 거꾸로 작동:** 흔한 단어를 빼는 방식으로 잡음을 거르려 했으나 **집행유예 9.85% · 보이스피싱 6.64%인데 오늘 2.30% · 저녁 0.57%** 였다. 법률 용어가 흔하고 일상어가 드물어 핵심어를 버릴 뻔했다 → 단어 빈도 대신 **질문 단위 게이트**(의미 검색이 아무것도 못 찾으면 글자 검색 결과도 쓰지 않는다)로 교체
    - **내린 글이 근거로 나가던 경로 차단:** 색인은 적재 시점 스냅샷이라 그 뒤 숨긴 글이 계속 인용된다. 공개 여부만은 **매 질의마다 원본 테이블에서** 확인 (`5d1c231`)
    - **⭐ 돌려보고서야 드러난 것 — 가드레일 3종이 뚫렸다:** ① 제목 뱃지를 떼도 본문에 처분 결과가 깔려 있어 모델이 "집행유예 성공"을 재생산 ② 없는 대표번호(`1577-3031`)와 오타 도메인을 생성 — 표현 문제가 아니라 **오배송** ③ 번호를 막았더니 이번엔 "전주·대구"(없는 지사)를 나열. 전화·주소는 DB에서 읽어 코드가 붙이고, 사무소 10곳은 사실로 주입해 해결 (`20254b1`)
    - **금요일 — 설계 분기점 해소:** 서울 리전에서 `gemini-2.5-flash`·`gemini-embedding-001` 실호출 성공. 9/2 "비활성"이 뒤집혀 **국외이전 고지 검토가 되살아날 일이 없어졌다.** 다만 `gemini-2.5-pro`는 서울에 없어(404) **상위 모델 에스컬레이션은 애초에 불가능** — Flash 단일 확정
    - **Phase 2 착수:** 답변 검사층을 백엔드로 이식. 실제로 새어 나왔던 문장을 회귀 테스트 27건으로 고정했다 (`3fc931c`)

- **사건관리 — PC 업로드 4개 기능을 직접 업로드로 전환 (9/14, 이슈 `#548`·`#549`)**

    - **32MB는 설정으로 못 올린다:** Cloud Run 플랫폼 하드 제한이라 릴레이 구조를 유지한 채로는 해결이 없다 — 브라우저가 Drive와 직접 통신하는 것이 사실상 유일한 해법
    - **4개 기능 전부 전환:** 수발신문서·계약·사건 Drive 패널·수기일정. 같은 구조·같은 위험이라 하나만 고치면 나머지 3곳이 그대로 남는다
    - **🔴 스코프 확대가 숨은 선행 조건이었다:** 기존 토큰은 `drive.readonly`라 업로드가 403. 이슈 계획에 없던 전제라 먼저 잡아 공유했다
    - **⭐ 재동의해도 안 되던 버그를 배포 전에 발견:** 구글은 **새 동의 때만 refresh_token을 재발급**한다. 옛 토큰이 남아 로그아웃·재로그인으로도 해결되지 않는 상태였다 — 배포 후였다면 "새 경로를 영영 못 타는" 사용자가 생겼다
    - **하드 컷오버 회피:** 재동의 전 사용자·합계 25MB 이하는 기존 서버 경유. 배포 시점에 전원이 동시에 재로그인할 필요가 없다
    - **서버가 폴더를 재검증:** 검증이 없으면 파일은 업로더의 내 드라이브에 남았는데 대장만 정상으로 보인다

## 2. 기술적 도전 및 트러블슈팅 (Technical Challenges & Troubleshooting)

- **"조용한 실패"가 세 건, 구조가 같았다.** 업로드는 25MB 초과 시 서버 경유로 폴백, 동기화 배치는 마지막 명령이 `echo`라 종료코드가 늘 0, 권한 연동은 못 읽으면 DB 권한으로 폴백. **셋 다 실패를 다른 경로로 덮는 설계**라 화면이 정상으로 보였다. 폴백 자체가 나쁜 것은 아니지만 **폴백이 조용하면 원인이 영구히 감춰진다** — 이번 주에 고친 것은 개별 버그가 아니라 이 패턴이다.
- **표본 7개로 정한 기준이 틀렸다.** 상담봇 판정선 0.28은 질문 7개로 본 값이었고, 50문항으로 재보니 정답 구간과 무관 구간이 겹쳤다. **수치를 근거로 제시했다는 사실이 그 수치를 검증하지 않는다** — 9월 2주차의 "월 $5" 오판과 같은 계열의 실수다.
- **도메인 지식이 일반 기법을 뒤집는 경우.** 검색에서 "드문 단어가 정보량이 많다"는 전제는 법률 코퍼스에서 정확히 반대로 작동했다(집행유예 9.85% vs 저녁 0.57%). 기법을 적용하기 전에 **우리 데이터에서 그 전제가 성립하는지** 재는 단계가 필요하다.
- **AI 출력은 프롬프트로 막히지 않는다.** 금지어를 명시했는데도 결과 표현이 새어 나왔고, 번호를 막으니 지사 목록을 지어냈다. 막을 때마다 **다른 자리에서 새어 나온다**는 것이 이번 주의 실측 결론이고, 그래서 출력 검사층이 프롬프트와 별개로 필요하다.
- **PowerShell·gcloud의 함정을 하루에 6개 밟았다.** `$PSScriptRoot`가 param 기본값에서 비는 것, BOM 없는 UTF-8을 ANSI로 읽어 **파싱까지 어긋나는** 것, `--update-env-vars`가 쉼표를 먼저 먹는 것, `--update-headers`가 기존 헤더를 통째로 교체하는 것, 그리고 **`$inserted건`을 통째로 변수명으로 읽어 건수가 빈칸이 되던 것**. 마지막 건은 실패 알림을 붙여 두지 않았으면 계속 몰랐다.
- **번호를 그대로 옮기면 안 되는 데이터가 있다.** 두 시스템이 각자 자동증가 번호를 발급하면 같은 번호에 다른 사람이 앉는다. 게시물은 건너뛰어도 글 하나가 안 들어올 뿐이지만 **상담은 전화를 기다리는 사람이 사라진다.** 같은 동기화라도 데이터 성격에 따라 전략이 갈린다는 것을 숫자로 확인했다.

## 3. 총평 및 향후 과제 (Wrap-up & Next Steps)

이번 주는 **"돌려보기 전에는 모른다"** 가 반복된 주였다. 상담봇은 스펙 599줄을 다 쓰고 나서 실제로 돌려보니 가드레일 3종이 뚫렸고, 동기화는 성공으로 보고되던 배치가 2주째 멈춰 있었으며, 권한 연동은 코드가 완성된 지 한참 지나서야 운영에서 한 번도 동작한 적 없다는 것이 드러났다. 세 건 다 **문서나 코드 리뷰로는 잡히지 않고 실행해야만 보이는 종류**였다. 그래서 이번 주에 들인 시간 중 값이 컸던 것은 새 기능이 아니라 **채점 체계(골든셋 50문항)와 알림 체계(실패 + 침묵)를 만든 것**이다. 다음에 같은 일이 생기면 몇 주가 아니라 하루 안에 드러난다.

- **AI 상담봇 Phase 2 계속** — 검색 층과 출력 검사는 옮겼고, 남은 것은 RRF 검색 서비스·Vertex 스트리밍·캡·대화 저장·SSE 컨트롤러다. 툴콜(`submit_consult`)은 **답변 품질이 검증되기 전에 실제 고객 접수를 붙이지 않는다**는 판단으로 Phase 4로 미뤘다.
- **문서 반영이 1순위** — 서울 리전 가용성 해소, Pro 모델 404, 예산 3만원 결정이 이슈 `#125`·스펙 §9에 아직 없다. 특히 §9-6에 **서울에서 불가능한 "2단 모델 구성"이 제안으로 살아 있어** 다음에 읽는 사람이 없는 선택지를 검토하게 된다.
- **동기화를 레거시 서버로 이전** — 지금은 사무실 PC에서 돌아 **전원과 유동 IP에 묶여 있다.** 서버로 옮기면 상시 가동이라 제약이 사라지고 설치할 런타임도 없다. 다만 26시간 침묵 감시가 붙어 있어 급하지는 않다.
- **초기 대응 매뉴얼 20~30건(Phase 0.5)이 여전히 미착수** — 변호사 리소스가 필요한 항목이라 개발과 병행되지 않으면 출시 시점에 병목이 된다.
- **남은 구멍 2개** — 업로드 파일 동기화(`#126`, DB 행만 가고 사진은 안 간다)와 대화 로그 개인정보 처리방침(`#135`). 후자는 법무 판단이 선행이다.
