# 주간 업무 회고 (9월 4주차)

> 이번 주는 수요일(9/23) 하루 작업이다(9/21~9/25). 9/21·9/22는 커밋·이슈 활동 기록이 없고, 9/24·9/25는 추석 연휴였다. 커밋 26건 — 전부 홈페이지 V2. 사건관리 앱·CRM·인프라 repo는 0건. 신규 이슈 2건, 이슈 코멘트 7건. 하루였지만 축은 분명했다. 지난주 Phase 1(검색 층)과 Phase 2 착수까지 온 **AI 상담봇을 화면에서 실제로 대화하고 상담 접수까지 이어지는 물건으로 완성**했고, 그 과정에서 **"코드는 다 됐는데 운영에서는 안 도는" 조건 두 가지**(운영 DB 미적용, 서울 리전 용량)를 찾아냈다.

## 1. 주요 업무 성과 (Key Achievements)

**연휴 직전 하루에 상담봇의 남은 층을 한 번에 이었다.** 9/18까지 터미널에서만 돌던 `질문 → 검색 → 답변`이 9/23 하루에 백엔드 서비스와 SSE 스트리밍, 화면 런처와 패널, 대화 안 상담 접수까지 연결됐다. 지난주에 실측으로 확인한 가드레일 구멍(결과 표현 재생산, 없는 번호, 없는 지사)은 이번에 **전송 전 누적문 검사**와 **완료 후 연락처·URL 검사**라는 두 시점의 검사로 구조화됐다. 구현보다 값진 것은 운영 준비에서 나왔다. 마이그레이션 SQL은 커밋됐지만 운영 DB에 적용되지 않아 첫 요청이 실패했고, 서울 리전 생성 요청은 간헐적으로 429를 냈다. 둘 다 로컬에서는 보이지 않는 종류다.

- **AI 상담봇 — 대화 처리 층 완성 (이슈 `#125`)**

    - **검색 서비스 이식:** CLI에서 채점한 RRF 검색을 백엔드로 옮겼다. 같은 벡터로 CLI와 서비스의 결과 순서까지 일치하는 것을 확인해, "평가한 것과 운영되는 것이 다르다"는 위험을 없앴다 (`04234c2`)
    - **Vertex 접근 계층 분리:** 인증, 임베딩, 생성, SSE 수신을 한 서비스로 묶었다. 실패는 상위 대화 서비스가 상담 접수 안내로 받는다 (`4f88ff4`)
    - **🔴 응답이 비던 원인은 줄바꿈 하나:** 모델 응답은 도착했는데 CRLF 이벤트 경계를 파서가 못 읽어 본문이 비었다 (`01a2df5`)
    - **대화 한 요청으로 연결:** 한도 확인 → 검색 → 생성 → 검사 → 저장을 SSE 엔드포인트 하나로 묶었다. 연락처는 모델이 아니라 **코드가 검증된 지사 정보로 붙인다** — 지난주 "없는 대표번호" 사고의 구조적 해법이다 (`867dfe7`)
    - **시간 예산 기반 재시도:** 재시도 횟수만큼 기다리던 것을 남은 요청 예산으로 제어했다. 스트리밍이 시작된 뒤에는 재시도하지 않는다 (`5282276`)
    - **⭐ 검사를 두 시점으로 나눴다:** 금지 표현은 조각이 아니라 누적문으로 검사해, 위반 조각은 **보내기 전에** 끊는다. 그런데 같은 시점에 URL 허용 목록을 보니 스트리밍 중 잘린 주소를 허위 주소로 오판해 안전한 답까지 막았다 → 연락처·URL 검사만 응답 완료 후로 옮겼다 (`838e1df`·`6dc14fe`)
    - **🔴 타입 검사가 못 잡은 기동 실패:** 알림 모듈 의존성 누락이 사이트 전체 API 서버의 시작을 막았다. 상담봇 기능 하나가 홈페이지 전체를 멈출 수 있는 경로였다 (`acefe74`)

- **AI 상담봇 — 화면과 접수 흐름 (이슈 `#125`)**

    - **런처·패널:** PC 채널 버튼 묶음과 모바일 하단 상담바 위에 진입점을 두었다. 차단으로 답이 바뀌는 것은 오류가 아니라 정상 흐름으로 보이도록 표시 규칙을 먼저 명세에 적었다 (`1132257`·`5cc1858`)
    - **성급한 답 → 되묻기:** 분야 이름만 듣고 답하던 것을 사연 확인으로 바꾸고, 그때는 검색을 건너뛴다 (`df18a21`)
    - **대화 안 접수:** 분야별 추가 질문, 긴급 상황 전화 안내, 동의 기반 접수 폼을 붙였다. 접수는 기존 상담 경로의 제한과 알림을 그대로 재사용한다 (`8fe22d0`)
    - **맥락 소실 수정:** 후속 질문에 사건명이 없으면 엉뚱한 분야를 검색하고 이미 말한 지점도 잊었다 → 대화 이력으로 검색 입력과 지점 판정을 보정 (`7340482`·`9411a3f`)
    - **근거 카드 기준 분리:** 모델에 주는 검색 자료와 화면에 내세우는 사례를 나눴다. 카드는 더 엄격한 기준과 복수 근거 조건을 통과해야 뜬다 (`40933db`)

- **AI 상담봇 — 운영 준비 (이슈 `#125`)**

    - **🔴 운영 DB 미적용:** SQL 파일은 커밋됐지만 운영에 자동 적용되지 않아 실제 요청에서 `tbl_chat_session` 부재가 드러났다. 적용 후 "DB → 소량 색인 → 전체 적재 → 운영 SSE 확인 → 프론트 배포" 순서를 문서로 고정했다 (`955d370`)
    - **서울 리전 429 관측:** 서울만 생성 요청이 간헐적으로 실패했다. 서울·도쿄 비교 측정 도구를 만들고 Cloud Scheduler로 측정을 돌렸다. 리전 이전은 국외이전 고지와 얽혀 있어 법무 판단 항목으로 남겼다 (`ab0b69b`)
    - **장문 색인 중단:** 문장 부호 없는 긴 글이 한 조각으로 남아 임베딩 상한을 넘었다. 자동 잘라내기로 조용히 버리는 대신 길이 기준으로 다시 나누고 앞 조각을 겹쳐 적재했다 (`b9465ce`)

- **홈페이지 V2 — 추석 안내와 레거시 이미지 (이슈 `#136`·`#137`)**

    - **추석 상담 공지 바:** 오래된 연휴 팝업 대신 헤더 맨 위 공지 바를 만들었다. UTC 서버에서도 KST 기간에 맞춰 켜지고 꺼지며, 고정 헤더·히어로·앵커 여백을 바 높이에 맞췄다 (`42ece62`)
    - **신규 이미지 누락:** 게시물만 동기화되고 새 파일은 GCS에 없는데 업로드 주소가 무조건 GCS로 향했다. 저장소에 없으면 원본 서버로 보내는 경로와 누락 파일 복구 도구를 넣었다. 동기화에 파일 이관을 포함하는 근본 해결은 후속으로 남겼다 (`b4ff0fe`)

## 2. 기술적 도전 및 트러블슈팅 (Technical Challenges & Troubleshooting)

- **검사의 "시점"이 검사의 정확도를 정한다.** 같은 출력 검사라도 금지 표현은 전송 전에 봐야 의미가 있고, URL·연락처는 문장이 끝나야 판정할 수 있다. 하나의 시점에 다 몰았더니 한쪽은 너무 늦고 한쪽은 너무 일렀다. **검사 대상의 성격에 따라 시점을 나눈 것**이 이번 주의 설계 판단이다.
- **스트리밍은 "되돌릴 수 없는 출력"이다.** 일반 응답은 다 만든 뒤 검사하면 되지만, 스트리밍은 이미 보낸 글자를 회수할 수 없다. 그래서 재시도도 스트리밍 시작 전까지만 허용하고, 위반은 조각 단위가 아니라 누적문으로 잡아 **보내기 전에** 끊는 구조가 필요했다.
- **"커밋 = 배포"가 아니다.** 마이그레이션 SQL이 저장소에 있다는 사실과 운영 DB에 테이블이 있다는 사실은 다르다. Prisma 스키마로 타입은 맞았지만 운영에는 없었다. 이번에 출시 절차를 문서로 고정한 이유다.
- **타입 검사가 잡지 못하는 실패.** NestJS 모듈 의존성 누락은 컴파일을 통과하고 기동 시점에만 터진다. 게다가 상담봇이 같은 API 서버에 붙어 있어 **부가 기능 하나가 사이트 전체를 멈출 수 있었다.** 실제 기동 확인을 배포 절차의 필수 단계로 올렸다.
- **지역별 용량은 코드로 해결되지 않는다.** 서울 429는 우리 요청이 많아서가 아니라 리전 공유 용량 문제로 보였다. 다만 리전을 옮기면 지난주 "국외이전 문제를 아예 만들지 않는다"는 선택 근거가 흔들린다. 그래서 바로 옮기지 않고 측정부터 돌렸다. 이 문제는 다음 주(9/28) "생성만 도쿄로" 결정으로 이어진다.

## 3. 총평 및 향후 과제 (Wrap-up & Next Steps)

하루짜리 주였지만, 상담봇이 **설계 문서 → 터미널 → 실제 대화 화면**으로 넘어간 주였다. 지난주 결론이 "돌려보기 전에는 모른다"였다면 이번 주는 그다음 단계, **"운영에 올려 보기 전에는 모른다"**였다. 운영 DB 미적용과 서울 429는 로컬과 개발 환경에서는 끝까지 안 보였을 것이다. 대신 대가도 있었다. 이날 외부에 공개된 상담봇은 개인정보 처리방침과 파기 장치가 갖춰지지 않은 상태였고, 연휴 동안 실제 사연이 쌓였다. 이것은 다음 주 첫날(9/28) 직원 전용으로 거두는 결정으로 이어진다.

- **개인정보 요건이 1순위** — 동의, 보유 기간, 파기, 처리방침 개정이 공개 전제 조건이다(`#135`). 연휴 뒤 첫 작업으로 처리한다.
- **서울 리전 429 판단** — 측정 결과를 보고 유지·이전·분리 중에 고른다. 국외이전 고지 문제를 다시 열지 않는 선택지가 우선이다.
- **레거시 이미지 동기화** — 지금은 없을 때 원본 서버로 돌리는 우회다. 게시물 동기화에 파일 이관을 넣어야 재발이 멈춘다(`#137`).
- **출력 검사 회귀 세트 확장** — 이번에 오판으로 막힌 정상 답(잘린 URL)도 회귀 테스트에 넣어, 검사를 강하게 할수록 정상 답이 막히는 반대 방향의 실패도 지킨다.
