# 주간 업무 회고 (7월 5주차)

> 이번 주는 월~금 5일 모두 작업(7/27~7/31). 커밋은 사건관리 앱에 집중되었고 CRM이 1건, 홈페이지 V2는 없음.

## 1. 주요 업무 성과 (Key Achievements)

**결재를 "메일에서 하는 것"에서 "앱에서 하는 것"으로 옮기고, 수발신 문서를 이름값에 맞는 대장(臺帳)으로 끌어올린 한 주.** 주 초 AMP 인이메일 결재를 완주 직전까지 밀어붙였으나 도메인 인증 요건 때문에 전면 롤백하고, 그 결정을 계기로 결재 흐름 전체를 재설계함 — 메일은 알림만 남기고, 결재자 지정·승인·반려는 앱에서, 결재자가 실제로 일할 결재 관리 화면과 열람 전용 참조자까지 새로 세움. 수발신 문서는 첨부를 여러 개 담고 Drive 파일을 사건 폴더로 편입해 "대장엔 있는데 폴더엔 없는" 상태를 없앰. 사건목록은 컬럼 다섯 개를 늘리고 기본 정렬을 3단으로 재정의해 실무자가 하루 종일 보는 표로 다듬었고, 대전/청주처럼 한 사무소로 운영되는 지사를 **6개 화면의 필터에서 한 칸으로 묶음**. 주 후반에는 **사용자 활동 감사 로그**를 신설해 "누가 무엇을 어떻게 바꿨는지"를 앱이 스스로 남기게 하고, 시스템 설정 화면을 실수 없이 쓸 수 있게 정비함. 사건 목록 조인 인덱스를 정상화해 **1695ms → 109ms(약 15배)** 로 끌어내린 성능 개선과, 배포 중 발생한 프로덕션 API 9분 중단 사고의 원인 규명·postmortem 기록도 포함됨.

- **사건관리 앱: 결재 흐름 재설계 · 수발신 문서 대장화 · 사건목록 실무화 · 지사 그룹 · 감사 로그**

    - **결재 흐름 재설계 — 메일에서 앱으로:**

        - AMP for Email 인이메일 결재를 마무리하려 Gmail preflight CORS 우회·전용 고정 발신 계정·본문 표시 규칙 정합까지 붙였으나, **AMP 발신자 등록 요건인 DKIM·DMARC가 도메인에 없어** 모든 수신자가 HTML 폴백만 받는 구조임을 확인하고 AMP 경로 전체를 걷어냄(링크 메일·인앱 결재는 유지)
        - 남아 있던 메일 안의 승인·반려 링크마저 제거해 **메일은 "결재할 문서가 등록됐다"는 알림 역할로 축소**하고 제목도 결재확인으로 변경, 이미 발송된 메일이 깨지지 않도록 토큰 결재 경로는 레거시로 남김
        - 그동안 자동 매핑에 맡겨져 손댈 수 없던 **결재자를 등록 폼과 상세 양쪽에서 직접 지정**할 수 있게 하고, 자동 매핑 대상을 재직자로 한정해 퇴직 변호사가 결재자로 잡히던 문제를 해소함
        - "등록 = 결재요청 = 메일발송"이 한 덩어리였던 구조를 셋으로 분리함 — 등록은 인앱 알림·상태·Drive 배지만, 결재요청은 발송 직전 결재자 오버라이드 허용, 안내 메일은 문서 여러 건을 골라 별도 발송
        - 개발용 오발송 방지 장치가 설정에 정의되지 않아 무시되던 것을 배선해 로컬에서 실제 변호사에게 메일이 나가던 상태를 차단하고, 이후 운영 전환 시점에 의도적으로 걷어냄

    - **결재 관리 화면·참조자 신설(이슈 #106, #136):**

        - 결재 요청이 인앱 알림만 남게 되면서 **알림을 지나치면 처리할 건을 찾아갈 데가 없다**는 구멍이 드러나, 결재 대기·결재 완료·기안함 3탭의 결재 관리 화면을 신설함(기존 목록 API의 필터 조합만 써서 **백엔드 변경 0건**)
        - 대시보드 결재 위젯을 같은 어휘의 3탭으로 맞추고 바로가기가 보던 탭 그대로 이동하게 하며, 결재 알림 클릭 시 결재 관리로 이동한 뒤 상세를 띄워 **처리하고 닫으면 남은 대기 목록이 이어지도록** 동선을 정리함
        - 결재 버튼은 없지만 결재를 같이 알아야 하는 사람을 위해 **열람 전용 참조자**를 별도 개념으로 세움(JSONB + GIN 인덱스, 알림 타입 분리, 결재 처리 시 참조 알림 자동 읽음 처리)
        - 참조함 탭은 대기·완료·보류를 한 탭에 담음 — 참조자가 정작 알고 싶은 것은 결과인데 완료되는 순간 목록에서 사라지면 그걸 볼 수 없기 때문
        - 참조자를 결재자·기안자를 뺀 사건 관계자 + 사건 지사의 고정 수신자 중 재직 직원으로 자동 매핑하되, 사용자가 명시적으로 비운 값은 덮어쓰지 않게 처리함

    - **수발신 문서 파일·메일 취급 정비(이슈 #100~#105, #135):**

        - 문서 1건에 파일 N개를 담도록 첨부를 다중화하고(기존 링크 전량 백필), 첫 파일 링크는 유지해 목록·결재 배지·메일 등 단일 링크를 전제한 기존 경로를 건드리지 않음
        - Drive에서 고른 파일을 **사건 폴더로 복사**해 대장이 사본을 가리키게 하고(이미 그 폴더에 있으면 복사 생략, 원본은 제자리), 폴더 링크를 저장해 상세 진입마다 Drive를 되짚던 비용을 없앰
        - 옛 데이터 1.4만여 건이 파일이 아니라 폴더 URL이었다는 사실이 드러나 상세에서 파일·폴더 표시를 갈랐고, 등록 시 파일 첨부를 필수화하되 파일 없는 레거시 문서가 잠기지 않게 수정·재요청은 제외함
        - 안내 메일을 실무 포맷으로 재구성함 — 제목의 분류태그·당사자명과 본문 첫 줄의 사건 정리를 자동 조립하고, 표 나열을 없앤 자리에 **사용자가 직접 쓰는 내용 입력란**을 둠(미리보기와 발송 본문이 같은 규칙을 공유)
        - 의뢰인이 당사자와 갈리는 사건에서 의뢰인이 드러나지 않는다는 점을 발견해 위임인 배치 조회를 신설함
        - **지사별 고정 수신 이메일**을 시스템 설정에 신설하고, 발송 시 문서 지사의 주소를 서버가 강제로 붙이며 지사가 섞이면 지사별로 한 통씩 분할 발송하도록 처리함

    - **사건목록을 실무 표로(이슈 #90, #121, #131~#134):**

        - 셀 값이 길면 행 높이가 늘던 것을 한 줄 말줄임 + 호버 툴팁으로 바꾸고, 이름에 붙어 저장된 직위를 표시에서만 떼어 좁은 셀의 폭 낭비를 줄임(잘라먹기 사고를 피하려 특정 패턴만 제거)
        - 담당직원·종결일·진행상황·등록일 컬럼을 추가하고, 목록에서 바로 종결 처리할 수 있게 하되 **되돌릴 수 없는 변경이라 확인 팝업과 종결일 지정**을 붙임
        - 기본 정렬을 사건유형 → 접수기관 → 등록일 3단으로 재정의하고, 그 규칙을 덮고 있던 두 층(보류 별도 섹션, 변호사·당사자 그룹 순서)을 걷어내 **그룹 사이 순서까지 같은 규칙으로** 정렬함
        - 접수기관 필터를 신설하고, 진행상태는 단일 탭 → 복수선택 → 진행/종결 탭 분리로 정착시킴(종결 탭은 회색조로 시각 구분, 그동안 앱에서 접근할 수 없던 보류 35건도 노출)
        - 종결 6,759건을 매번 내려받지 않게 되어 조회량도 함께 줄어듦

    - **지사 그룹으로 사무소 필터 통합:**

        - 대전/청주, 인천/부천처럼 한 사무소로 운영되는 지사가 필터에서 두 칸으로 갈려 있던 것을, 새 개념을 만들지 않고 **기존 시스템 설정 「지사 그룹 관리」를 그대로 읽는 공용 훅**으로 묶음(대시보드 목표액이 쓰던 설정과 한 곳에서 관리)
        - 사건목록·담당사건 트리·미수금·상담료·계약목록·열람등사·문서대장 6개 화면에 일괄 적용하고, 백엔드에는 복수 사무소 파라미터를 추가하되 권한 범위와 교집합을 취해 우회 차단 동작을 유지함
        - 저장된 필터가 병합 전 사무소 키면 속한 그룹으로 정규화함 — 모르는 값을 두면 전체로 폴백해 조회 범위가 조용히 넓어지기 때문
        - 부수 효과로 특정 권한이 없는 사용자에게 **탭 라벨이 내부 키로 노출되던 문제**도 해소됨

    - **사용자 활동 감사 로그 신설(이슈 #171, #173):**

        - Cloud Run 로그에는 사용자와 요청 본문이 남지 않고 보관도 30일이라 "누가 무엇을 바꿨나"에 답할 수 없어, 저장소를 비교한 뒤 앱이 DB에 직접 적재하는 쪽으로 결정함
        - 요청 컨텍스트를 심는 미들웨어와 SQLAlchemy 세션 훅 2단 구조로 6개 테이블의 변경을 적재하고, update는 바뀐 필드만·등록/삭제는 스냅샷을 남김
        - 컨텍스트 없는 크롤러·스케줄러 자동 갱신은 제외하고(기일 일일 갱신만 월 5천여 건), 반대로 **데이터가 바뀌지 않는 권한 거부(403)는 별도로 기록**함 — 막힌 시도야말로 감사에서 봐야 할 기록이라는 판단
        - 시스템 설정에 super_admin 전용 조회 화면을 붙여 필드별 이전값 → 이후값 diff를 펼쳐 보이게 하고, 행위자 지사와 대상 지사가 다르면 「타 지사」 경고 배지를 띄움
        - 지사명·사건번호는 저장하지 않고 조회 시 조인해 얻도록 함(파생값을 박아두면 원본이 바뀔 때 어긋남)

    - **시스템 설정 화면 정비:**

        - 하위 화면으로 가면 좌측 메뉴가 통째로 사라져 돌아갈 길이 없던 것을 중첩 라우트 공용 셸로 묶고, 하위에서 섹션을 누르면 설정 본문의 해당 위치로 스크롤되게 함
        - 지사마다 입력창이 항상 펼쳐져 세로로 늘어지던 것을 요약 한 줄 + 아코디언으로 바꾸고, **저장하지 않고 접으면 저장된 값으로 되돌리게** 처리함
        - 쉼표 한 줄 입력이라 실수로 전체를 지우면 복구할 수 없던 고정 수신 이메일을 주소별 행·개별 삭제로 바꾸고 추가 시점에 형식·중복을 검사함
        - 저장 버튼이 저장 중 → 저장됨으로 바뀌게 하고, 확인도 알림도 없이 즉시 지워지던 계약 설정 삭제에 확인 다이얼로그와 결과 토스트를 붙임

    - **타임라인 · Drive · 기일 · 열람등사:**

        - 타임라인 소스 필터를 단일선택에서 다중선택으로 바꿔 "특정 소스만 빼고 보기"가 되게 하고, 풀페이지·사이드패널에 복붙돼 있던 필터 UI를 공용 컴포넌트로 합침(이슈 #142)
        - 연결사건(이송·송치·기소 등)을 별도 소스로 타임라인에 추가하고(이슈 #143), 사건상세 타임라인에 **CRM 상담 이력**을 새 소스로 얹어 선임 이전의 맥락(상담 → 계약 → 사건)을 이어붙임(이슈 #127)
        - 조회 전용이던 Drive 패널에 파일을 끌어다 놓으면 지금 보는 폴더로 바로 업로드되게 함(복수 파일, 부분 실패 구분 보고 — 이슈 #141)
        - 기일 충돌을 표시만 하고 끝이던 것을 **출석비고를 채우면 해제**되게 바꾸고(신규 컬럼 없이 기존 필드를 해소 신호로 재사용), 참석자와 불출석이 동시에 저장될 수 있던 모순을 서로 배타로 처리함(이슈 #130)
        - 열람/등사 목록에 의뢰인·신청서류 컬럼을 추가하고 발송 이력을 행 펼침에서 셀 hover로 축소, 완료 상태를 등사일자 기준으로 통일해 **등사일자 없는 완료 건**이 생기지 않게 막음(이슈 #107, #108)
        - 사건검색 결과를 기초사실 트리뷰로 렌더해 같은 의뢰인 아래 사건의 소속을 구조로 보이게 함(이슈 #117)
        - 실행취소 기능은 범위·UX 결정부터 확정해 1단계(스택·헤더 드롭다운·되돌릴 내용 표시·안전장치 2종)를 붙였으나, 주 후반 관련 이슈를 **폐기로 정리**함

    - **성능 · 목록 UX · 운영:**

        - 당사자 조인의 타입 불일치로 무효화된 인덱스를 캐스팅으로 살려 사건 목록 보강 쿼리를 **1695ms → 109ms(약 15배)** 로 개선함
        - 진행상황 칩이 외부 클릭 리스너를 항상 등록해 최대 1000행 목록에서 클릭 한 번에 핸들러가 1000번 돌던 것을, 팝오버가 열렸을 때만 등록하도록 바꿈
        - 표 페이지당 행 수를 뷰포트 높이에 맞춰 자동 계산하게 하고(행 높이 실측·소수 오차·상한 처리 포함), 컬럼 폭을 줄이면 옆 컬럼까지 움직이던 공용 표 버그를 여백 칼럼으로 해결함
        - 상담료 등록에 사건 검색 자동매핑과 높이 고정 모달을 넣어 손입력을 줄이고, 상담료·미수금 목록에 결제방법 필터를 공통으로 붙임
        - 배포 스크립트에 프로젝트를 고정해 **배포자·환경에 따라 목적지가 달라지는 사고**를 막고, 주 후반 발생한 프로덕션 API 중단 사고의 경위·재발방지를 postmortem 이슈로 남김

- **CRM (고객관계관리 시스템): 캘린더 상담사 표기 정렬**

    - 조회 순서에 따라 캘린더 제목의 상담사 이름 순서가 뒤바뀌던 문제를, 변호사 직군 우선 + 직급 서열 오름차순으로 정렬해 해결함
    - 캘린더 제목·상담사 선택 결과·상담 일정 저장 순서·상담 목록/상세 레이블까지 같은 기준으로 통일하고, 이름에 직함이 포함된 변호사도 변호사로 판별하도록 보강함

## 2. 기술적 도전 및 트러블슈팅 (Technical Challenges & Troubleshooting)

- **AMP 인이메일 결재의 완주 실패와 판단:** Gmail이 AMP 폼 전송 시 보내는 preflight를 전역 CORS 설정에 뚫지 않고 해당 경로만 미들웨어를 우회시켜 해결하고, AMP 허용이 발신 주소 단위라는 제약에 맞춰 결재 메일 전용 고정 발신 계정을 두는 데까지 갔음. 그러나 발신자 등록의 전제인 **DKIM·DMARC가 도메인에 설정돼 있지 않아** 등록 전까지는 전 수신자가 HTML 폴백만 받는 구조였음. 동작하지 않을 코드를 남기지 않기로 하고 AMP 경로 전체를 제거함 — 대신 그 결정이 "결재는 앱에서"라는 방향을 확정시켜 결재 관리 화면·참조자 설계로 이어졌음.

- **타입 불일치로 죽어 있던 인덱스(약 15배):** 당사자 조인 키가 한쪽은 고정길이 문자형, 다른 쪽은 text로 저장돼 **인덱스가 무효화되어 행마다 약 4만 행 순차 스캔**이 반복되고 있었음. 캐스팅으로 인덱스를 살려 목록 보강 쿼리를 1695ms에서 109ms로 줄임. 느린 화면의 원인이 쿼리 구조가 아니라 컬럼 타입에 있던 사례.

- **감사 로그를 어디서 잡아야 누락도 유령도 없는가:** flush 이후에는 변경 이력이 비어 무엇이 바뀌었는지 알 수 없고, flush 이전에는 신규 레코드의 PK가 없음. `before_flush`에서 변경 내역을 수집하고 `after_flush`에서 PK를 확인해 **같은 트랜잭션에** 적재하는 2단 구조로 정리해, 롤백된 변경이 로그로 남는 유령 기록과 PK 누락을 동시에 막음. 클라이언트 IP는 프록시 헤더의 첫 값을 취해야 내부 프록시 IP가 찍히지 않는다는 점도 함께 처리함.

- **FDW의 조인 푸시다운 부재와 실데이터가 드러낸 결함:** CRM 스키마가 이미 FDW로 마운트돼 있어 미러 테이블 없이 타임라인에 상담 이력을 붙였으나, **인라인 조인이 원격에 푸시다운되지 않아** 원격 테이블을 반복 스캔함 — 사건 전체를 도는 조회를 짰다가 5분을 넘겨 중단하고 상담만 먼저 뽑아 이름·사무소를 배치로 해소하는 방식으로 다시 작성함. 더 중요한 건 검증 단계에서 잡은 결함으로, 중복 제거를 날짜만으로 판정해 **같은 날 방문상담 예약이 있으면 그날 전화상담 3건이 통째로 사라지고** 있었음 — 판정 키를 (날짜) → (날짜, 유형)으로 바꿔 같은 유형만 접게 함.

- **겉으로 보이는 원인 뒤의 진짜 원인:** 목록 호버가 굼뜬 것은 CSS 페이드 때문으로 보였으나, 실제로는 행에 마우스를 올릴 때마다 상태가 갱신되며 **화면의 모든 행이 리렌더**되고 있었음(병합 셀 강조용 상태가 병합이 아닌 행에서는 애초에 불필요) — 조건을 좁혀 호버 리렌더를 없앰. 'CRM으로 이동' 역시 링크만 고치면 될 줄 알았으나, 목록과 상세의 의뢰인 키 해석이 달라 **같은 사건인데 서로 다른 의뢰인으로 갈 수 있는** 문제가 뒤에 있었음.

- **Drive 라벨이 개인 드라이브 파일에서 조용히 실패:** 결재 상태 배지를 세팅하는 호출이 관리자 계정 하나로 고정돼 있어, 공유 드라이브 파일은 되는데 **Picker로 고른 개인 파일은 관리자에게 보이지 않아 404/403으로 무성 실패**하고 있었음(best-effort라 예외를 먹고 로그만 남김). 위임 계정을 후보 목록으로 받아 관리자 → 기안자·요청자 순으로 시도하게 바꾸고 각 시도의 성공·실패 계정을 로그에 남김.

- **정렬 규칙을 정하자 그것을 덮고 있던 층들이 드러남:** 사건목록 기본 정렬을 3단으로 정의하는 과정에서, 보류 사건을 별도 섹션으로 내리던 처리가 **배치 규칙을 보류/비보류로 두 번 반복**시키고 있었고 변호사·당사자 그룹 순서가 위에서 규칙을 가리고 있었음. 두 층을 걷어내며 사이드패널 동작 불일치와 **새 컬럼이 저장된 순서 탓에 항상 맨 뒤에 붙던 문제**까지 함께 정리됨.

- **닫아도 화면이 잠기던 Picker:** 파일 선택 팝업을 닫아도 배경이 어둡고 클릭이 막히던 원인은 Picker 인스턴스를 만들고 `dispose()`를 한 번도 부르지 않아 오버레이 노드가 body에 남는 것이었음. 선택·취소 시 정리하도록 바꾸고, 폴더 링크 조회가 호출마다 토큰 교환을 유발하던 지연도 토큰 캐싱과 동시 호출 병합으로 줄임.

- **프로덕션 API 9분 중단 — 200을 믿은 것이 문제:** 배포 명령의 소스 경로가 셸의 잔여 디렉터리 상태 때문에 잘못 지정돼 **백엔드가 빠진 프론트 전용 이미지**가 올라가, 모든 요청이 SPA로 폴백되며 로그인·API가 전멸함(GET은 200처럼 보이고 POST/PUT은 404). 루트 절대경로로 재배포해 복구했으나, 배포 직후 헬스체크 200을 근거로 정상이라 판단한 것이 문제였음 — **상태코드가 아니라 응답 본문·Content-Type까지 봐야** 이 형태의 장애를 잡는다는 점을 postmortem에 남김.

- **감사 로그 화면이 항상 500이던 원인:** 원시 SQL 안에서 `::date` 캐스트를 쓰면 ORM이 `::`를 **바인드 파라미터 구분자로 읽어** 파라미터가 SQL에 그대로 남아 syntax error가 남. 화면 기본값이 최근 7일이라 페이지가 열릴 때마다 500이던 상태를 명시적 CAST 문법으로 교체해 해결함.

## 3. 총평 및 향후 과제 (Wrap-up & Next Steps)

> **"결재를 앱으로 옮기고, 수발신 문서를 진짜 대장으로 만들고, 앱이 스스로 기록하게 만든 한 주"**

이번 주의 출발점은 실패였음 — AMP 인이메일 결재를 마무리 직전까지 밀어붙였지만 도메인 인증 요건 때문에 걷어냈고, 동작하지 않을 코드를 남기지 않는 쪽을 택함. 그 결정이 오히려 방향을 정리해줘서, "메일은 알림·처리는 앱"으로 역할을 가른 뒤 그동안 손댈 수 없던 결재자 지정을 열고, 결재자가 실제로 일할 화면과 열람 전용 참조자까지 이어붙임. 수발신 문서는 첨부 다중화·사건 폴더 편입·폴더 링크 저장으로 대장의 신뢰도를 올렸고, 안내 메일을 실무가 쓰는 포맷으로 되돌렸음. 사건목록은 컬럼을 늘리고 정렬을 재정의하는 과정에서 **규칙을 정하자 그 규칙을 덮고 있던 층들이 차례로 드러난** 것이 소득이었고, 지사 그룹은 새 개념을 만들지 않고 기존 설정을 읽는 방식으로 6개 화면을 한 번에 정리했음. 주 후반 감사 로그는 단순 로깅이 아니라 **어디서 잡아야 누락도 유령도 없는가**를 정하는 작업이었고, 시스템 설정 정비는 사용자가 실수하거나 결과를 모르는 지점을 없애는 작업이었음. 성능에서는 타입 불일치로 죽어 있던 인덱스를 살려 목록 조회를 15배 개선했고, 반대로 배포에서는 잘못된 소스 경로로 프로덕션 API를 9분 중단시켰음 — 헬스체크 200을 정상으로 읽은 것이 더 아픈 지점이라 postmortem으로 남김.

**향후 과제:**

- **배포 절차 개선:** 소스 경로를 셸 상태에 의존하지 않게 고정하고, 헬스체크를 상태코드가 아니라 응답 본문·Content-Type까지 검증하도록 보강
- **감사 로그 운영:** 적재량·보관 기간 정책 결정, 조회 화면의 실사용 피드백 반영, 대상 테이블 확대 여부 판단
- **결재·참조자 실사용 검증:** 결재 관리 3탭과 참조함, 지사별 고정 수신 이메일이 실제 결재·발송 흐름에서 의도대로 도는지 확인
- **CRM 상담 연동 범위 판단:** 상담이 의뢰인에 달려 있어 같은 의뢰인의 다른 사건 상담도 함께 노출되는 현재 동작을 유지할지, 사건 단위로 좁힐지 결정
- **실행취소 폐기 후속 정리:** 1단계까지 붙였다가 폐기로 정리된 만큼, 잔여 코드·UI 정리와 대체 안전장치(확인 팝업 등) 적용 범위 점검
